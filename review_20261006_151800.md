## 1. Domain & Architectural Analysis

### 1.1 Root Cause Identification
1. **Property Overlap False Positives (9 Apache Daffodil TDML tests):**
   - In DFDL v1.0 §4.1.2, properties defined locally on an element take precedence over properties on its referenced simpleType, which in turn take precedence over file-level default formats (`<dfdl:format>` or `<dfdl:format ref="...">`).
   - The compiler previously executed `resolve_ref_formats(&mut resolved_st_props)` and `resolve_ref_formats(&mut resolved_elem_props)` *prior* to testing for overlapping property definitions.
   - Because standard schemas define common formatting defaults (`initiator=""`, `terminator=""`, `occursCountKind="implicit"`, `ignoreCase="no"`) at the schema root `<dfdl:format>`, both `resolved_st_props` and `resolved_elem_props` inherited these default bindings.
   - Consequently, when testing whether a property was defined on both the element and the simpleType (or across simpleTypes in a restriction chain), the compiler falsely flagged universal format defaults as conflicting overlaps.
   - Furthermore, between an element and its simpleType, DFDL explicitly permits local properties on an element to override or refine non-conflicting properties from its base simpleType. True overlap violations occur either:
     - On element references (`<xs:element ref="e" dfdl:.../>`) duplicating local properties on the referenced element declaration;
     - When conflicting mutually-exclusive formatting properties (e.g., both declaring contradictory local padding or alignment parameters) are specified on restriction chains.

2. **Cross-Namespace Format Resolution (`defineFormat not found`):**
   - When a schema imported a chameleon schema (a schema with no target namespace), or imported definitions without an explicit prefix on `ref="GeneralFormat"`, the Clark-notation lookup `{http://example.com}GeneralFormat` failed if the format was registered under `{}` or vice versa.
   - Normalizing prefix/namespace mapping and checking both qualified and unqualified variants of the format name ensures conformance across multi-file schema architectures.

## 2. Changes Made & Conformance

### 2.1 Compiler Architecture ([`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs))
- **Separation of Direct vs Inherited Format Properties:**
  - Evaluated property overlaps using direct component properties (`elem.properties` and `st_props`) prior to format inheritance injection.
  - Allowed proper element-level property overriding over simpleType base defaults without triggering false positive SDEs.
- **Cross-Namespace Format Lookup:**
  - Enriched `resolve_ref_formats_bounded` to resolve format names across chameleon and namespace-qualified contexts.
