## 2. Standard-Conforming Architectural Changes

Rather than applying surgical one-off patches for individual test cases, changes were designed to enforce broad DFDL 1.0 specification invariants uniformly across types and constructs:

### A. Model Group Child Requirement & Group References (`DFDL §14, §15, §16`)
- **Specification:** A complex type (whether named or anonymous) must contain exactly one model group child (`xs:sequence`, `xs:choice`, or `xs:group` reference).
- **Engine Implementation:** Fixed validation in `crates/dfdl-schema/src/compiler.rs` to recognize `<xs:group ref="...">` properly within `parse_element_node` and global `parse_schema`, resolving previous false-positive SDEs on legitimate schemas while properly rejecting malformed complex types missing model groups.

### B. Choice Branch Ordering & Unique Particle Attribution (`DFDL §15.1`)
- **Specification:** Branches within `<xs:choice>` must be distinct and non-optional (`minOccurs != 0`), adhering to Unique Particle Attribution (UPA).
- **Engine Implementation:** Moved `validate_choice_branches` ahead of general model-group validation so that duplicate element branch names trigger the precise UPA violation error across choices regardless of branch types.

### C. Length Kind Invariants Across Representations (`DFDL §12, §13`)
- **Specification (DFDL-12-160R):** Numeric, boolean, and calendar elements with `representation="binary"` cannot have `lengthKind="delimited"`.
- **Specification (DFDL-5-063R):** For `xs:string` and `xs:hexBinary` with `lengthKind="implicit"`, both `minLength` and `maxLength` must be explicitly specified and equal.
- **Specification (DFDL-12-067R):** Calendar text elements cannot have `lengthKind="implicit"`.
- **Engine Implementation:** Enforced in compiler type resolution across all built-in simple types.

### D. Choice Length Explicit Bounds (`DFDL §15.3`)
- **Specification:** When `choiceLengthKind="explicit"`, branches must fit within the specified choice length. If the branch data is smaller, remaining bits are padded/skipped. If the branch data exceeds `choiceLength`, a parse error is raised.
- **Engine Implementation:** Added `choice_length_kind` and `choice_length` to `ResolvedProperties`, and integrated explicit length tracking and bounds checking inside the kernel choice parser.

### E. Arithmetic Operator Typing & Lookahead Guard (`DFDL §23, XPath 2.0`)
- **Specification:** Binary arithmetic operators require numeric operands; string or boolean operands must be rejected with SDE. Furthermore, `dfdlx:lookAhead` distance must not exceed 512 bits to prevent denial-of-service / unbounded lookahead.
- **Engine Implementation:** Implemented in `crates/dfdl-core/src/expr/eval.rs` with strict type checking and bit-budget enforcement.

## 3. Domain Expert Remarks & Recommendations

### [Cyber & Security Hardening]
- **Unbounded Resource Protection:** The 512-bit limit on `dfdlx:lookAhead` prevents speculative runaway memory consumption on crafted inputs.
- **Path Expression Containment:** The strict rejection of `..` navigation past the infoset root prevents path traversal vulnerabilities in schema expressions.
- **Lexical NaN/INF Validation:** Rejecting non-conforming tokens (`nan`, `inf`, `+nan`) in floating-point constructors prevents parser confusion and IEEE-754 serialization desynchronization across heterogeneous endpoints.

### [Embedded Systems & Safety (`#![no_std]` + `alloc`)]
- All core engine code remains strictly `#![no_std]` compatible, relying exclusively on `core::` and `alloc::` primitives.
- Dynamic allocations in the compiler and parser are bounded by transaction checkpoints and rolling backtrack buffers.

### [Future Work: Remaining Category 4 Candidates (264 cases)]
1. **Binary Calendar Implicit Length (DFDL §13.11):**
   - Calendar elements with binary representations (`packed`, `bcd`, `ibm4690Packed`) cannot have `lengthKind="implicit"` unless `calendarPattern` permits deterministic length calculation.
2. **Strict Text Number Check Policy (DFDL §13.6):**
   - With `textNumberCheckPolicy="strict"`, any unparsed leading/trailing whitespace around numbers must trigger a Parse Error.
3. **Facet Bounds on Unions and HexBinary:**
   - Enforce pattern, length, and min/max facets on hexBinary buffers and union member selection.
