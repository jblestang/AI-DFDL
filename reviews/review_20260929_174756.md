## 1. Overview & Rationale

Prior to this refactoring, `crates/dfdl-schema/src/compiler.rs` relied on `extract_literal_or_expr`, an ad-hoc function that manually trimmed `{` and `}` braces, stripped single/double quotes, and trimmed nested parentheses using custom string search and slicing logic (`find('\'')`, `trim_start_matches`, `trim_end_matches(')')`).

This manual string manipulation was fragile and duplicate effort because `dfdl-core` already incorporates a formal Pest PEG parser (`dfdl_expression.pest`) and evaluation engine (`dfdl_core::expr::parse_expr` and `eval_expr`) conforming strictly to DFDL 1.0 Specification §18.

### Key Changes
1. **Removed `extract_literal_or_expr`**: Deleted the hardcoded ad-hoc string slicing function completely.
2. **Pest Expression Parsing & Evaluation**: Updated `parse_default_value` to parse inputs using `dfdl_core::expr::parse_expr(val_str)` and evaluate them via `dfdl_core::expr::eval_expr`.
3. **AST Value Coercion**: Introduced `coerce_dfdl_value` to convert evaluated `DfdlValue` results into the target `DfdlSimpleType`.
4. **Fallback Handling**: If `parse_expr` or evaluation fails (e.g. for bare unquoted literal strings in XML attributes like `default="hello"`), the value is treated as a bare string scalar and coerced cleanly.
5. **Unit Test Suite**: Added `test_parse_default_value_expressions_and_literals` in `compiler.rs` covering literals (`"42"`), enclosed expressions (`"{ 42 }"`), parenthesized literals (`"{ (42) }"`), arithmetic expressions (`"{ 10 + 32 }"`), single-quoted strings (`"{ 'hello' }"`), bare strings (`"hello"`), and booleans (`"true"`, `"{ true }"`).
