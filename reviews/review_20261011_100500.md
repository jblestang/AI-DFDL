## 1. Executive Summary

This review validates the design, implementation, and performance impact of two major optimization milestones in the AI-DFDL engine:
1. **Zero-Allocation Variable Checkpointing**: Replacement of full heap-cloning of `VariableMap` during backtracking with an append-only undo-log transaction model (`checkpoint(&self) -> usize`, `rollback(&mut self, usize)`).
2. **Pre-compiled Expression ASTs in IR**: Compilation of expressions (`choiceDispatchKey`, `discriminator`, `assert`) into Abstract Syntax Trees (`ExprAst`) at schema build time, removing runtime Pest tokenizer and grammar parsing overhead.
3. **Validation Mode Conformance**: Resolution of user critique concerning facet validation under `ValidationMode::Off`.

All 289 unit/integration tests in `dfdl-core` pass, `dfdl-benchmark` passes all 7 validation suites, and `cargo clippy --workspace --all-targets -- -D warnings` completes with zero warnings.

## 2. Technical Architecture & Analysis

### 2.1 Zero-Allocation Variable Checkpointing (`crates/dfdl-core/src/expr/variables.rs`)
- **Previous Pattern**: Backtracking points of uncertainty (element occurrence loops, choice branches, unordered sequences) unconditionally cloned the entire `VariableMap` (including `Vec<DfdlVariable>`, nested strings, and scoped instance stacks) via `let vmap_cp = self.variable_map.clone();`.
- **New Transactional Undo Log**:
  - `undo_log: RefCell<Vec<VariableUndo>>` tracks only active mutations (`SetValue`, `PushInstance`, `PopInstance`, `StateChange`).
  - `checkpoint(&self) -> usize`: Returns the current length of the undo log in $O(1)$ time with zero heap allocations.
  - `rollback(&mut self, cp: usize)`: In the 99.9% common case where variables are not mutated during an attempt, `log.len() > cp` is false, executing an instantaneous $O(1)$ NO-OP without memory operations.
  - All 5 backtracking sites in `element.rs` (lines 751, 806, 1409, 1447) and `mod.rs` (line 1238) now use `checkpoint()` and `rollback()`.

### 2.2 Pre-compiled Expression ASTs in IR (`ir.rs`, `properties.rs`, `element.rs`, `mod.rs`)
- **Previous Pattern**: Every discriminator check, choice dispatch key evaluation, and assertion parsed expression strings at runtime using Pest (`crate::expr::parse_expr`).
- **Pre-compilation in Schema IR**:
  - Added `choice_dispatch_key_ast: Option<ExprAst>` and `discriminator_ast: Option<ExprAst>` to `ResolvedProperties`.
  - Added `test_ast: Option<ExprAst>` to `CompiledAssert`.
  - `to_resolved_properties` parses and validates expressions during schema compilation into ASTs once.
  - Runtime execution in `ParserEngine` (`mod.rs:1107`, `element.rs:2390`, `element.rs:2519`) evaluates the pre-compiled AST directly, bypassing Pest tokenization and regex overhead completely.
  - Fallback mechanisms preserve dynamic parsing compatibility for hand-crafted unit tests without pre-compiled ASTs.

### 2.3 Strict Facet Validation under `ValidationMode::Off`
- **Resolution**: Reverted the temporary `check_facets` flag.
- **Specification Compliance**: Per DFDL v1.0 §9.4 and §16.1, facet validation is strictly suppressed when `self.validation_mode == ValidationMode::Off`. In `parse_simple_value`:
  ```rust
  if self.validation_mode != ValidationMode::Off
      && props.facets.has_facets()
      && props.rep_type.is_none()
      && props.rep_simple_type.is_none()
  {
      // Validate facets
  }
  ```
  Facet validation is completely bypassed when validation is off, eliminating redundant facet evaluation and strictly honoring the user's design principle.
