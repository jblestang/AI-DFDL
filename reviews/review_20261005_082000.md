## Root Cause Analysis
1. **Missing Built-In XML Schema Type Resolution in Schema Compiler**:
   - In `crates/dfdl-schema/src/compiler.rs`, `prefixLengthType` checking looked up `clean_plt` only in `schema.named_simple_types`.
   - When a schema specified a built-in XML Schema integer primitive type (`xs:unsignedShort`, `xs:int`, `xs:byte`, etc.), it was not in `schema.named_simple_types`.
   - Consequently, the compiler did not emit the structured type descriptor (`{type}:{rep}:{length}:{units}::{min}:{max}`), leaving `prefixLengthType` as an unencoded QName.
2. **Missing Text/Decimal Implicit Length Resolution in Schema Compiler**:
   - When `dfdl:representation="text"`, `compiler.rs` had `implicit_len` set to `None`, producing an empty length slot (`::{units}:`).
3. **Ad-Hoc String Matching Fallbacks**:
   - Because of (1) and (2), the parser, unparser, and expression evaluator had fallback logic attempting to inspect the lowercase name of the type:
     ```rust
     if lower.contains("threebyte") || lower.contains("twentyfour") { 24 }
     else if lower.contains("fourbyte") || lower.contains("thirtytwo") { 32 }
     else if lower.contains("byte") || lower.contains("prefixlengthtype") { 8 } ...
     ```
   - This hardcoding of schema-specific type names directly violated the DFDL specification principles and clean architecture.

## Technical Changes & Implementation

1. **Schema Compiler ([compiler.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs))**:
   - For user-defined simple types:
     - Added support for `totalDigits` and `maxLength` in text representation to compute effective implicit length.
     - Added `DfdlSimpleType::Decimal` alongside `Long`/`UnsignedLong` to default to 64 bits (8 bytes).
   - For built-in XML Schema integer types:
     - Added `else` block when `clean_plt` is not in `schema.named_simple_types`.
     - Maps standard XML Schema integer types to exact byte lengths:
       - `byte`, `unsignedByte` -> 1 byte (8 bits)
       - `short`, `unsignedShort` -> 2 bytes (16 bits)
       - `int`, `unsignedInt` -> 4 bytes (32 bits)
       - `long`, `unsignedLong`, `integer`, `nonNegativeInteger` -> 8 bytes (64 bits)
     - Resolves `representation` and `lengthUnits` from format scope.
     - Formats complete descriptor: `{clean_plt}:{rep}:{len}:{units}::`.

2. **Unparser ([unparser.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs))**:
   - Removed all `lower.contains(...)` name-matching branches.
   - Decodes structured descriptor directly from compiled schema properties.
   - If an unencoded built-in type name is received, maps standard XML Schema primitive type sizes via strict exhaustive pattern matching (`byte`/`short`/`int`/`long`).

3. **Parser ([element.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs))**:
   - Removed all `lower.contains(...)` name-matching branches.
   - Symmetrically decodes compiled descriptor and standard XML Schema primitive types.

4. **Expression Evaluator ([eval.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/eval.rs))**:
   - Replaced `lower.contains("prefixlengthtype")` with structured descriptor decoding and standard XML Schema primitive type byte mapping.
