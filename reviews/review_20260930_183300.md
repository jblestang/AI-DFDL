## 1. Executive Summary

This code review documents the implementation and architectural integration of generic, standards-compliant fixes addressing **"Expected Error Not Raised"** failures in the Apache Daffodil official TDML test suite.

The fixes address root causes across expression evaluation, schema compilation, property resolution, and runtime parsing:
1. **Generic XSD Constructor Function Evaluation (`eval.rs`):** Eliminated unchecked `as` casts and silent `.unwrap_or(0)` fallbacks in constructor functions (`xs:int`, `xs:short`, `xs:long`, `xs:byte`, `xs:unsignedByte`, `xs:unsignedShort`, `xs:unsignedInt`, `xs:unsignedLong`, `xs:float`, `xs:double`), raising proper `DFDLError` instances on overflow or malformed string inputs.
2. **`inputValueCalc` Schema Facet Validation (`parser.rs`):** Ensured that scalar values calculated via `dfdl:inputValueCalc` are validated against their simple type schema facets (`minInclusive`, `maxInclusive`, `minLength`, `maxLength`, `pattern`, `enumeration`, etc.).
3. **Sequence & Choice `initiatedContent="yes"` Validation (`compiler.rs`):** Added schema compiler checks enforcing DFDL 1.0 Section 14.1 rules requiring all child elements of an initiated sequence/choice to declare an initiator.
4. **Property Validation & Embedded Runtimes:** Added property validation for empty `textStandardExponentRep` and negative `dfdl:length` values, while strictly preserving `#-[#no_std]` + `alloc` compatibility (`thumbv7m-none-eabi`).

## 2. Technical Domain & Safety Review

### 2.1 Constructor Function Evaluation Safety
- **Macro `cast_to_int!`:** Implemented in `eval_fn_call` to perform checked range conversions (`try_into()` and finite `f64` range bounds checking) across all integer variants.
- **Error Propagation:** Malformed strings, out-of-range numerical casts, and non-numeric value inputs return `DFDLErrorKind::SchemaDefinition` instead of silently defaulting to `0`.
- **Unit Testing:** Added `test_constructor_function_range_and_errors` in `eval.rs` covering valid conversions, out-of-range errors, and invalid string inputs across `xs:short`, `xs:byte`, `xs:unsignedByte`, `xs:unsignedInt`, `xs:int`, and `xs:double`.

- **Engine Enforcement:** Invoked `term.properties.facets.validate_value_detailed(&value)?` in `parse_element_scalar` immediately after evaluating `dfdl:inputValueCalc`.
