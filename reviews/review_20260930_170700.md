## 2. Technical Domain & Safety Review

### 2.1 Generic Simple Type Handling (`DfdlValue`)
- **Unified Integer Conversion (`as_i128`):** Added `DfdlValue::as_i128()` in `crates/dfdl-core/src/infoset/value.rs` to convert all numeric scalar representations (`Int`, `Long`, `Short`, `Byte`, `UnsignedLong`, `UnsignedInt`, `UnsignedShort`, `UnsignedByte`, `Decimal`, `String`) into a 128-bit integer for uniform range checking.
- **Signedness Check (`is_negative`):** Added `DfdlValue::is_negative()` to detect negative scalar inputs across all types, guaranteeing that negative values assigned to unsigned simple types (`xs:unsignedLong`, `xs:unsignedInt`, `xs:unsignedShort`, `xs:unsignedByte`) consistently produce a `"must match in signedness"` parse error.
- **Generic `checkConstraints` Facet Evaluation:** Updated `eval_fn_call` in `crates/dfdl-core/src/expr/eval.rs` to leverage `as_i128()` and `is_negative()` generically across all simple types.

### 2.2 DFDL 1.0 Schema Prohibitions (`dfdl:outputValueCalc` / `dfdl:inputValueCalc`)
- **DFDL 1.0 Section 19.2 & 19.3 Rules:**
  - `dfdl:inputValueCalc` and `dfdl:outputValueCalc` MUST NOT be placed on optional elements (`minOccurs == 0`).
  - `dfdl:inputValueCalc` and `dfdl:outputValueCalc` MUST NOT be placed on array elements (`maxOccurs > 1` or `maxOccurs = unbounded`).
  - `dfdl:inputValueCalc` and `dfdl:outputValueCalc` MUST NOT be placed on complex elements.
- **Engine Implementation:** Enforced in `Compiler::compile_element` inside `crates/dfdl-schema/src/compiler.rs`, raising a `DFDLErrorKind::SchemaDefinition` error whenever these prohibited annotation combinations are encountered.

- Zero standard library dependencies added; memory layout remains heap-minimal and suitable for microcontrollers and embedded runtimes.
