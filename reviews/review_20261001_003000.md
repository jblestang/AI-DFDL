**Timestamp:** 2026-10-01T00:30:00+02:00  
**Context:** Analysis of "Other Parse Errors" and "Left over data remaining after root element parse" conformance failures, surgical resolution of bitstream delimiter scanning, TDML bitstream assembly concatenation, dynamic `fn:count` XPath evaluation, and sequence loop progress semantics.

## 1. Domain Expertise Analysis

### 1.1 DFDL Standard & Sequence Delimiter Semantics (DFDL 1.0 §14.2 & §9.3)
- **Sequence Element Loop Progress & Delimiter Suppression:**
  - *Standard Requirement (DFDL 1.0 §14.2):* When parsing an array or optional element within a sequence governed by `dfdl:separatorPosition="infix"`, the first occurrence does not have a leading separator, but subsequent occurrences require an infix separator. When an element occurrence consumes 0 bytes (e.g. empty string), the parser must not terminate early if a matching separator is present ahead in the bitstream. Terminating prematurely leaves the remaining separators and subsequent array items unparsed in the stream.
  - *Root Cause Discovered:* In `crates/dfdl-core/src/kernel/parser.rs`, an infinite-loop guard checked `(self.reader.is_eof() || new_reader_cp == reader_cp)` and broke out of the occurrence loop after occurrence 0 when 0 bytes were consumed. This aborted parsing before the infix separator could be matched, causing all subsequent occurrences and trailing separators to be stranded in the reader and failing root validation with `"Left over data remaining after root element parse"`.
  - *Fix Applied:* Updated the break condition to verify whether a matching separator is next in the bitstream (`(self.reader.is_eof() || (new_reader_cp == reader_cp && !has_next_sep))`). If `has_next_sep` is true, the loop continues and consumes the separator and following items.

### 1.2 Binary Data Processing & Bit-Level Representation (DFDL 1.0 §13.7)
- **Delimited Binary `xs:hexBinary` Delimiter Scanning:**
  - *Standard Requirement (DFDL 1.0 §13.7.1):* When `xs:hexBinary` is parsed with `dfdl:lengthKind="delimited"`, it consumes binary octets until an in-scope terminator or delimiter matches.
  - *Root Cause Discovered:* In `parse_binary_value` for `DfdlSimpleType::HexBinary`, when `dynamic_len` was `None`, the loop greedily consumed all bytes to EOF without testing in-scope delimiters. This caused `hexBinary_Delimited_01a` and `hexBinary_Delimited_01` to read the entire bitstream, exhausting input before the postfix separator could be matched and triggering `Delimiter mismatch: end of data reached`.
  - *Fix Applied:* Integrated in-scope delimiter and terminator scanning prior to reading each byte in the binary `HexBinary` loop, matching the text delimited scan mechanism.

### 1.3 Signal / Bitstream Assembly in TDML Test Harness
- **Sub-Byte Bitstream Concatenation:**
  - *Standard Requirement (TDML Specification):* Consecutive `<tdml:documentPart type="bits">` fragments in TDML define a single continuous bitstream. Fragment boundaries need not align to 8-bit octet boundaries unless explicitly stated.
  - *Root Cause Discovered:* In `crates/dfdl-tests/src/tdml.rs`, `assemble_document_bytes_with_base_dir` padded each `type="bits"` fragment to an 8-bit boundary upon completing each fragment. In tests such as `hexBinary_Delimited_01`, where bit parts were segmented mid-byte (e.g. 130 bits, 126 bits), zero-padding was injected between every part, corrupting ASCII characters across part boundaries.
  - *Fix Applied:* Refactored bit assembly with a persistent bit buffer (`pending_byte`, `pending_bit_count`) that carries over fractional bits across consecutive `type="bits"` parts, only flushing padding when transitioning to non-bit parts or at EOF.

### 1.4 XPath Expression Engine Architecture (DFDL 1.0 §23.5)
- **Dynamic `fn:count` Node Sequence Evaluation:**
  - *Standard Requirement (DFDL 1.0 §23.5):* The function `fn:count($arg)` returns the number of items in the sequence resulting from evaluating `$arg`. In `dfdl:occursCount="{ fn:count(../../header/title) }"`, it must return the total count of matched sibling elements in the parent container.
  - *Root Cause Discovered:* In `crates/dfdl-core/src/expr/eval.rs`, `fn:count` was previously a stub returning a constant `1` for any non-empty string. Consequently, in `dfdl2263`, `occursCount` evaluated to 1 instead of 2, leaving the second row field unparsed and stranding a comma delimiter.
  - *Fix Applied:* Implemented path-aware `fn:count` resolution that resolves the parent container element from `ctx.current_path` and `doc`, counts matching child element nodes by name or wildcard, and returns the accurate element count.
