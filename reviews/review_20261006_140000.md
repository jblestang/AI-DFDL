## 1. Executive Summary & Root Cause Analysis

Category 1 failures comprised 10 tests across two distinct clusters in Apache Daffodil's official test suite:
1. **Cluster A (9 tests — "Overlapping properties" False Positives):**
   - `TestCheckDigit.tdml`: `test_checkDigit_ok_01`, `test_checkDigit_bad_invalid`, `test_checkDigit_unparse_ok_01`.
   - `namespaces.tdml`: `multifile_facets_01`, `long_chain_01`, `long_chain_03`, `long_chain_06`, `long_chain_06b`, and `cFoo:cElem` vs `foo:cType`.
   - *Root Cause:* In [`crates/dfdl-schema/src/xsd_ast.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/xsd_ast.rs), when cross-document schemas were merged via `XsdSchema::merge`, default properties from `other.global_format` (such as `initiator=""`, `terminator="B"`, `encoding="US-ASCII"`, `occursCountKind="implicit"`, `ignoreCase="no"`) were copied directly into the simple type's `props`. Consequently, in [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), `resolved_st_props` was polluted with document-level fallback defaults. The collision check (`for binding in resolved_st_props.bindings() { if elem_direct_props.get_property(k).is_some() { return Err("Overlapping properties..."); } }`) falsely treated document defaults as local/direct properties of the simple type, rejecting valid schemas whenever an element explicitly specified any property present in the default format.
2. **Cluster B (1 test — "defineFormat not found"):**
   - `namespaces.tdml`: `namespace_scope_02` (`defineFormat {http://foo.com}GeneralFormat not found`).
   - *Root Cause:* In `compiler.rs`, chameleon inclusion of no-namespace schemas (`imported_schema.target_namespace.is_none()`) was unconditionally clobbering `namespace = tns.clone()` across *all* defined formats and components, including formats imported from an external namespace that already carried an explicit target namespace URI (`{http://foo.com}GeneralFormat`). This broke cross-namespace Clark notation resolution in `resolve_ref_formats_bounded`.

## 2. Standard-Conforming Architectural Fixes (DFDL v1.0 & W3C XSD)

### 2.1 Distinction of Direct vs Default Properties on Simple Types (DFDL §4.1.2 & §12.1.2)
- Rather than a local surgical exemption for `checkDigitType`, we applied a general architectural model across all XSD simple types:
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq)]
  pub struct XsdNamedSimpleType {
      pub name: QName,
      pub base_type: XsdType,
      pub local_props: PropertyStore,
      pub default_props: PropertyStore,
  }
  ```
- **Local Properties (`local_props`):** Stores only properties defined directly on `<xs:simpleType>`, child annotations, or referenced via `dfdl:ref`.
- **Default Properties (`default_props`):** Stores fallback document defaults (`dfdl:format`). In `XsdSchema::merge`, `other.global_format` is merged exclusively into `default_props`.
- **DFDL §4.1.2 Overlapping Properties Invariant:**
  - Overlap collision checking evaluates strictly `local_props` of the simple type against `elem_direct_props` (element local properties) and against `prev_props` (base simple type local properties in the restriction chain).
  - Schema-level default format properties NEVER participate in overlap collision checks.
- **DFDL §12.1.2 Property Resolution & Precedence:**
  - Effective properties are assembled strictly in accordance with the standard precedence hierarchy:
    1. Element declaration local properties (`elem_direct_props`).
    2. Format referenced by element declaration.
    3. Simple type local properties (`resolved_st_props`).
    4. Base simple type local properties (restriction chain).
    5. Element schema document default format (`resolved_global_format`).
    6. Innermost simple type schema document default format (`effective_st_defaults`).

### 2.2 XML Schema 1.0 Chameleon Inclusion Semantics
- In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), chameleon inclusion now strictly tests `if component.namespace.is_none()` before assigning `tns.clone()`.
- Explicitly namespaced components (such as formats, escape schemes, elements, and simple types originating from foreign imports) retain their qualified namespace and resolve accurately via Clark notation (`{http://foo.com}GeneralFormat`).
