# Code Review — F4: Détermination précise de la longueur en caractères UTF-8 pour les éléments complexes

**Date:** 2026-10-07 06:53:00 UTC+2  
**Composants impactés :** `crates/dfdl-core/src/kernel/parser/element.rs`, `crates/dfdl-tests/src/lib.rs`  
**Référence normative :** GFD.240 §12.3.7 (*dfdl:lengthUnits*)  

---

## 1. Contexte & Diagnostic initial

L'affirmation F4 relevait :
> Le parent complexe convertit encore une longueur en caractères par `length * encoding_unit_bits`. Avec UTF-8, cette formule limite deux caractères à deux octets. Le parsing de `éAZ` réussit avec `p/s="é"` et `tail="AZ"`, au lieu de `p/s="éA"` et `tail="Z"`. Un enfant fixe de deux caractères dans le parent rejette aussi `éA` comme données insuffisantes.

### Analyse technique
- Dans `crates/dfdl-core/src/kernel/parser/element.rs:2140–2148`, pour un élément complexe avec `lengthUnits="characters"` :
  ```rust
  let bits = match term.properties.length_units {
      crate::schema::ir::LengthUnits::Bits => l,
      crate::schema::ir::LengthUnits::Bytes => l.saturating_mul(8),
      crate::schema::ir::LengthUnits::Characters => {
          l.saturating_mul(crate::encoding::encoding_unit_bits(&term.properties.encoding))
      }
  };
  ```
- `encoding_unit_bits("UTF-8")` renvoie 8 bits (1 octet), ce qui est exact pour l'unité d'encodage minimale (*code unit*), mais faux pour la longueur en caractères (*code points*) dans un encodage à largeur variable comme UTF-8 où chaque caractère peut occuper entre 1 et 4 octets.
- Conséquences :
  1. La limite de bits (`bit_limit`) appliquée au parseur du complexe tronquait les caractères multi-octets.
  2. Le champ `tail` subséquent se voyait réattribuer silencieusement les octets tronqués du parent complexe.
  3. Les enfants du complexe avec longueur fixe en caractères échouaient avec `DFDLErrorKind::Parse` (données insuffisantes) sur des chaînes valides comme `"éA"`.

---

## 2. Solution Implémentée

### A. Conformité DFDL GFD.240 §12.3.7
Per GFD.240 §12.3.7 :
> *When lengthUnits is 'characters': For variable-width encodings, the representation length is determined by scanning characters in the specified encoding until the specified number of characters is reached.*

Dans `element.rs` :
- Lorsque `length_units == LengthUnits::Characters` et que l'encodage est UTF-8 :
  1. On effectue un checkpoint de la position du lecteur (`let cp = self.reader.checkpoint();`).
  2. On lit `l` caractères UTF-8 via le décodeur `read_utf8_char_bytes`.
  3. Si le flux contient moins de `l` caractères ou des données tronquées, on annule le checkpoint et renvoie une erreur explicite `DFDLErrorKind::Parse`.
  4. La longueur en bits exacte `consumed_bits` est calculée par différence de position du lecteur.
  5. On restaure le checkpoint pour que les enfants du complexe soient ensuite parsés normalement à l'intérieur de la fenêtre délimitée par `start_bit + consumed_bits`.
- Si un autre encodage à largeur variable non supporté pour les complexes est spécifié, une erreur explicite de définition de schéma à l'exécution (`SchemaDefinition`) est émise au lieu d'une corruption silencieuse.
- Pour les encodages à largeur fixe (ASCII, UTF-16, UTF-32), la formule `l * encoding_unit_bits` est conservée.

## 3. Revue par domaine d'expertise

### A. Spécification DFDL & Standardisation
- **Conformité GFD.240 §12.3.7 :** Implémentation conforme à la lettre du standard : l'élément complexe de longueur en caractères calcule sa borne en scannant les caractères dans l'encodage effectif.
- **Rétrocompatibilité :** Aucun impact sur les encodages fixes ou les unités en `bytes`/`bits`.

### B. Développement & Robustesse logicielle
- **Transactionnalité du lecteur bitstream :** L'usage de `checkpoint` / `rollback` garantit qu'aucun bit n'est consommé ou altéré pour le sous-arbre de parsing avant que les enfants ne commencent.
- **Gestion des cas limites :**
  - `l = 0` : boucle 0-op, retourne 0 bits.
  - Données insuffisantes (EOF) : rollback propre et émission d'une erreur typée `DFDLErrorKind::Parse`.
  - Entrées multi-octets 2, 3, 4 octets : parfaitement gérées par la machine à états de `read_utf8_char_bytes`.

### C. Sécurité & Intégrité des données
- **Prévention des corruptions d'infoset :** Élimination définitive de la réallocation silencieuse de données vers les champs suivants (`tail`).
- **Absence d'overruns :** Le bit limit protège les sous-parseurs contre tout débordement au-delà des `l` caractères scannés.
