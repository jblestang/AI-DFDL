## Domain Expert Analyses

### 1. DFDL Standard Conformance Expert Review
- **Binary Number Representations & Packed Types (DFDL §13.7)**:
  - BCD encoding and IBM 4690 packed decimal unparsing was implemented according to §13.7.1.3 & §13.7.1.4:
    - BCD encodes 2 decimal digits per byte; odd digit counts are prefixed with `0` nibble; target lengths are padded with `0x00`.
    - IBM 4690 packed unparsing correctly signs negative values and pads target byte lengths with leading `0xFF` nibbles.
  - Packed Decimal Sign Nibble Validation (§13.7.1.1):
    - `binaryPackedSignCodes` property parsing and resolution correctly validates the terminal nibble during both parsing and unparsing. Sign codes `C, D, F` are verified with strict error reporting when invalid nibbles occur (e.g. `packedCharset05`).
- **Schema Compiler Generalizations (DFDL §12.3.7.2, §13.7)**:
  - Bit length validation for binary integers is now strictly restricted to `binaryNumberRep == Binary`. Packed, BCD, and IBM 4690 types are no longer rejected at schema compilation based on fixed integer bit limits, as their lengths are byte-oriented representations.
  - Representation check gating: `binaryNumberRep` restrictions are now evaluated only when `representation == Binary`, eliminating false-positive schema definition errors for text representations where defaults were set at schema root.
- **Infoset Element Unparsing for Empty & Default Values (DFDL §9.4, §13.2, §13.3)**:
  - When infoset elements have `ElementState::NoValue` or `ElementState::Empty`, simple string and `hexBinary` types now correctly unparse empty string or empty byte payloads rather than being omitted.
  - Length padding and framing (initiators, terminators, alignment) are honored systematically across `Explicit`, `Implicit`, and `Delimited` length kinds.
- **Calendar Pattern Numeric Field Bounds (DFDL §13.11)**:
  - SimpleDateFormat parser for adjacent numeric fields (e.g. `MMddyy`) now uses non-greedy digit extraction bounded by pattern token length, avoiding parser collapse where the first token greedily consumed all subsequent field digits.
