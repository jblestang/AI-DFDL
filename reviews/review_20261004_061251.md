## 2. Domain-Specific Analysis & Expert Remarks

### A. Signal Processing & Binary Bitstream Domain (LSBF vs ByteOrder)
- **Observation**: `BitWriter::write_bits` under `BitOrder::LeastSignificantBitFirst` fills byte buffer positions starting from byte 0 with low-order bits (bits 0..7 into byte 0, 8..15 into byte 1, etc.).
- **Evaluation**: In earlier code, `to_le_bytes()` or `swap_bytes()` was invoked for all `ByteOrder::LittleEndian` values before calling `write_bits`. Under LSBF, this caused little-endian multi-byte integers, floats (`f32`), and doubles (`f64`) to be reversed a second time into big-endian byte sequence.
- **Conforming Fix**: Pre-byte swapping for LittleEndian is strictly conditioned on `bit_order == BitOrder::MostSignificantBitFirst` (`needs_byte_swap = byte_order == LittleEndian && bit_order == MSBF`). This conforms with DFDL §11.3 and IEEE 754 floating point serialization.
- **Unit Test Coverage**: `test_unparse_lsbf_little_endian_float` validates that a 32-bit float (`1.25f32`) written under `ByteOrder::LittleEndian` + `BitOrder::LeastSignificantBitFirst` outputs native `[0x00, 0x00, 0xa0, 0x3f]`.

### B. DFDL Specification & Schema Compilation Domain (DFDL §12.3, Table 23 & §14.4.1)
- **Delimited Binary Formats**:
  - DFDL Table 23 explicitly specifies that binary numbers with `packed`, `bcd`, or `ibm4690Packed` representations (as well as packed calendar types) may have `lengthKind="delimited"`. Only standard binary representation (`binaryNumberRep="binary"`, floats, doubles, booleans) cannot be delimited.
  - The schema compiler check for `DFDL-12-160R` was corrected to inspect `binaryNumberRep` and `binaryCalendarRep`, allowing packed/BCD delimited numbers and delimited calendar types to compile.
- **Hidden Choice Validation**:
  - DFDL §14.4.1 specifies: *"When unparsing a choice in a hidden group, the first branch that can legally produce output without requiring any events from the DFDL Infoset is selected. It is a schema definition error if no branch can produce output without requiring events from the DFDL Infoset."*
  - The prior check rejected choices if *any* branch lacked an `outputValueCalc` or default value, which broke schemas containing parse-only branches with `dfdl:inputValueCalc`. The compiler now verifies whether *at least one* branch can produce output without the infoset, allowing valid schemas while correctly catching invalid ones.
- **Unit Test Coverage**:
  - `test_binary_delimited_representation_rules` validates acceptance of packed/BCD delimited numbers and rejection of standard binary numbers.
  - `test_hidden_choice_validation` tests both acceptance when at least one branch has OVC and rejection when no branch can produce output.

### C. Unparser & Infoset Conformance Domain (DFDL §14.4)
- **Infoset Element Independence**:
  - Elements declared in hidden groups do not exist in the infoset during unparsing.
  - When an unhidden element with the same QName follows a hidden element (e.g., `<xs:sequence dfdl:hiddenGroupRef="s" /> <xs:group ref="s" />`), the hidden element unparser must not match against or consume the infoset's node.
  - `find_child_elements` and `branch_matches_element` now immediately return empty/false for hidden terms (`is_hidden = true`).
  - `unparse_term` synthesizes the dummy element tree for hidden branches and evaluates default values or `outputValueCalc` expressions without advancing `child_cursor`.
- **Unit Test Coverage**:
  - `test_hidden_group_unparse_preserves_infoset_elements` verifies that a hidden element `<a>` with `outputValueCalc` is synthesized while leaving the infoset node `<a>` intact for the subsequent non-hidden element.

### D. Software Architecture & Safety Domain (`no_std` + `alloc` Panic Safety)
- **Memory Safety**: No `unsafe` code was introduced. All allocations use safe fallible/checked patterns (`alloc::vec!`, `alloc::format!`).
- **Compiler & Clippy Diagnostics**: Clean compilation with `cargo clippy --workspace --all-targets --all-features -- -D warnings`.
- **Deterministic Resource Budgets**: All new traversal methods in compiler and unparser include bounded recursion depth limits (`depth >= 16` and `depth >= 32`) to prevent stack overflow on circular references.
