# Code & Architecture Review: Explicit `payloadLength` Binding on STANAG 5602 SIMPLE Payloads

- **Timestamp**: 2026-11-02T20:28:00+01:00
- **Scope**:
  - `crates/dfdl-example/schemas/stanag5602_simple.dfdl.xsd`
  - `crates/dfdl-vm/src/compiler.rs`
  - `crates/dfdl-example/tests/test_stanag5602_simple.rs`

---

## 1. Domain Expertise (Tactical Communications & DFDL Framing)
- **Framing Invariant Enforcement**:
  - In STANAG 5602, the 28-octet transport header strictly defines `payloadLength` (octets 26–27).
  - Previously, `<control>` and `<link16>` inside the Layer 2 `<xs:choice>` did not reference `payloadLength`. Consequently, variable or padded payloads were unbounded and malformed frame sizes could not be detected.
  - Added explicit DFDL length bounding to both branches:
    ```xml
    dfdl:lengthKind="explicit" dfdl:length="{ ../payloadLength }"
    ```
  - This guarantees that both Native SIMPLE Management frames and Link 16 J-Series frames are strictly delimited and bounded by the header's declared length.

---

## 2. DFDL-VM Architecture & Compiler Lowering
- **Dynamic Register Sibling Collection**:
  - Extended `collect_referenced_siblings_recursive` in `crates/dfdl-vm/src/compiler.rs` to detect dynamic expressions inside `term.properties.length_expr` (e.g. `{ ../payloadLength }`).
  - Automatically allocates a register (`Register::R1`..`R5`) for the sibling field and emits `MoveReg` when `payloadLength` is parsed.
- **Dynamic Complex Element Bounding**:
  - Updated `lower_single_element` to detect complex elements with dynamic explicit length (`props.length_kind == LengthKind::Explicit && props.length_expr.is_some()`).
  - Emits `Instruction::RecordPosition { dest: reg }` prior to parsing the payload.
  - Emits `Instruction::PadToRegLength { start_reg: reg, length_reg }` upon exiting the payload, ensuring trailing padding within the packet is consumed and stream alignment is preserved.
