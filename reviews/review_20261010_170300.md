## 1. Contexte et Objectifs de l'Étape 3

Dans l'architecture historique, les propriétés physiques DFDL pouvant contenir des expressions dynamiques (ex: `encoding="{ ../hdr/enc }"`, `byteOrder="{ $dfdl:byteOrder }"`, `separator="{ $sep }"`, `initiator`, `terminator`) souffraient d'un anti-pattern majeur :
1. Elles étaient stockées sous forme de chaînes de caractères brutes (`String`) dans `ResolvedProperties`.
2. À chaque évaluation pendant le parsing ou l'unparsing d'un élément :
   - Le moteur vérifiait `s.starts_with('{') && !s.starts_with("{{") && s.ends_with('}')`.
   - Il découpait la chaîne pour isoler le corps de l'expression.
   - Il invoquait la grammaire Pest (`crate::expr::parse_expr`) pour re-parser l'AST XPath à chaque élément.

### Objectifs atteints :
- [x] Définition dans [`crates/dfdl-core/src/schema/ir.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs) de l'énumération générique `DfdlProp<T>` (`Constant(T)` ou `Expression { raw: String, ast: Box<ExprAst> }`).
- [x] Compilation systématique des expressions en [`ExprAst`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/ast.rs) dès la compilation du schéma (`to_resolved_properties` dans [`properties.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs)).
- [x] Gestion native de l'échappement DFDL `{{` sans allocation inutile.
- [x] Intégration de `byte_order_prop`, `encoding_prop`, `separator_prop`, `initiator_prop` et `terminator_prop` dans [`ResolvedProperties`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs).
- [x] Ajout de [`evaluate_prop_at`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs) et [`evaluate_ast_at`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs) pour exécuter l'AST pré-compilé directement sans passer par Pest.
- [x] Respect rigoureux des contraintes de l'environnement : `#![no_std]` + `alloc`, 0 warning Clippy sous `-D warnings`.

## 2. Architecture et Implémentation

### 2.1 Énumération `DfdlProp<T>` ([`schema/ir.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs))
```rust
#[derive(Debug, Clone, PartialEq)]
pub enum DfdlProp<T> {
    /// Valeur constante statique connue dès la compilation.
    Constant(T),
    /// Expression dynamique pré-compilée en AST.
    Expression {
        raw: String,
        ast: Box<crate::expr::ast::ExprAst>,
    },
}
```

### 2.2 Méthodes associées
- `constant(val: T) -> Self`
- `expression(raw, ast: ExprAst) -> Self`
- `is_constant(&self) -> bool`
- `is_expression(&self) -> bool`
- `as_constant(&self) -> Option<&T>`
- `expr_ast(&self) -> Option<&ExprAst>`
- `parse_with<F>(raw: &str, convert_const: F) -> DFDLResult<Self>` : compile l'expression avec `parse_expr` si entourée d'accolades simples, gère le dé-échappement de `{{`, ou convertit en constante statique.
- `parse_str(raw: &str) -> DFDLResult<DfdlProp<String>>`

### 2.3 Évaluation Haute Performance ([`delimiters.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs))
```rust
pub(crate) fn evaluate_prop_at(
    &mut self,
    prop: &crate::schema::ir::DfdlProp<String>,
    builder: &InfosetBuilder,
    elem_name: Option<&str>,
    namespaces: Option<&[(alloc::string::String, alloc::string::String)]>,
) -> DFDLResult<String> {
    match prop {
        crate::schema::ir::DfdlProp::Constant(s) => Ok(s.clone()),
        crate::schema::ir::DfdlProp::Expression { ast, .. } => {
            self.evaluate_ast_at(ast, builder, elem_name, namespaces)
        }
    }
}
```
- Pour les constantes : retour immédiat en $O(1)$ sans aucun parsing ni scan de chaîne.
- Pour les expressions : évaluation directe de l'AST dans le contexte d'expression, sans appel à `parse_expr`.
