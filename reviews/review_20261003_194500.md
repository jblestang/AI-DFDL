## 1. Domain Expertise Analysis

### XML Schema (W3C XSD 1.0) & TDML Conformance
- **`elementFormDefault` Handling**:
  - Per W3C XML Schema 1.0 §3.15.2, `elementFormDefault` on `<xs:schema>` defaults to `"unqualified"`. This ensures local element declarations in schemas lacking an explicit `elementFormDefault` are unqualified, while global element declarations are in `targetNamespace`.
  - In TDML (`<tdml:defineSchema>`), per the TDML specification and Apache Daffodil reference behavior, `elementFormDefault` defaults to `"qualified"`. The synthetic `<xs:schema>` wrapper preserves this distinction.
  - Standard XSD attributes (`name`, `ref`, `type`, `form`, `minOccurs`, `maxOccurs`) on `<xs:element>` are strictly unprefixed. Elements specifying DFDL extension attributes (e.g. `dfdl:ref="be"`) are no longer erroneously treated as referencing a global XSD element declaration.
- **Ambient Namespace Propagation**:
  - TDML test files declare ambient namespaces and default namespaces on enclosing structures (`<tdml:testSuite>`, `<tdml:infoset>`).
  - When serializing infoset XML buffers in TDML test execution, in-scope namespace bindings (including the ambient default namespace and prefix mappings like `tns`) are emitted onto the infoset root element, guaranteeing that infoset elements resolve identically during test verification and unparsing.

### Unparser Engine & Infoset Invariants
- **Clark Notation**:
  - Implemented `QName::clark_notation(&self) -> String` (`{uri}local` or `{}`local) conforming to James Clark's universal XML naming notation.
  - All unparse diagnostics (element mismatch, unconsumed child elements, missing required elements) report Clark notation, matching TDML expectation patterns precisely.
- **Sequential Child Cursor Matching**:
  - Complex elements and sequences now track unparsing via `child_cursor: usize`.
  - Sequential matching enforces exact `QName` equality between the schema declaration and the received infoset node.
  - Complex element model groups verify that upon sequence completion, no unexpected unconsumed child nodes remain in the infoset (`"Unparse Error: expected element end for '{uri}parent', but received element start '{uri}child'"`).
- **Index Safety & Bound Checks**:
  - Replaced all direct slice indexing (`parent.children[cursor]`) with checked `.get(cursor)` access across `UnparserEngine`.
  - Clippy check `--workspace --all-targets` passes with 0 errors and 0 warnings.
