## 1. Domain Expertise Analysis & Conformance Framework

### A. Separation of AST Construction vs. Component Compilation (DFDL Spec §5, §6)
In standard XSD and DFDL processing, a single schema document or schema set may contain multiple element declarations, complex types, and annotations:
- In test suites (such as the Apache Daffodil TDML benchmark), a single `.dfdl.xsd` or embedded `<tdml:defineSchema>` commonly hosts both valid elements under test and unreferenced negative-test elements (e.g., an intentional facet contradiction such as `minInclusive > maxInclusive`, an empty `testPattern`, or conflicting assertion attributes).
- Eager validation during XML reading (`parse_element_node`, `parse_annotation_container`, `defineEscapeScheme`) prematurely aborted schema file loading even when the test runner targeted a completely separate, valid element (`e5`, `shishishishi`, `e2`).
- Conformance requires separating syntax capture into the XSD AST from semantic compilation (`compile_element` / `lower_term_to_ir`). Semantic validation must only apply to components reachable from the root element of the schema compilation target, while recording construct-level errors (via `assert_errors`) so that unreferenced negative tests do not block valid tests, yet still fail with `SchemaDefinition` errors whenever they are compiled.

### B. DFDL Escape Schemes & References (DFDL §13.2.1)
- **Definition & Syntax:** `<dfdl:defineEscapeScheme name="NCName">` requires an NCName (which must not contain a colon `:`) and must contain a child `<dfdl:escapeScheme>`. If the child element is missing, an explicit Schema Definition Error ("The content of element 'dfdl:defineEscapeScheme' is not complete") is required.
- **Reference Resolution:** Elements and formats bind an escape scheme via `dfdl:escapeSchemeRef="QName"`. Setting `escapeSchemeRef=""` explicitly indicates that no escape scheme is in effect. When referenced, escape scheme properties (`escapeKind`, `escapeCharacter`, `escapeEscapeCharacter`, `escapeBlockStart`, `escapeBlockEnd`, etc.) extend the element's effective property store.
- **Deferred Property Validation:** In shared test schemas, escape schemes defined with deliberate whitespace errors (e.g. `[ start ]` without entity references) for negative testing must validate when referenced by an element under test (`resolve_escape_scheme_ref`), rather than failing top-level schema ingestion.

### C. OccursCountKind Scope and Applicability (DFDL §16.1)
- Per DFDL §16.1 ("Properties for Array Elements and Optional Elements"), `dfdl:occursCountKind` is strictly applicable to array elements (`elem.is_array()`, where `maxOccurs != 1`).
- Default format annotations frequently specify `occursCountKind="expression"` globally. Scalar elements (`minOccurs="1"`, `maxOccurs="1"`) inheriting this default do not evaluate `dfdl:occursCount`. Enforcing `occursCount` presence on scalar elements violated §16.1.

### D. Model Groups & Choice Branches (DFDL §14, §15)
- **Choice Branch Occurrences:** DFDL §15 permits optional choice branches (`minOccurs="0"`). Eagerly rejecting `minOccurs="0"` on choice branches was non-conforming and broke multiple valid choice branch schemas.
- **Hidden Groups with Complex Members:** Under DFDL §14.2.1 / §14.2.2, hidden groups cannot output infoset elements. Any simple element within the hidden group must define `dfdl:outputValueCalc` or be defaultable. When a hidden group contains complex elements (`InlineSequence`, `InlineChoice`, `Complex(QName)`), validation must recurse into child elements rather than rejecting the complex container as a non-defaultable scalar.
- **Choice Dispatch Key and Ranges:** Daffodil extension schemas support specifying both discrete keys (`choiceBranchKey`) and contiguous ranges (`choiceBranchKeyRanges`) on the same choice branch.

### E. Number Representation & Calendar Constraints (DFDL §13.7.1, §13.12)
- **Empty Exponent Representation:** `textStandardExponentRep` is a DFDL String Literal; declaring `textStandardExponentRep=""` explicitly disables exponent representation and must not be treated as a missing property.
- **BCD Calendar Constraints:** Delimiter character prohibition (`-`, `/`, etc.) in `dfdl:calendarPattern` applies exclusively when `representation="binary"`, `calendarPatternKind="explicit"`, and `binaryCalendarRep="bcd"`. It does not apply to text calendar representations or implicit calendar patterns.
