## 1. Executive Summary & Defect Scope (Issue F6)

### 1.1 Specification Baseline (DFDL v1.0 §7.7 `dfdl:setVariable`)
- In DFDL, `dfdl:setVariable` mutates the runtime value of an in-scope DFDL variable.
- In the unparsing direction, when elements or terms inside a container modify a variable, subsequent elements that reference that variable (for instance through `dfdl:outputValueCalc` or dynamic expressions) must observe the updated variable value.
- For prefixed complex elements (`dfdl:lengthKind="prefixed"`), the unparser buffers the element payload in an inner `UnparserEngine` (`sub_unparser`) to calculate its serialized byte/bit length and write the prefix length before the payload.
- Previously, `self.variable_map` was cloned into `sub_unparser.variable_map`, but upon completion of `sub_unparser.unparse_term(child_id, elem)`, the modified `sub_unparser.variable_map` was discarded, leaving the parent `self.variable_map` with stale values.

## 2. Technical Implementation & Fixes

### 2.1 Variable Map Propagation ([crates/dfdl-core/src/kernel/unparser.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs#L1697-L1703))
- Extracted the mutated `variable_map` from `sub_unparser` and assigned it back to `self.variable_map` after `sub_unparser.unparse_term` succeeded and unconsumed child validation passed:
  ```rust
  let updated_vmap = sub_unparser.variable_map.clone();
  drop(sub_unparser);
  self.variable_map = updated_vmap;
  sub_writer.flush()?;
  let buf = sub_writer.into_sink().into_vec();
  ```
- Dropping `sub_unparser` before `sub_writer.flush()` releases the mutable borrow on `sub_writer` cleanly, avoiding borrow conflicts while guaranteeing rollback semantics: if `sub_unparser.unparse_term(...)` fails, the `?` operator aborts early without mutating `self.variable_map`.

### 2.2 Formal Reproduction Test Added ([crates/dfdl-tests/src/lib.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-tests/src/lib.rs#L5355-L5470))
- Added `prefixed_complex_unparse_must_preserve_set_variable`:
  - Defines variable `v` with initial value `0`.
  - Defines a prefixed complex `PrefixComp` with 2-byte prefix length (`prefixLengthType="ex:prefixShort"`).
  - Inside `PrefixComp`, child `Sub` contains `"A"` (`0x41`) and executes `<dfdl:setVariable ref="ex:v">{ 7 }</dfdl:setVariable>`.
  - Sibling element `Follow` uses `dfdl:outputValueCalc="{ xs:string($ex:v) }"`.
  - Verifies that the unparsed byte stream produces exactly `[0x00, 0x01, 0x41, 0x37]` (`00 01 41 37`), proving that `Follow` evaluated `$ex:v` as `7` rather than `0`.
