# Code Review: NATO STANAG 5602 Framing Synchronization & Wireshark Dissector Alignment

**Date / Timestamp:** 2026-11-02T22:17:00+01:00  
**Domains:** Military Tactical Data Links, NATO STANAG 5602 (SIMPLE), Packet Dissection (Wireshark), Protocol Synthesis & Testing

---

## 1. Context & Problem Formulation
- **Observed Behavior in Wireshark:**
  When PCAP captures containing nominal/valid NATO STANAG 5602 (SIMPLE) packets generated by `dfdl-pcap-gen` were opened in Wireshark, the packets were systematically flagged with:
  - `[Bad sync bytes]` (Wireshark filter: `simple.sync_bytes.bad: True`)
  - Info column displaying `Entete inconnue 0x0203` (or `0x0100`).
- **Root Cause Analysis:**
  - Wireshark's built-in `SIMPLE` dissector (`packet-simple.c`) checks the first 16 bits of the UDP application payload:
    - Byte 0: `sync1` (`0x49`, ASCII `'I'`, decimal 73)
    - Byte 1: `sync2` (`0x36`, ASCII `'6'`, decimal 54)
    - Header magic word: `0x4936` (Big-Endian) or `0x3649` (Little-Endian).
  - In `crates/dfdl-example/schemas/stanag5602_simple.dfdl.xsd`, the `SimplePacketType` definition omitted the two synchronization octets and started directly with `version` (1 or 2) and `securityClassification` (0..4).
  - As a result, valid packets had `0x02 0x03` at offset 0, which failed Wireshark's sync verification.

---

## 2. Changes Made
1. **DFDL Schema Alignment (`crates/dfdl-example/schemas/stanag5602_simple.dfdl.xsd`):**
   - Added `SyncByte1Type` constrained to enumeration value `73` (`0x49`).
   - Added `SyncByte2Type` constrained to enumeration value `54` (`0x36`).
   - Added `sync1` and `sync2` as the first two elements of `SimplePacketType` with `default="73"` and `default="54"`.
   - Updated header length specification to 30 octets (2 sync bytes + 28 transport header bytes).
2. **Nominal Payload Generator (`crates/dfdl-payload-generator/src/valid.rs`):**
   - Updated `build_element` to check `elem.default_value` before generating random values for simple types, ensuring schema-defined default/fixed synchronization constants are always preserved in nominal generation.
3. **Integration Tests & Examples:**
   - Updated `create_sample_packet_full` in `crates/dfdl-example/tests/test_stanag5602_simple.rs` to prefix packets with `0x49, 0x36`.
   - Updated `build_simple_packet` in `crates/dfdl-example/examples/stanag5602_simple.rs` to prefix packets with `0x49, 0x36`.
   - Enhanced `test_valid_payload_generation_stanag5602_simple` in `crates/dfdl-payload-generator/tests/test_payload_generator.rs` to assert `payload.bytes[0] == 0x49` and `payload.bytes[1] == 0x36`.
