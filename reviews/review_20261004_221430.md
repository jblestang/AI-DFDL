## 2. Multi-Domain Expertise Assessment

### A. DFDL 1.0 & XML Schema (XSD) Domain Expertise
- **Element Ref vs DFDL Format Ref Separation (DFDL §7.1, W3C XSD 1.0 §3.3.2):**
  - In `compile_element`, `<xs:element ref="...">` specifies an XSD element reference to a global element declaration. Previously, `local_props.set_property("ref", r)` stored this XSD element reference under the property key `"ref"`, which was subsequently treated by `resolve_ref_formats` as a `dfdl:defineFormat` reference.
  - Fix: Decoupled XSD element reference storage (`"__dfdl_element_ref"`) from DFDL format reference storage (`"ref"`). Added `PropertyStore::remove_property` and guarded `lower_element_to_ir_bounded` so element references never corrupt format resolution.
  - Conformance impact: Fixed schema compilation failure in `test_debug_property_scoping_s3` and prevented false format lookups.

- **Element Ref Mutual Exclusivity (W3C XSD 1.0 §3.3.2):**
  - In XML Schema, an element declaration specifying `ref` cannot also declare `type` (and `name` is forbidden or redundant).
  - Implemented validation in `compile_element`: when `ref` is present, `type` is rejected with `Schema Definition Error: The 'name' and 'type' attributes cannot appear when 'ref' is specified on an element declaration`.
  - Conformance impact: Resolved `nameAndRefError_01` (**PASS**).

- **xs:restriction Base Type Validation (W3C XSD 1.0 §3.14.3):**
  - In `<xs:simpleType><xs:restriction base="...">`, when `base` is prefixed with an XML Schema namespace prefix (e.g. `xs:` or `xsd:`), the referenced type must be a recognized built-in XML Schema primitive or derived simple type.
  - Previously, `parse_xsd_type_name` defaulted unrecognized types to `XsdType::Complex(...)`, allowing invalid types such as `xs:nonExistent` to be accepted without raising a Schema Definition Error.
  - Added strict validation rejecting unknown base types in the XSD namespace.
  - Conformance impact: Resolved `errorLocations_01` (**PASS**).

- **Diagnostic Location Context for Imported/Included Schemas (DFDL §3.2):**
  - Errors occurring within recursively imported or included schema documents are now annotated with the import `location` URI.
  - Conformance impact: Allows diagnostics to identify the offending sub-schema document (e.g., `multi_C_13.dfdl.xsd`).
