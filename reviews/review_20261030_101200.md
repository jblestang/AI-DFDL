## 2. Profile Hotspots & Root Cause Analysis

### Hotspot 1: BitReader & BitWriter Bit-by-Bit Shift Loop Overhead
- **Location:** [`crates/dfdl-core/src/io/bitstream.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/io/bitstream.rs) `read_bits` and `write_bits`.
- **Root Cause:** Primitive integer extraction and serialization unconditionally routed all reads and writes through a `while bits_needed > 0` loop with bit shifts, masking, and buffer updates—even when the reader/writer was strictly byte-aligned (`bits_in_buf == 0`) and operating on whole scalar primitives (8, 16, 32, 64 bits).
- **Remediation:** Added `#[inline]` byte-aligned fast-paths for 8, 16, 32, and 64-bit operations. When `bits_in_buf == 0`:
  - 8-bit reads/writes delegate directly to single-byte source/sink operations (`read_byte()` / `write_byte()`).
  - 16, 32, and 64-bit operations read/write raw byte chunks directly in big-endian (MSBF) or little-endian (LSBF) byte order, completely bypassing bitwise shift arithmetic.

### Hotspot 2: Delimiter Matching Checkpoint & Token Re-Parsing Churn
- **Location:** [`crates/dfdl-core/src/kernel/parser/delimiters.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs) in `match_literal_delimiter`, `peek_literal_delimiter`, and `peek_delimiter_match_length`.
- **Root Cause:** In `match_literal_delimiter`, single-alternative delimiters were evaluated twice: once during candidate ranking with checkpoint/rollback, and a second time by re-parsing tokens (`parse_single_delim_tokens`) and re-executing `match_single_delim_tokens_with_case`. Furthermore, `match_single_delim_tokens_with_case` performed an owned clone of `expected_bytes` on every literal token match.
- **Remediation:**
  1. Borrowed `expected_bytes: &[u8]` directly without cloning when encoding is UTF-8 or ASCII.
  2. Implemented byte-aligned slice lookahead: when the reader is byte-aligned and matching literal ASCII/UTF-8 delimiters without `%` entities, it performs an in-place slice comparison using `peek_bytes()` and advances with `skip_bits()`, skipping all intermediate token allocations and checkpoints.
  3. Short-circuited single-alternative delimiters to execute matching directly in a single pass.

### Hotspot 3: Sequence Child Unparse String Formatting
- **Location:** [`crates/dfdl-core/src/kernel/unparser/mod.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser/mod.rs) lines 370 and 616.
- **Root Cause:** Each child element occurrence within sequences allocated an owned string (`alloc::format!("{}[{}]", child_elem.name.local_name, idx.saturating_add(1))`), passed it to `unparse_element_with_seg`, which then invoked `PathStep::from_segment` to re-parse the string into index and target components, only to pop it off at the end.
- **Remediation:** Replaced string formatting with `unparse_element_with_index(term_id, elem, occurs_index)`. Structured `PathStep` instances are now pushed directly to `current_path` via `try_push_step`, eliminating all temporary string heap allocations.

### Hotspot 4: Binary & Text Calendar Allocations
- **Location:** [`crates/dfdl-core/src/kernel/unparser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser/element.rs) and [`crates/dfdl-core/src/kernel/parser/calendar.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/calendar.rs).
- **Root Cause:** BCD and Packed calendar formatting allocated temporary `String` instances and collected BCD digits into heap-allocated `Vec<u8>`. `format_calendar_with_pattern` also allocated heap strings via `to_ascii_lowercase()` on every element format.
- **Remediation:**
  1. Utilized a 64-byte stack buffer (`[u8; 64]`) for BCD and packed digits in `unparse_binary_calendar`. When `calendar_pattern` is empty, digits are extracted directly from `s_val.bytes()`.
  2. Replaced `to_ascii_lowercase()` with zero-allocation slice checks (`eq_ignore_ascii_case`).
  3. Utilized a 64-character stack buffer (`['\0'; 64]`) for pattern parsing in `parse_calendar_with_pattern`.

### Hotspot 5: Mandatory Alignment Encoding Clone & Text Vector Sizing
- **Location:** [`crates/dfdl-core/src/kernel/parser/text.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/text.rs).
- **Root Cause:** `check_mandatory_alignment` took `EncodingKind` by value, triggering `props.encoding.clone()` on every parsed text value. Furthermore, `parse_text_value` started with an empty `Vec::new()`, resulting in multiple `RawVec::try_reserve` heap reallocations.
- **Remediation:** Changed `check_mandatory_alignment` to borrow `&props.encoding` and pre-allocated `bytes` with capacity `Vec::with_capacity(byte_len.min(1024))`.
