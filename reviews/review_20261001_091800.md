## 2. Root Cause Analysis & Architectural Resolutions

The analysis of the 456 tests failing with "Expected Error Not Raised" revealed 6 core structural omissions in the parser and schema compiler where invalid inputs or illegal schema definitions were silently accepted instead of raising specification-mandated errors:

### A. IEEE-754 Floating-Point NaN Incomparability Facet Validation (XSD Part 2 §3.2.4 & §3.2.5)
- **Defect:** In standard IEEE-754 semantics, `NaN < bound`, `NaN > bound`, `NaN <= bound`, and `NaN >= bound` all evaluate to `false`. The existing facet bounds checking `if num < bound` failed to trigger for `NaN`, silently allowing `NaN` values to pass `minInclusive`, `maxInclusive`, `minExclusive`, and `maxExclusive` facet constraints.
- **Architectural Fix:** Implemented explicit partial comparison logic via `matches!(num.partial_cmp(&bound), ...)` ensuring that any incomparable value (`NaN`) fails every inclusive and exclusive range facet, while properly preserving `+INF` and `-INF` unbounded relationships.

### B. Enumeration Facet Uniqueness Enforcement (XSD Part 2 §4.3.5.3)
- **Defect:** Duplicate `<xs:enumeration value="..."/>` tags within a simpleType restriction were silently accepted into the property store.
- **Architectural Fix:** Enforced the XML Schema Part 2 constraint that enumeration facets within a type restriction must be unique. `PropertyStore::add_enumeration` now verifies uniqueness and raises a Schema Definition Error upon duplicate declaration.

### C. Choice Point Discriminator Context & Backtracking (DFDL §7.5 & §15.1)
- **Defect:** Discriminator evaluation inside choice branch elements lacked access to the compiled schema (`ctx.schema` was `None`), causing `{ dfdl:checkConstraints(.) }` and custom XPath expressions on choice elements to fail silently or succeed erroneously without validating branch constraints.
- **Architectural Fix:** Threaded the active schema into `ExprContext::with_schema` during both choice branch discriminator evaluation and element-level discriminator evaluation. When all alternatives fail their discriminators or parsers, the choice fails with `"Parse Error: All Choice Alternatives Failed: All choice branches failed to parse or satisfy discriminators"`.

### D. Choice Branch Element MinOccurs Constraint (DFDL §15)
- **Defect:** DFDL §15 explicitly prohibits `<xs:element ... minOccurs="0"/>` as an immediate branch of `<xs:choice>`, because an optional branch makes the choice always succeed vacuously. The compiler previously accepted `minOccurs="0"` on choice branches.
- **Architectural Fix:** Enforced `elem.min_occurs > 0` validation on all direct element children of `<xs:choice>` during schema compilation.

### E. OccursCountKind="fixed" Cardinality Equivalence (DFDL §16.1)
- **Defect:** When `dfdl:occursCountKind="fixed"`, the specification requires `minOccurs` and `maxOccurs` to be explicitly defined and identical. Schema compilation was not enforcing this equivalence, allowing variable ranges under fixed occurs policy.
- **Architectural Fix:** Added validation in `lower_element_to_ir_bounded` requiring `elem.max_occurs == Some(elem.min_occurs)` when `occursCountKind="fixed"`.

### F. Simple Type Facet Applicability & Integer Bound Overflow
- **Defect:** Facet checks previously allowed `totalDigits` on non-numeric types, `fractionDigits` on non-decimal types, string range facets on integers, and integer bounds that exceeded the target integer type width (e.g. `maxInclusive="500"` on `xs:byte`).
- **Architectural Fix:** Implemented `validate_simple_type_facets` to enforce type applicability and numeric representation bounds across all numeric types before emitting compiled IR.

## 3. Domain Expertises & Review Remarks

### A. Formal Language & Specification Conformance Review
- **Finding:** The separation between XSD simple type facets (e.g. `minLength`, `maxLength`) and DFDL properties (e.g. `dfdl:length`) is critical. In DFDL, `dfdl:length` is applicable to all simple types when `lengthKind="explicit"`, whereas `xs:maxLength` is restricted to `xs:string` and `xs:hexBinary`. The fix properly isolates facet validation from DFDL format properties.
- **Verification:** TDML test cases with explicit length on integers and decimals pass without schema rejection.

### B. Embedded Systems & `#![no_std]` Safety Review
- **Finding:** All newly added validation logic uses `alloc::format!`, `matches!`, and `core::cmp::Ordering`. No standard library dependencies (`std::*`) were introduced into `dfdl-core`, `dfdl-xml`, or `dfdl-schema`.
- **Verification:** Target check `cargo check --target thumbv7m-none-eabi -p dfdl-core -p dfdl-xml -p dfdl-schema` passed cleanly with 0 warnings.

### C. Security & Robustness Review
- **Finding:** The rejection of `NaN` on range facets eliminates potential logic bypass vulnerabilities where out-of-spec or poisoned floating point data could bypass schema-enforced range validations.
- **Verification:** Unit tests confirm `NaN` produces an immediate `DFDLErrorKind::Validation` error without panicking.
