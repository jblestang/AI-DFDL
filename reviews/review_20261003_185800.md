## 2. Detailed Technical Review

### 2.1 Binary Representation for `xs:decimal` and Bit Length Bounds (§13.7)
- **Problem**: When simple elements of type `xs:decimal` were unparsed with `representation="binary"` and `binaryNumberRep="binary"`, `unparser.rs` previously wrote raw ASCII string bytes (`'1' = 0x31`) instead of packing into two's complement binary integers according to `binaryDecimalVirtualPoint` and `props.byte_order`. Furthermore, minimum length checks (`is_unsigned_int`, `is_signed_int`) previously matched only `DfdlValue::Byte/Short/Int/Long`, ignoring `DfdlValue::Decimal` with `dfdl:decimalSigned`.
- **Solution**:
  - Generalized `is_unsigned_int` and `is_signed_int` checks in `unparse_binary_value`:
    - `is_unsigned_num`: matches unsigned integers or `DfdlValue::Decimal` with `!props.decimal_signed`.
    - `is_signed_num`: matches signed integers or `DfdlValue::Decimal` with `props.decimal_signed`.
  - Added binary decimal packing for `DfdlValue::Decimal(s)`: applies `scale = props.binary_decimal_virtual_point`, converts to scaled integer `val_i64 = (s * 10^scale).round()`, masks to `requested_bits_opt`, applies endianness (`ByteOrder::BigEndian` / `LittleEndian`), and outputs bits via `BitWriter`.
- **Validation**: Fixed `outOfRangeLengthBinaryDecimal3, 4, 6, 8, 10` with 100% pass rate. Added dedicated unit test `test_unparse_binary_decimal_signedness_and_bounds` verifying signed/unsigned bounds and virtual scale points.

### 2.2 XPath 2.0 F&O Functions & Type Constructors
- Implemented `fn:substring-before($source, $target)` and `fn:substring-after($source, $target)` in accordance with W3C F&O specification §7.4.5 & §7.4.6:
  - If `$target` is empty, `substring-before` returns `""`, while `substring-after` returns `$source`.
  - If `$target` is not found, both return `""`.
- Added constructor support for `date(...)`, `dateTime(...)`, `time(...)`, and `boolean(...)` into `eval_expr`.

### 2.3 Dynamic `dfdl:byteOrder` Property Evaluation
- Extended `ResolvedProperties` to retain `byte_order_expr: Option<String>`.
- Evaluated `byte_order_expr` dynamically during runtime element unparsing, allowing expressions such as `dfdl:byteOrder="{ ../order }"` to govern downstream binary unparsers.
