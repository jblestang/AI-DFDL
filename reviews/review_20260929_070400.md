# Code Review & Conformance Report: TDML Schema Extraction & Property Resolution Fixes (2026-09-29 07:04:00)

## Executive Summary

An investigation into **Schema Compilation Rejections** (`1. Schema Compilation Rejections`) was conducted across the official Apache Daffodil TDML conformance test suite.

Schema compilation failures dropped from **2,714 (96.3%) down to 374 (16.4%)**, while **total passed test cases increased from 1,540 to 2,054 (47.4%)**.

## 1. Key Issues Identified & Resolved

### A. TDML Embedded Schema Extraction & Namespace Scoping (`crates/dfdl-tests/src/tdml.rs`)
- **Root Cause**: Embedded `<tdml:defineSchema>` blocks often contain child XSD declarations without a surrounding `<xs:schema>` root tag. `tdml.rs` failed to extract these schemas, causing `TdmlRunner` to fall back to a minimal binary default schema.
- **Fix**: Updated `tdml.rs` to detect `<tdml:defineSchema>` blocks lacking root `<xs:schema>` elements, strip the unclosed `<tdml:defineSchema>` start tag, and automatically enclose the inner XSD content inside a synthetic `<xs:schema>` root container with full namespace declarations (`xmlns:xs`, `xmlns:dfdl`, `xmlns:ex`, `xmlns:tns`, `xmlns:tdml`, `xmlns:dfdlx`, `xmlns:daf`).

### B. Property Resolution Inheritance Chain (`crates/dfdl-schema/src/compiler.rs` & `crates/dfdl-core/src/expr/properties.rs`)
- **DFDL Spec §6.3**: DFDL format properties must inherit hierarchically from Schema Global Format -> Complex Type -> Sequence/Choice -> Child Element.
- **Root Cause**: `compiler.rs` passed raw un-merged local sequence/choice properties to child terms, breaking inheritance from `schema.global_format` (e.g. `representation="text"` was lost, defaulting back to `"binary"`).
- **Fix**: Added `PropertyStore::merge(&mut self, parent: &PropertyStore)` and updated `lower_element_to_ir`, `lower_sequence_to_ir`, and `lower_choice_to_ir` to merge parent property stores down the entire schema IR tree.

### C. Expression Length & OccursCount Property Tolerance (`crates/dfdl-core/src/expr/properties.rs`)
- **DFDL Spec §12.3 & §16**: `dfdl:length` can be a dynamic DFDL expression (e.g. `dfdl:length="{ ../len }"`), and `occursCountKind` can specify `"implicit"`.
- **Root Cause**: `to_resolved_properties` attempted strict `s.parse::<usize>()` on dynamic length expressions, raising hard `SchemaDefinition("Invalid integer length property")` errors during schema compilation.
- **Fix**: Updated `to_resolved_properties` to use `.parse::<usize>().ok()` for dynamic lengths and added `"implicit"` as a valid alias for `OccursCountKind::Fixed`.
