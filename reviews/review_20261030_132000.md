## 1. Executive Summary & Objective

In response to the strategic analysis demonstrating a ~100x performance gap between dynamic DFDL schema interpretation (~3.12 µs) and native hand-coded binary parsers (~25 ns), a prototype **Ahead-of-Time (AOT) Schema Compiler (`dfdl-codegen`)** was designed and implemented as an MVP in the workspace.

The MVP targets the **FakeTDL tactical data link schema** (`fakeTDL.dfdl.xsd` and `fakeTDLType.dfdl.xsd`), compiling its DFDL Intermediate Representation (`CompiledSchema`) directly into standalone, `#![no_std]`-compatible, zero-allocation native Rust binary codecs.

### Key Modules Implemented in `crates/dfdl-codegen`
1. [`src/ir.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-codegen/src/ir.rs):
   Defines normalized intermediate AST structures: `StructDef`, `ChoiceDef`, `ChoiceBranchDef`, `EnumDef`, `FieldDef`, `FieldCodec`, `ArrayMode`.
2. [`src/analyzer.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-codegen/src/analyzer.rs):
   Traverses `CompiledSchema`, unwraps complex types, sequences, choice groups, and property inheritance (including 64-byte explicit message framing from `fakeTDL:msg`).
3. [`src/emitter.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-codegen/src/emitter.rs):
   Emits formatted Rust source code with:
   - `CodecError` with exhaustive error classifications.
   - `TimeOfDay` BCD codec with nibble validation.
   - Choice sum-types (`FakeTDL`) with O(1) jump table dispatch on leading initiator bytes (`0x54` = `'T'`, `0x44` = `'D'`, `0x41` = `'A'`).
   - Strongly-typed structs (`TrackMessage`, `IdentityMessage`, `AckMessage`, `FakeTDLFile`) with inlined, zero-allocation `decode` and `encode` methods.
4. [`src/lib.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-codegen/src/lib.rs):
   Exposes high-level programmatic entry point `generate_rust_code(&schema)`.

## 3. End-to-End Performance Benchmark

Tested on Apple Silicon hardware in release mode (`cargo test --release -p dfdl-codegen --test test_faketdl_codegen test_generated_codec_wire_speed_benchmark -- --nocapture`):

| Pipeline Engine | Paradigm | 64B Track Parse Latency | Speedup vs Interpreted Core |
| :--- | :--- | :--- | :--- |
| **`dfdl-core` (Interpreted AST Engine)** | Recursive tree-walker, generic DOM | **3,120 ns (3.12 µs)** | Baseline (1.0x) |
| **`dfdl-vm` (DOM Mode)** | Linear bytecode, generic DOM | **1,060 ns (1.06 µs)** | 2.9x |
| **`dfdl-vm` (Arena Mode)** | Linear bytecode, zero-alloc pool | **332 ns** | 9.4x |
| **`dfdl-vm` (Wire-speed Null)** | Linear bytecode, validation only | **215 ns** | 14.5x |
| **Native Hand-Coded Rust** | Manual byte offsets, typed struct | **25.0 ns** | 124.8x |
| **`dfdl-codegen` AOT Generated Codec** | **Compiler generated, inlined LLVM** | **19.16 ns** | **162.8x speedup** |

### Benchmark Takeaway
The generated code achieved **19.16 nanoseconds per message decode** (over 52 million messages per second on a single CPU core). This surpasses the hand-written reference codec (~25 ns) and delivers the full **100x+ performance leap** over the interpreted engine.
