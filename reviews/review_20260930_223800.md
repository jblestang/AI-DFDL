## 2. Standards Compliance & Generic Fixes Implemented

### 1. BCD Disallow Signed Integer Types (DFDL 1.0 §13.7.1)
- **Specification:** Binary Coded Decimal (BCD) does not encode a sign nibble and represents non-negative numbers only. Allowed types are strictly `xs:decimal`, `xs:nonNegativeInteger`, and unsigned integer types derived from them (`xs:unsignedLong`, `xs:unsignedInt`, `xs:unsignedShort`, `xs:unsignedByte`). Signed integer types (`xs:long`, `xs:int`, `xs:short`, `xs:byte`) are strictly prohibited and must result in a Schema Definition Error.
- **Implementation:** In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), when `resolved_props.binary_number_rep == BinaryNumberRep::Bcd`, only unsigned scalar types and `Decimal` are allowed; any signed integer type triggers `"Schema Definition Error: Type '{:?}' is not an allowed type for bcd on element '{}'"`.
- **Unit Test:** `test_bcd_signed_integer_type_error` in `dfdl-schema`.

### 2. `lengthKind='implicit'` Prohibition for Packed Binary Formats (DFDL 1.0 §12.3.7.2)
- **Specification:** For binary representation, when `binaryNumberRep` is `packed`, `bcd`, or `ibm4690Packed`, `lengthKind='implicit'` is not allowed because the length is not fixed by the primitive type definition.
- **Implementation:** In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), if `representation == Binary` and `length_kind == Implicit` while `binary_number_rep != Binary`, the compiler emits `"Schema Definition Error: lengthKind='implicit' is not allowed with packed binary formats on element '{}'"`.
- **Unit Test:** `test_packed_implicit_length_error` in `dfdl-schema`.

### 3. Packed Binary Format Length & Alignment Bit Multiples (DFDL 1.0 §12.1, §13.7.1)
- **Specification:** Packed binary numbers encode 4-bit nibbles. When `lengthUnits="bits"`, explicit length must be greater than 0 and a multiple of 4. When `alignmentUnits="bits"`, alignment must also be a multiple of 4 bits.
- **Implementation:** In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), validated that `len > 0` and `len % 4 == 0` for bit length units, and `alignment % 4 == 0` for bit alignment units when using packed formats (`packed`, `bcd`, `ibm4690Packed`).
- **Unit Test:** `test_packed_bit_length_multiple_of_four_error` in `dfdl-schema`.

### 4. Calendar Pattern Sub-Nanosecond Fractional Seconds Limit (DFDL 1.0 §13.11)
- **Specification:** Calendar patterns support up to 9 consecutive `'S'` characters (nanosecond precision). Patterns containing more than 9 fractional seconds cannot be represented and must trigger a Schema Definition Error.
- **Implementation:** In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), scanned `calendarPattern` for unquoted `'S'` runs. If consecutive `'S'` count exceeds 9, raises `"Schema Definition Error: More than 9 fractional seconds unsupported in dfdl:calendarPattern for {xs:time|xs:dateTime|xs:date}"`.
- **Unit Test:** `test_calendar_pattern_fractional_seconds_excess_error` in `dfdl-schema`.

### 5. Unparser Explicit Length Exceeded & Number Truncation Prohibition (DFDL 1.0 §11.2, §13.6)
- **Specification:** When unparsing explicit-length textual fields, if the formatted data length exceeds the explicit length, numbers, dates, times, and booleans can NEVER be truncated. Only `xs:string` may be truncated, and only if `truncateSpecifiedLengthString="yes"`.
- **Implementation:**
  - Added `truncate_specified_length_string: bool` to [`ResolvedProperties`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs).
  - Resolved `dfdl:length` dynamic expressions in [`UnparserEngine::resolve_explicit_length`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs).
  - Enforced in `unparse_text_value` that if unit length exceeds `target_len`, non-string values or strings with `truncateSpecifiedLengthString="no"` raise `"Unparse Error: Data length ({}) exceeds explicit length ({}) and cannot truncate"`.
- **Unit Test:** `test_unparse_number_truncation_prohibited_error` in `dfdl-core`.

### 6. Discriminator and Assert Mutual Exclusion & Multiple Discriminator Prohibition (DFDL 1.0 §7, §15)
- **Specification:** A component can contain at most one `dfdl:discriminator`. A component cannot contain both a `dfdl:discriminator` and one or more `dfdl:assert` statements.
- **Implementation:**
  - In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs) `parse_annotation_child`, reject multiple `<dfdl:discriminator>` statements and reject co-occurrence of `<dfdl:assert>` and `<dfdl:discriminator>`.
  - In [`crates/dfdl-core/src/expr/properties.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs) `to_resolved_properties`, reject if `discriminator` and `asserts` are both present on the resolved property store.
- **Unit Tests:** `test_both_discriminator_and_assert_error` and `test_multiple_discriminator_error` in `dfdl-schema`.
