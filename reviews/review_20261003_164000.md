# Review 2026-10-03 16:40 - Variable declaration validation

Scope: dfdl-schema compiler (defineVariable, setVariable, newVariableInstance).

## Changes
- `resolve_variable_value`: value given as attribute XOR element body (DFDL 7.2, 7.7). Applied to top-level defineVariable, annotation defineVariable/newVariableInstance and setVariable.
- setVariable refs must be distinct per annotation; newVariableInstance refs distinct; NVI forbidden on xs:element.
- Per-component errors are deferred via `add_assert_error` (raised only for reachable components, as Daffodil does). Top-level defineVariable errors stay eager.

## Remarks
- Safety: no panics/unwrap; only string comparisons.
- Spec gap: distinctness is checked per annotation block, not across several appinfo blocks on one component.
- NVI-on-element detection relies on `component_tag == "xs:element"`; `xsd:` prefixed schemas are not covered.
- Conformance 706 -> 699, zero regressions. Remaining variable tests (setAfterReadErr, varInstance_06/08, circular, no-default reads, direction errors) need runtime checks: not done yet.
- A first attempt with eager errors regressed 26 tests (shared TDML schemas hold intentionally bad components); fixed by deferral.
- Earlier work not yet recorded here: byte-encoding error policy, requireEncodingErrorPolicy tunable, UTF-8 lossy/malformed handling, US-ASCII parse policy left as "replace" (Daffodil quirk).

## Addendum 2026-10-03 (escape schemes, tunables, explicit length, fillByte)
- extraEscapedCharacters now validated like other escape properties (single-char items, no byte/class entities). Escape-vs-delimiter conflict SDE for element terminator / direct parent separator (expression and entity escapes skipped: runtime-only).
- Escape schemes are merged into element properties but NOT applied by the parser/unparser kernel: this is a functional gap, only compile-time validation was added.
- requireTextBidiProperty / requireFloatingProperty tunables (same pattern as encodingErrorPolicy).
- lengthKind=explicit without length: SDE only when declared on the element itself and not a ref (inherited default-format values and refs legitimately lack a local length; a generic check regressed 40 tests).
- fillByte: ResolvedProperties.fill_byte_defined + lazy SDE at padding sites. alignmentFillByteNotDefined still fails: merge_parent leaks a sequence-level fillByte attribute into children, so it looks defined (known limitation).
- Conformance 699 -> 684, zero regressions at each step.
