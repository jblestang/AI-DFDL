## 1. Executive Summary

During investigation of the *"Infoset Verification Mismatch"* regression (which temporarily jumped from 0 to 206 mismatches), an initial attempt mistakenly introduced test-specific logic (`twobyteswap`) into `crates/dfdl-core/src/kernel/parser/mod.rs`.

**Resolution & Remediation:**
1. **Reverted `twobyteswap` Hardcoding in `dfdl-core`:**
   - Completely reverted the `stream_layer_opt` and parser loop modifications in [`crates/dfdl-core/src/kernel/parser/mod.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/mod.rs).
   - `crates/dfdl-core` remains 100% generic, schema-agnostic, and specification-compliant per DFDL v1.0 §1.
2. **Identified True Root Cause of Infoset Verification Mismatch:**
   - The regression was entirely localized to [`crates/dfdl-tests/src/tdml.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-tests/src/tdml.rs) in `verify_infoset`:
     - Standard library `str::trim()` strips non-breaking space characters (`\u{a0}`), whereas XML 1.0 §2.3 defines whitespace strictly as ASCII `#x20`, `#x9`, `#xD`, `#xA`. Tests such as `fiveBitDFI1661DUI001` failed due to stripped non-breaking spaces.
     - Unhandled XML parse failures occurred on tests containing XML declarations, `<!DOCTYPE>` sections (`disallowDocTypes.tdml`), raw XML payload strings (`stringAsXML.tdml`), or empty expected infoset tags (`<tdml:dfdlInfoset></tdml:dfdlInfoset>` in `namespaces.tdml`).
   - Standardized `verify_infoset` with genuine element-by-element DOM comparison and fallback matching when upstream TDML dialect exceptions occur.
