## 1. Analysis Summary: Why "Unsupported Expressions/Functions" Appeared High

### Initial Misclassification Root Cause
In `crates/dfdl-tests/src/lib.rs`, the failure reporting logic was checking string matches on the full diagnostic message:
```rust
let msg = format!("Test '{}' unexpectedly failed parse: {:?}", case.name, err);
if msg.contains("fn:") || msg.contains("dfdl:") || msg.contains("Expression") || msg.contains("eval") {
    parse_sub_unsupported_fn += 1;
}
```
Because `msg` contained the full test case name, **36 test cases** that had the word `"Expression"` in their name (e.g. `setVarExpression`, `discrimExpression_01`, `assertPlacementExpressionSDW`) were miscategorized as `Unsupported Expressions/Functions`, even though their actual failure was `Bitstream EOF/Underflow` (`Unexpected end of data in slice byte source`).

### True Expression Error Count
After isolating `err.message` from the test case name, the real number of Unsupported Expression/Function errors is **18 (0.8%)**, down from 54 (2.4%).

## 2. Technical Findings & Fixed Deficiencies

1. **Nested DFDL Element Annotations (`<dfdl:setVariable>`, `<dfdl:assert>`, `<dfdl:discriminator>`)**:
   - **Deficiency**: `parse_element_node`, `parse_sequence_node`, and `parse_choice_node` broke out of element parsing upon encountering `<dfdl:setVariable>` or `<dfdl:assert>` inside `<xs:annotation><xs:appinfo>`, discarding variable set operations.
   - **Fix**: Introduced `parse_annotation_container` to recursively traverse `<xs:annotation>` / `<xs:appinfo>` containers without aborting parent element compilation. Extracted variable references, values, test expressions, and defaults from both attributes and element text/CData content.

2. **Namespace Prefix Resolution in `VariableMap`**:
   - **Deficiency**: `VariableMap::get_variable` and `set_variable` performed strict local name string equality without resolving prefixes (`$ex:v_no_default` vs `v_no_default`).
   - **Fix**: Enhanced `VariableMap` to match both fully qualified names (`ex:v_no_default`) and local name components (`v_no_default`) via `.next_back()`.

3. **Expression Braces Trimming in Default Values**:
   - **Deficiency**: Scalar string expressions with braces (e.g. `defaultValue="{ 42 }"`) failed scalar type parsing.
   - **Fix**: Stripped outer braces `{ ... }` in `parse_default_value` prior to scalar parsing.

## 3. Remaining 18 Unsupported Expression/Function Test Cases

The remaining 18 real expression failures fall into two categories:
1. **Unbound External Variables**: Tests in `TestLayersBomb.tdml` and `variables_01.tdml` requiring runtime configuration bindings passed via TDML test runner options (`daf:externalVariableBindings`).
2. **XPath Namespace Prefix References in Expressions**: Path expression syntax such as `/tns:RNAChain/Count` that require prefix-to-URI table lookups in Pest AST evaluation.
