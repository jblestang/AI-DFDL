# Review 2026-10-03 08:55

Scope: audit of old fix plan (maxOccurs optional, layers, decimalSigned, signed-binary min length);
implementation of `allowSignedIntegerLength1Bit` tunable.

## Audit result (conformance run, 787 failures before -> 780 after)
- maxOccurs for optional elements: no remaining failing tests. Only `maxOccursBoundsExceeded`
  (needs the `maxOccursBounds` tunable, not implemented) relates to maxOccurs.
- decimalSigned negative rejection: no remaining failing tests (`validate_unparse_value`).
- Layers (~57 failures): mostly Daffodil Java SPI "Bomb"/"testBad*" layers (Java classes,
  META-INF services) that cannot exist in this Rust engine; real gap = gzip/base64/IMF layer
  transforms (`gzipLayer1`, `base64GzipLayers1`, `foldedIMFBase64Layers1`). Not implemented.
- Signed binary min length: root cause was missing Daffodil tunable (default: 1-bit signed allowed,
  read as unsigned). Implemented. Fixed 7 tests; `outOfRangeLengthBinaryInteger5` still fails
  (len element is empty in infoset + OVC, expects unparse error with tunable off).

## Changes
- `CompiledSchema.disallow_signed_integer_length_1bit` (default false) set by
  `SchemaCompiler::with_allow_signed_integer_length_1bit`.
- Parser/unparser/compiler gate the 1-bit error on that flag; 0-bit signed stays an error.
- `sign_extend`: 1-bit reads as unsigned.
- TDML runner: parses `defineConfig` + `config=`, cache key includes the tunable.
- Unparser: OVC result coerced to the element's simple type (fixes unsignedByte written as 4 bytes).
- Test `test_binary_integer_bit_length_bounds_rejection` case 2 now uses the tunable-off compiler
  (old always-reject expectation was the bug).

## Remarks
- Only the one tunable is parsed from `defineConfig`; other tunables are ignored silently.
- `coerce_and_validate_ivc_value` returns Parse-kind errors; OVC path ignores them (falls back to raw
  value) so behaviour is unchanged on failure.
- `bitOrderOVC1` now fails differently (wrong bytes) - separate pre-existing bug, not investigated.
- Safety: no new unwrap/unchecked arithmetic in non-test code.
