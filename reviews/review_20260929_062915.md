## 1. Summary of Standard-Compliant Fixes

### A. Delimited Scanner Lookahead (`peek_literal_delimiter`)
- **DFDL 1.0 Spec §12.3.2**: `lengthKind="delimited"` text fields are bounded by in-scope delimiters OR End of Data (EOF).
- **Fix**: Added `peek_literal_delimiter(&mut self, delimiter: &str) -> bool` in [`crates/dfdl-core/src/kernel/parser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L284-L292). In `parse_text_value`, peeking multi-byte delimiters (`separator` and `terminator`) avoids overreading past delimiter boundaries or throwing raw bitstream underflows.

### B. Soft Binary & Explicit Length Field Bounds (`read_binary_bits`)
- **DFDL 1.0 Spec §12.3.3**: Attempting to read a fixed-length binary or text scalar when insufficient bits remain in the bitstream is a **Parse Error** (processing error).
- **Fix**: Added `read_binary_bits(&mut self, bits: usize) -> DFDLResult<u64>` in `crates/dfdl-core/src/kernel/parser.rs`. Checked explicit length reading in `parse_text_value` and mapped bitstream underflow to `DFDLErrorKind::Parse("Insufficient binary/text data for primitive scalar")`.

### C. Optional Array Occurrence Backtracking (`minOccurs`)
- **DFDL 1.0 Spec §16.1**: Array occurrence parsing loops while `count < max_occurs`. When parsing an optional occurrence (`count >= min_occurs`), encountering an EOF or delimiter mismatch is not an error—the parser rolls back the checkpoint and breaks cleanly out of the occurrence loop (`Ok(count)`).
- **Fix**: Updated `parse_element_with_separators` in `crates/dfdl-core/src/kernel/parser.rs` line 384. If `parse_res` returns an error when `count >= min_occurs`, the engine rolls back `reader` and `builder` checkpoints and breaks cleanly out of the loop.

### D. Typed Delimiter Mismatch on Bitstream EOF
- **DFDL 1.0 Spec §12.1-§14.2**: Matching a mandatory initiator, terminator, or sequence separator at EOF returns a Delimiter Mismatch Parse Error.
- **Fix**: Updated `match_literal_delimiter` in `crates/dfdl-core/src/kernel/parser.rs` lines 257-270. Reading past EOF in `match_literal_delimiter` emits `DFDLErrorKind::Parse("Delimiter mismatch: end of data reached")`.
