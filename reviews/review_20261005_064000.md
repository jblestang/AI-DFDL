## 2. Multi-Domain Expert Review

### A. DFDL 1.0 Specification Conformance & XML Schema Domain
1. **Chameleon Inclusion & QName Format Resolution (Cluster 1, DFDL §12 / §13 / §14):**
   - **Mechanism:** In XML Schema and DFDL, schemas without a `targetNamespace` that are `<xs:include>`-d into a schema with a `targetNamespace` adopt that target namespace (chameleon inclusion).
   - **Resolution Architecture:** Previously, `resolve_qname_properties` converted un-prefixed format references (e.g. `ref="GeneralFormat"`) to Clark notation `"{}"GeneralFormat`. When `DFDLGeneralFormat.dfdl.xsd` was chameleon-included into a schema with a target namespace (e.g. `http://example.com`), `GeneralFormat` was indexed as `{http://example.com}GeneralFormat`. The format lookup rejected `"{}"GeneralFormat` because it strictly searched for empty namespace formats. Furthermore, annotation-level `<dfdl:defineFormat>` elements were missing in-scope namespace binding propagation.
   - **Conforming Fix:**
     - Propagated reader in-scope namespace bindings during `defineFormat` parsing at both top-level and container levels.
     - Enhanced `resolve_ref_formats_bounded` fallback resolution: if a prefix/URI lookup is not found, or if an unqualified format is requested, search candidate formats by local name if unique or defined in scope.
   - **Impact:** Cluster 1 dropped from 88 to 29 failures (-59 failures).

2. **Longest Match for Enclosing In-Scope Delimiters (Cluster 4 & 2c, DFDL §12.3.2 / §14.2):**
   - **Mechanism:** DFDL §12.3.2 specifies that all delimiters of enclosing components (both terminators and separators) are in-scope delimiters that take precedence over child delimiters when matching longer substrings.
   - **Resolution Architecture:** The parser engine tracked `in_scope_delimiters` (including sequence separators) but `is_in_scope_terminator_longer` only checked `in_scope_terminators`. In nested sequences like `nestedRootOk` with postfix separator `"||%NL;"`, child occurrences greedily consumed `"|"` as a prefix separator, preventing the outer sequence delimiter from matching.
   - **Conforming Fix:** Checked all `in_scope_delimiters` in `is_in_scope_terminator_longer`, guaranteeing that child separators yield whenever any enclosing delimiter matches a longer prefix.
   - **Impact:** Resolved `occursCountKindImplicitSeparators05Strict` and `occursCountKindImplicitSeparators05` without regressions.

### B. XPath 2.0 / Functions and Operators (F&O) Domain
1. **Boolean Ordering Comparisons (Cluster 2a, XPath 2.0 §3.5.2):**
   - **Mechanism:** XPath 2.0 §3.5.2 and DFDL §23 define value comparisons `lt`, `le`, `gt`, `ge` over `xs:boolean`, where `false < true`.
   - **Resolution Architecture:** A legacy check in `eval_cmp` unconditionally returned an error `Unsupported operation on type boolean`.
   - **Conforming Fix:** Removed the blanket prohibition in `eval_cmp` and implemented standard `false.cmp(&true) == Ordering::Less` semantics for `(DfdlValue::Boolean, DfdlValue::Boolean)`.
   - **Impact:** Resolved all 16 `comparison_operators_57` through `comparison_operators_72` tests.

2. **Temporal Component Extraction Functions (Cluster 2a, F&O §10.5 / §10.6 / §10.7):**
   - **Mechanism:** Implemented standard XPath 2.0 functions:
     - `fn:year-from-date`, `fn:month-from-date`, `fn:day-from-date`
     - `fn:year-from-dateTime`, `fn:month-from-dateTime`, `fn:day-from-dateTime`, `fn:hours-from-dateTime`, `fn:minutes-from-dateTime`, `fn:seconds-from-dateTime`
     - `fn:hours-from-time`, `fn:minutes-from-time`, `fn:seconds-from-time`
   - **Conformance Details:**
     - Enforced strict temporal type checks per F&O (e.g., passing `DateTime` or `Time` to `year-from-date` raises a SchemaDefinition error `"DateTime cannot be converted to Date"`).
     - Component extraction parses ISO 8601 formats including negative BC years, sub-second fractions, and timezones (`+HH:MM`, `-HH:MM`, `Z`).
     - Seconds return `DfdlValue::Decimal` (e.g. `0` or `5.18`), while year, month, day, hour, and minute return `DfdlValue::Long`.
   - **Impact:** Resolved temporal function tests in `functions.tdml` and `Functions.tdml`.

3. **Pest Grammar Structural & Compound Atomic Rules (Cluster 2a, XPath 2.0 §3.2):**
   - **Mechanism:** XPath permits whitespace between tokens in path expressions and predicates (e.g. `[ /ex:e1/ex:index ]`, `[ 6-5 ]`).
   - **Resolution Architecture:** `path`, `path_step`, and `predicate` were defined as compound atomic rules `${ ... }` in `dfdl_expression.pest`, which prohibited whitespace after `[` or between steps.
   - **Conforming Fix:** Defined structural rules (`path`, `path_step`, `step_node`, `predicate`) as standard whitespace-skipping rules `{ ... }` while keeping lexical leaf rules (`qname_step`, `prefix`, `local_name`) atomic.
   - **Impact:** Resolved `predicate_01` and `predicate_04`.
