## 2. Domain Reviews & Architectural Fixes

### 2.1 DFDL 1.0 Specification Conformance & Standards Review

1. **Prefixed Length Type Resolution & Implicit Lengths (DFDL §12.3.2)**:
   - In `crates/dfdl-schema/src/compiler.rs`: Handled implicit length computation for binary integer `prefixLengthType` definitions (`xs:byte`: 1, `xs:short`: 2, `xs:int`: 4, `xs:long`: 8) when `dfdl:length` is omitted.
   - Handled empty length strings gracefully during prefix type descriptor resolution in `crates/dfdl-core/src/kernel/unparser.rs` and `crates/dfdl-core/src/kernel/parser/element.rs`.
   - Verified that fixed length values around prefixed lengths are computed with accurate bit-lengths and byte alignments.

2. **Unified Escape Scheme Logic & OVC Synthesis (DFDL §13.2.1, §17)**:
   - Refactored `escape_text` into `CompiledEscapeScheme::escape_text` in `crates/dfdl-core/src/schema/ir.rs`, ensuring unified execution across both the streaming unparser and expression evaluation.
   - Enforced DFDL §13.2.1 rule for `escapeBlock`: `extraEscapedCharacters` forces the generation of an escape block, but characters within `extraEscapedCharacters` are not escaped inside the block itself.
   - In `crates/dfdl-core/src/expr/eval.rs`: Enabled `calc_elem_value_length` to synthesize values for unmaterialized elements with `outputValueCalc`, compute their formatted string representations, and apply active escape schemes.

3. **Numeric Text Formatting & ICU DecimalFormat Patterns (DFDL §13.7.1)**:
   - Implemented `format_text_number` in `crates/dfdl-core/src/kernel/parser/numbers.rs` supporting:
     - Positive and explicit negative subpatterns (`pos;neg`).
     - Quoted/escaped affixes (e.g., `'$'#0.0`).
     - Dual grouping sizes (primary and secondary grouping).
     - Scientific and engineering notation with custom exponent representations (e.g., `E`, runtime property expressions).
     - Fraction digit minimums (`0`) and maximums (`#`), with trailing fractional zeros trimmed back to `min_frac`.
   - Integrated `format_text_number` directly into `unparse_text_value` in `unparser.rs` and `calc_elem_value_length` in `eval.rs`.

4. **Simple Type Coercion in Expression Value-Length Calculations (DFDL §17)**:
   - When elements are parsed from infosets (e.g. `<z>5.0</z>`), simple types defined in the schema (e.g., `xs:float`) are now coerced using `coerce_and_validate_ivc_value` in `calc_elem_value_length`.
   - This ensures expressions like `dfdl:valueLength(../z, 'bytes')` evaluate using formatted text numbers with schema properties (e.g. `textStandardDecimalSeparator`), resolving cascading length discrepancies.

5. **`dfdl:textStandardZeroRep` Unparsing (DFDL §13.7.1.6)**:
   - Per DFDL §13.7.1.6: When unparsing a numeric value that equals zero, if `dfdl:textStandardZeroRep` is defined, the unparser uses the first alternative (with character entity decoding). If not defined, it formats using the pattern.
   - Implemented `is_numeric_zero` and integrated zero representation resolution into both `unparse_text_value` and `calc_elem_value_length`.
