# Root Cause Analysis: "Insufficient binary data for primitive scalar" in `InputValueCalc_` Test Family (2026-09-29 06:41:00)

## Executive Summary

An in-depth investigation was performed into the failure of the `InputValueCalc_` test family (e.g., `InputValueCalc_01`, `InputValueCalc_05`, `InputValueCalc_06`, `InputValueCalc_08`, `InputValueCalc_10`, `InputValueCalc_11`) in the Apache Daffodil TDML test suite.

The test cases unexpectedly failed during parse execution with:
`DFDLError { kind: Parse, message: "Insufficient binary data for primitive scalar" }`

---

## 1. Technical Root Cause Breakdown

The failure was caused by a multi-stage disconnect between TDML embedded schema extraction and schema property resolution:

### A. TDML Embedded Schema Extraction Failure (`crates/dfdl-tests/src/tdml.rs`)
1. **TDML Spec §4**: `<tdml:defineSchema>` elements in TDML files can either:
   - Contain an explicit `<xs:schema ...>` root tag.
   - Contain raw XSD child declarations directly inside `<tdml:defineSchema>` (e.g. `<xs:include>`, `<dfdl:format>`, `<xs:element>`).
2. **Extraction Defect**: In `crates/dfdl-tests/src/tdml.rs` (lines 205-224), `TdmlTestSuite::parse` searched for `<xs:schema` or `<schema` inside `<tdml:defineSchema>`.
3. When parsing `inputValueCalc.tdml`, `<tdml:defineSchema name="inputValueCalc-Embedded.dfdl.xsd">` direct children started with `<xs:include ...>` and `<dfdl:format ...>` without a surrounding `<xs:schema>` tag.
4. `tdml.rs` failed to find `<xs:schema` and silently failed to register `inputValueCalc-Embedded.dfdl.xsd` into `suite.embedded_schemas`.

### B. Fallback to Minimal Default Schema (`default_schema_xml`)
1. When executing `InputValueCalc_01`, `TdmlRunner` attempted to resolve `tc.model = "inputValueCalc-Embedded.dfdl.xsd"`.
2. Because the embedded schema was not registered, `TdmlRunner` fell back to `default_schema_xml`, which defines a generic binary element `<xs:element name="r" type="xs:int"/>` with `representation="binary"`.

### C. Bitstream Read Overrun (`crates/dfdl-core/src/kernel/parser.rs`)
1. When `InputValueCalc_01` ran against `default_schema_xml`, the parser attempted to read a 32-bit (4-byte) binary integer for `<xs:element name="r" type="xs:int"/>`.
2. However, the input document for `InputValueCalc_01` was a 1-byte text string (e.g. `"9"`).
3. Attempting to read 32 binary bits from a 1-byte stream caused `read_binary_bits(32)` to hit EOF and raise:
   `DFDLErrorKind::Parse("Insufficient binary data for primitive scalar")`.

---

## 2. Standard-Compliant Fix Plan

To fix this issue according to standard expectations:

1. **Update TDML Embedded Schema Extractor (`crates/dfdl-tests/src/tdml.rs`)**:
   - When `<tdml:defineSchema>` does not contain an explicit `<xs:schema>` tag, automatically wrap the inner XML content in a standard `<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema" xmlns:dfdl="http://www.ogf.org/dfdl/dfdl-1.0/" xmlns:ex="http://example.com" xmlns:tns="http://example.com" targetNamespace="http://example.com">` container.
2. **Ensure Top-Level `<dfdl:format>` Inheritance (`crates/dfdl-schema/src/compiler.rs`)**:
   - Verify that `<dfdl:format representation="text" ...>` attributes at schema level correctly populate `schema.global_format` so that element representation resolves to `Representation::Text`.
3. **Verify DFDL 1.0 §17 `dfdl:inputValueCalc` Behavior**:
   - Ensure calculated value elements consume 0 bitstream bytes and evaluate their DFDL expressions against the active infoset context.
