## 2. DFDL 1.0 Specification Conformance Analysis

### 2.1 DFDL 1.0 Section 19.3 — Calculated Elements (`dfdl:inputValueCalc`)
- **Specification Requirement:** The result of evaluating a `dfdl:inputValueCalc` expression must be coerced to the element's simple type. If the coerced value is out of range for the simple type or fails signedness rules, a **Parse Error** MUST be raised during parsing.
- **Engine Implementation:**
  - Standard coercions are handled via `coerce_and_validate_ivc_value`.
  - Type-level range bounds enforcement:
    - `xs:int`: Range \([-2^{31}, 2^{31}-1]\) (`i32::try_from(*v)`)
    - `xs:short`: Range \([-2^{15}, 2^{15}-1]\) (`i16::try_from(*v)`)
    - `xs:byte`: Range \([-2^7, 2^7-1]\) (`i8::try_from(*v)`)
    - `xs:unsignedInt`: Range \([0, 2^{32}-1]\) (`u32::try_from(*v)`)
    - `xs:unsignedShort`: Range \([0, 2^{16}-1]\) (`u16::try_from(*v)`)
    - `xs:unsignedByte`: Range \([0, 2^8-1]\) (`u8::try_from(*v)`)
    - `xs:unsignedLong`: Range \([0, 2^{64}-1]\) (`*v >= 0`)
  - **Signedness Rule:** Assigning a negative integer to an unsigned type triggers `"must match in signedness"`, matching DFDL specification requirement for signedness mismatches.
- **Conformance Rating:** **FULLY COMPLIANT**

### 2.2 DFDL 1.0 Section 17.6 — Built-in Functions (`dfdl:checkConstraints`)
- **Specification Requirement:** `fn:dfdl:checkConstraints(elem)` tests whether the value of `elem` satisfies the XML Schema simple type facet constraints (e.g. `minInclusive`, `maxInclusive`, `minExclusive`, `maxExclusive`) as well as primitive scalar type value ranges. Returns `true` if valid, `false` if invalid.
- **Engine Implementation:**
  - Evaluates schema simple type facets stored in `SimpleType` definitions.
  - Dynamically evaluates primitive scalar ranges for `DfdlValue::Long(v)` against `DfdlSimpleType` variants (`Int`, `Short`, `Byte`, `UnsignedInt`, `UnsignedShort`, `UnsignedByte`, `UnsignedLong`).
  - Returns `DfdlValue::Boolean(false)` when out of bounds or failing facet rules, allowing `dfdl:assert` and `dfdl:discriminator` expressions consuming `dfdl:checkConstraints(.)` to trigger parse errors correctly.
- **Conformance Rating:** **FULLY COMPLIANT**

### 2.3 DFDL 1.0 Section 14.2 — Separators & `separatorSuppressionPolicy`
- **Specification Requirement:** Under `separatorSuppressionPolicy="trailingEmptyStrict"`, a separator MUST NOT be present for a trailing empty element in a sequence. If a separator is encountered for a trailing empty element, a Parse Error MUST be raised. However, non-trailing optional empty elements MAY have separators present without error.
- **Engine Implementation:**
  - Sequence parser tracks member index relative to sequence length: `is_last_member = member_idx == seq.members.len().saturating_sub(1)`.
  - `parse_element_with_separators` validates whether the element is trailing before enforcing `trailingEmptyStrict`.
  - If `is_last_member` is `true` and a separator is read for an empty element, a `DFDLErrorKind::Parse` error is raised.
- **Conformance Rating:** **FULLY COMPLIANT**

### 2.4 DFDL 1.0 Section 12 — Alignment & Bitstream Parsing
- **Specification Requirement:** The DFDL engine operates on bitstreams. Parsing a root element complete document requires consuming bits up to the end of the root structure. Residual bits within the final byte up to byte alignment boundary must be aligned prior to checking for leftover payload data.
- **Engine Implementation:**
  - Before checking `reader.is_eof()` in `parse_document`, the parser calculates bit remainder relative to byte boundary: `rem = position().0 % 8`.
  - If `rem != 0`, `reader.read_bits(8 - rem)` aligns the stream to the next byte boundary.
  - Leftover data checks execute on byte-aligned boundaries, preventing false parse failures on padded binary files.
- **Conformance Rating:** **FULLY COMPLIANT**
