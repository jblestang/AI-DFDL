## 1. Summary of Optimizations Implemented

Following release CPU/allocation profiling with macOS `sample` on 300,000 benchmark iterations (`profile_faketdl_v14.txt`), three hotspots were addressed:

### Hotspot 1: Zero-Allocation Element Name Resolution (`prefixed_name_cow`)
- **Location**: [`crates/dfdl-core/src/types.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/types.rs), [`crates/dfdl-core/src/kernel/parser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs)
- **Problem**: In `parse_single_element_occurrence`, every scalar element invoked `elem.name.prefixed_name()` to pass the element name to `parse_simple_value`. For unprefixed elements (common in binary & text telemetry), `prefixed_name()` allocated a brand new heap `String` by cloning `local_name`.
- **Remediation**: Added `prefixed_name_cow(&self) -> alloc::borrow::Cow<'_, str>` to `QName`. In `parse_single_element_occurrence`, borrowed slice `as_ref()` is passed without heap allocation for unprefixed elements, completely eliding string duplication per scalar element.

### Hotspot 2: Zero-Allocation `Cow<'_, str>` in `unparse_text_value`
- **Location**: [`crates/dfdl-core/src/kernel/unparser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser/element.rs)
- **Problem**: `unparse_text_value` allocated heap strings via `alloc::string::ToString::to_string(val)` even when `val` was already a `DfdlValue::String(s)`, and eagerly re-allocated during PUA character remapping scans even when no PUA codepoints existed.
- **Remediation**: Converted `unparse_text_value`'s working buffer `s` to `alloc::borrow::Cow<'_, str>`. `DfdlValue::String(ref s_val)` is borrowed directly (`Cow::Borrowed(s_val.as_str())`), and PUA remapping / escape schemes only clone into `Cow::Owned` if matching characters are found or escapes applied.

### Hotspot 3: Pre-Reserving Child Capacity in Complex Element Tree
- **Location**: [`crates/dfdl-core/src/infoset/tree.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/infoset/tree.rs)
- **Problem**: `try_add_child` initially allocated 8 child slots on the first child. Messages with more than 8 fields (e.g. FakeTDL radar tracks with 18 fields) hit `RawVecInner::finish_grow`, dynamic reallocations, and `platform_memmove` twice per message (at fields 9 and 17).
- **Remediation**: Increased initial reservation to 24 slots in `try_add_child` and pre-reserved 24 capacity on non-nil `StartElement` in `push_event_with_hidden`. This completely eliminated reallocation overhead during tree construction for complex messages.

## 2. Benchmark Comparison (Before vs After Pass 5)

Tested on Apple M-series hardware using release build (`cargo run --release -p dfdl-benchmark -- --bench`):

| Operation | Pass 4 Mean | Pass 5 Mean | Pass 4 Median | Pass 5 Median | Improvement |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Raw DFDL parse (64B Track)** | 3.32 µs | **3.12 µs** | 3.00 µs | **2.83 µs** | **-6.0% (mean) / -5.7% (median)** |
| **Raw DFDL unparse (64B Track)** | 1.63 µs | **1.60 µs** | 1.62 µs | **1.58 µs** | **-1.8% (mean) / -2.5% (median)** |
| **Raw DFDL roundtrip (64B Track)** | 5.17 µs | **4.92 µs** | 4.88 µs | **4.67 µs** | **-4.8% (mean) / -4.3% (median)** |
| **Raw DFDLFile parse (192B Multi)** | 7.29 µs | **6.96 µs** | 7.12 µs | **6.79 µs** | **-4.5% (mean) / -4.6% (median)** |
| **Raw DFDLFile unparse (192B Multi)** | 5.86 µs | **5.52 µs** | 5.79 µs | **5.46 µs** | **-5.8% (mean) / -5.7% (median)** |
| **Raw DFDLFile roundtrip (192B Multi)** | 13.92 µs | **13.12 µs** | 13.71 µs | **12.88 µs** | **-5.7% (mean) / -6.1% (median)** |

*Key Highlights*:
- Raw DFDL parse latency dropped below 3.0 µs median (**2.83 µs**).
- Raw DFDL roundtrip latency dropped below 5.0 µs mean (**4.92 µs**).
- Multi-message roundtrip latency dropped below 13.0 µs median (**12.88 µs**).
