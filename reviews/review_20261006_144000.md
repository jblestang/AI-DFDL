## 2. Root Cause Analysis & Architectural Conformance

### A. Overlapping Properties vs DFDL Scoping Precedence (DFDL v1.0 §4.1.2)
- **The Issue:**
  In `crates/dfdl-schema/src/compiler.rs`, the compiler previously performed an overlap check between element properties and referenced `simpleType` properties after calling `resolve_ref_formats(&mut resolved_elem_props)` and `resolve_ref_formats(&mut resolved_st_props)`.
  Because `resolve_ref_formats` merges all properties defined in the schema file's default format (`<dfdl:format>`), properties like `initiator=""`, `terminator="B"`, `encoding="ASCII"`, and `separator=""` were populated into both property bags. The compiler subsequently raised a false `SchemaDefinitionError: Overlapping properties`.
- **DFDL v1.0 Rule (§4.1.2):**
  - Element local properties override simpleType properties.
  - SimpleType local properties override default format properties.
  - Default format properties NEVER participate in overlap collisions; they provide fallback defaults.
  - Furthermore, per DFDL §4.1.2 and Apache Daffodil semantics, local element properties can override simpleType properties (e.g. specialized lengthKind or delimiters). Overlap collisions apply between direct definitions on simpleType derivation chains or element references when both specify non-overridable conflicting properties.
- **Conforming Fix:**
  1. Preserved `elem.properties` (direct properties) separate from file-level `resolved_global_format`.
  2. Maintained `effective_st_props` (direct simpleType properties) distinct from `effective_st_defaults` (default format properties associated with the simpleType).
  3. Checked overlap strictly between direct properties (`effective_st_props` vs subsequent restriction steps).
  4. Cascaded property inheritance strictly following DFDL §4.1.2:
     - 1. Direct element properties.
     - 2. Direct simpleType properties.
     - 3. Direct base simpleType properties.
     - 4. Parent element / model group inherited properties.
     - 5. Element schema document default format.
     - 6. Simple type schema document default format.

### B. Chameleon Inclusion & Cross-Schema `defineFormat` Resolution (W3C XSD 1.0)
- **The Issue:**
  In `namespaces.tdml` (`namespace_scope_02`), schema `schemaA.dfdl.xsd` included an un-namespaced schema document `schemaB.dfdl.xsd` (chameleon inclusion). During inclusion, components without a target namespace adopt `schemaA`'s target namespace (`http://b.com`). However, `schemaB` contained a `defineFormat` explicitly namespaced to `{http://foo.com}GeneralFormat`.
  The chameleon copier previously blindly reassigned every top-level format's namespace to the including document's target namespace, mangling `{http://foo.com}GeneralFormat` into `{http://b.com}GeneralFormat`.
- **W3C XML Schema Rule:**
  Chameleon inclusion ONLY assigns target namespace to components that lack a namespace. Definitions already in an explicit target namespace must remain in their original namespace.
- **Conforming Fix:**
  In `crates/dfdl-schema/src/xsd_ast.rs` (`resolve_includes_recursive`), when copying defined formats, simple types, and element declarations from a chameleon-included schema:
  - If `fmt.name.namespace` is empty or matches the source document's target namespace, assign the parent document's target namespace.
  - If `fmt.name.namespace` is non-empty and explicit (e.g. `http://foo.com`), preserve its original namespace.
  - Additionally, in `resolve_ref_formats_bounded`, implemented namespace-aware QName matching comparing local names and matching namespace URIs.

### C. Calendar `lengthKind='implicit'` with Explicit Pattern (DFDL-12-067R)
- **The Issue:**
  When resolving calendar types with `lengthKind='implicit'`, an SDE was unconditionally thrown based on DFDL-12-067R.
- **DFDL v1.0 §12.3.7.2 Rule:**
  Calendar elements with `representation='text'` and `lengthKind='implicit'` are prohibited only when `calendarPatternKind='implicit'`. When `calendarPatternKind='explicit'`, the length is governed by the explicit calendar pattern and is fully conforming.
- **Conforming Fix:**
  Gated the DFDL-12-067R check to trigger only when `calendarPatternKind == "implicit"`.
