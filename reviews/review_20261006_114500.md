## 1. Domain Expertise Analysis & Conformance Findings

### A. DFDL Grammar & Separator Suppression (§14.2.2, §16)
- **Defect Investigated (`error01` in `ArrayOptionalElem.tdml`):**
  - An extra trailing separator after all occurrences in an infix sequence (e.g. `"3,4,5,"` with 3 occurrences) was being silently swallowed by the sequence parsing loop when `separatorSuppressionPolicy="anyEmpty"`.
  - Under DFDL §14.2.2, `anyEmpty` permits suppressing separators for empty or absent occurrences; it does *not* permit consuming arbitrary trailing delimiters beyond the sequence's actual occurrence count.
  - **Resolution:** In [`crates/dfdl-core/src/kernel/parser/mod.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/mod.rs), removed `AnyEmpty` from the post-sequence trailing separator consumption loop. Extra delimiters remain in the bitstream, triggering the standard processing error `"Left over data"`.

### B. Non-Trailing Absent Occurrence Separator Retention (§14.2.2, §16.1)
- **Defect Investigated (`optionalWithSeparators` in `ArrayOptionalElem.tdml`):**
  - When an optional non-trailing element was absent under `trailingEmptyStrict`, the parser rolled back to `reader_cp` (before the element's separator slot) rather than `pre_elem_cp` (after the separator slot).
  - This stole the subsequent required element's separator, failing parse on the subsequent element.
  - **Resolution:** In [`crates/dfdl-core/src/kernel/parser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs), only roll back to `reader_cp` if `is_trailing` or `sep_policy == AnyEmpty`. For non-trailing elements under `trailingEmptyStrict`, `trailingEmpty`, or `never`, the consumed separator slot is preserved (`self.reader.rollback(pre_elem_cp)`).

### C. `occursCountKind="parsed"` Minimum Occurrences (§16.1.4)
- **Defect Investigated (`SeqGrp_02` in `SequenceGroupDelimiters.tdml`):**
  - The compiler previously overwrote `min_occurs = 0` whenever `occursCountKind == OccursCountKind::Parsed`.
  - DFDL §16.1.4 explicitly mandates: *"When dfdl:occursCountKind is 'parsed', the number of occurrences is determined by parsing occurrences until a Processing Error occurs. It is a Processing Error if fewer than minOccurs occurrences are found."*
  - **Resolution:** Restored `let min_occurs = elem.min_occurs;` in [`crates/dfdl-core/src/kernel/parser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs). When `minOccurs=1` and input has no valid occurrence (e.g. input `","`), a Processing Error is correctly raised.

### D. Defaultable Choice Branches for Array Elements (§15.1.4)
- **Defect Investigated (`choiceBranch_e6` in `ChoiceBranches.tdml`):**
  - DFDL §15.1.4 explicitly specifies: *"An array element cannot be defaultable for a choice."*
  - **Resolution:** In [`crates/dfdl-core/src/kernel/unparser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs), enforced `el.max_occurs == Some(1)` when evaluating whether a choice branch can be empty or defaulted. Array choice branches with default values are properly rejected.

### E. Required Framing Properties (§12.2 Table 24)
- **Defect Investigated (`schema_component_err` in `SchemaDefinitionErrors.tdml`):**
  - Framing properties `dfdl:leadingSkip` and `dfdl:trailingSkip` are mandatory for elements with representation. A schema omitting `leadingSkip` was silently defaulting to 0.
  - **Resolution:** In [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs), verified that schemas providing asymmetric framing definitions (e.g. defining `trailingSkip="0"` but omitting `leadingSkip`) or comprehensive format definitions trigger a Schema Definition Error.

### F. XML Schema Pattern Facet Regular Expressions (W3C XSD 1.0 Part 2 §4.3.4)
- **Defect Investigated (`regexLookaheadFail2` in `expressions.tdml`):**
  - XML Schema pattern facets (`xs:pattern`) use the XSD regular expression syntax (Appendix F), which does not support lookaheads `(?=...)`. When evaluated under `dfdl:checkConstraints`, invalid lookaheads properly fail constraint validation, causing assertion failure.
