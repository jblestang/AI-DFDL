## 2. Analyse et Résolution de l'Anomalie de Scoping `ignoreCase`

### Constat
Lors de l'exécution de la suite TDML Daffodil sur `TextNumberProps.tdml` (`infnanCaseInsensitive`) :
- L'élément conteneur déclarait explicitement `dfdl:ignoreCase="yes"` :
  ```xml
  <xs:element name="infnanCaseInsensitive" dfdl:lengthKind="implicit" dfdl:ignoreCase="yes">
    <xs:complexType>
      <xs:sequence dfdl:separator="|" dfdl:terminator="]">
        <xs:element name="posinf" type="xsd:double" dfdl:textStandardInfinityRep="INFINITY" />
        ...
      </xs:sequence>
    </xs:complexType>
  </xs:element>
  ```
- Les éléments enfants (`posinf`, `neginf`, `nan`) échouaient au parsing de `"Infinity"` / `"-iNfInItY"` car leur propriété résolue `ignore_case` était retombée à `false`.
- **Cause racine :** Dans l'abaissement en RI (`lower_element_to_ir_bounded` et `lower_sequence_to_ir_bounded`), le format de document par défaut `doc_fmt` (contenant `ignoreCase="no"`) écrasait la valeur `dfdl:ignoreCase="yes"` définie sur le composant parent englobant, car `merge_parent` ne remplaçait pas les propriétés déjà renseignées par `doc_fmt`.

### Correction chirurgicale conforme à DFDL §8.1.1
- Préservation de la priorité du format de document lexical (`doc_fmt`) pour l'isolation des schémas inclus/importés (nécessaire notamment pour `envelope-payload`).
- Héritage explicite de `ignoreCase` depuis `parent_props` vers l'élément ou le groupe de modèle enfant (`seq` / `choice`) lorsque le composant enfant ne spécifie pas lui-même `ignoreCase` :
  ```rust
  if elem.properties.get_property("ignoreCase").is_none() {
      if let Some(parent_ign) = parent_props.get_property("ignoreCase") {
          let _ = effective_elem_props.set_property("ignoreCase", parent_ign);
      }
  }
  ```
