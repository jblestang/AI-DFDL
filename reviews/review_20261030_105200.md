## 1. Executive Summary & Benchmark Evolution

In this optimization pass, we identified and eliminated the top remaining leaf bottlenecks discovered during sampling (`profile_faketdl_v10.txt`). The primary culprit was the eager and unconditional invocation of `builder.active_doc()` during expression evaluation, which performed a deep clone of the entire in-progress infoset tree and counted all elements across the tree, only to drop and deallocate the cloned tree immediately upon expression evaluation.

Combined with redundant path allocations in `InfosetBuilder`, unconditional `Cow`-less separator/terminator string cloning, unparser numeric conversions, and direct string building in calendar parsers, these changes achieved significant latency improvements:

## 3. Detailed Root Cause Analysis & Implementations

### A. Gated `active_doc()` Construction via `ExprAst::needs_infoset_doc()`
- **Issue:** Whenever `choiceDispatchKey`, `execute_set_variables`, `execute_new_variable_instances`, or element length expressions were evaluated, `builder.active_doc()` was called unconditionally. In FakeTDL telemetry, choice branches are dispatched using `dfdlx:lookAhead(0, 8)` which reads directly from the bitstream and never inspects the DOM tree. Deep-cloning the entire in-progress tree per choice branch placed severe pressure on the memory allocator.
- **Solution:**
  - Added `pub fn needs_infoset_doc(&self) -> bool` to `ExprAst` in [`crates/dfdl-core/src/expr/ast.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/ast.rs).
  - Traverses the AST: returns `false` for literals, variable references, arithmetic, `lookAhead`, `occursIndex`; returns `true` only for `Path` expressions or functions inspecting elements (`checkConstraints`, `count`, `exists`, `empty`).
  - Gated all 10 parser evaluation sites in [`parser/mod.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/mod.rs), [`parser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs), and [`parser/delimiters.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs).

### B. On-Demand `InfosetBuilder::current_path()` & Removal of Premature Capacity Allocation
- **Issue:** On every `StartElement` event, `push_event_with_hidden` cloned the element's local name into a `PathStep`, allocated space on `self.current_path`, and called `elem.children.try_reserve(16)`. On `EndElement`, `self.current_path.pop()` freed the step. 99% of parsing never queries `current_path`. Furthermore, pre-reserving 16 child slots for every scalar or 2-child element caused 896 bytes of allocation per element.
- **Solution:**
  - Removed `current_path` field from `InfosetBuilder` and `InfosetCheckpoint`.
  - Implemented `current_path(&self) -> InfosetPath` on-demand by walking `self.stack` only when explicitly queried.
  - Removed `try_reserve(16)`, letting `Vec<InfosetNode>` grow dynamically based on actual child element counts.

### C. Zero-Copy `evaluate_prop_cow` & Aligned Byte Slicing in `text.rs`
- **Issue:** `parse_text_value` unconditionally evaluated `separator_prop` and `terminator_prop` by cloning the property string on every text scalar, even for static constants (e.g. `separator="/"`, `terminator=";"`). In addition, fixed-length byte scalars were read in 1-byte chunks via `read_bits(8)`.
- **Solution:**
  - Added `evaluate_prop_cow` returning `Cow<'a, str>`, borrowing constant strings directly from the compiled schema graph with 0 heap allocations.
  - Added a byte-aligned fast path in `parse_text_value` utilizing `self.reader.read_bytes(&mut bytes)` directly from the slice source.

### D. Unparser Value Validation Match Fast-Path & Inlining
- **Issue:** In `validate_unparse_value`, typed simple values (e.g. `DfdlValue::Int(42)`) were converted via `val.as_i128()` and subsequently checked with `i32::try_from(val_num)`, consuming 43 leaf samples in `as_i128`.
- **Solution:**
  - Added an identity matching fast-path: if `(st, val)` already match in type (e.g. `DfdlSimpleType::Int` with `DfdlValue::Int(_)`, `UnsignedLong` with `UnsignedLong(_)`, etc.), returns `Ok(())` immediately.
  - Added `#[inline]` annotations to `as_i128` and `effective_boolean_value` in [`infoset/value.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/infoset/value.rs).

### E. Direct String Buffer Construction in `calendar.rs`
- **Issue:** Calendar parsing in `parse_calendar_from_digits` invoked `alloc::format!("{}-{}-{}T{}:{}:{}", ...)` which repeatedly resized small formatting buffers.
- **Solution:**
  - Replaced `alloc::format!` with direct `String::with_capacity(19)` / `(10)` / `(8)` and `push_str()` calls, performing a single exact heap allocation.

## 4. Multi-Domain Expert Review

### Safety & Embedded / `no_std` Systems
- All newly introduced logic adheres strictly to `no_std` + `alloc`. No operating system dependencies or thread-local storage introduced.
- On-demand path construction is completely deterministic and bounded by the element stack depth (enforced by `limits.check_nesting`).

### Cybersecurity & Telemetry Defenses
- Eliminating unnecessary string cloning and heap allocations prevents heap fragmentation during high-throughput ingestion of military telemetry (e.g. Link-16, STANAG, fakeTDL).
- Path calculation correctly preserves element occurrence indexing (`item[2]`) in accordance with DFDL 1.0 §18.
