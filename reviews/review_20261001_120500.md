# Architectural & Conformance Code Review: Resolution of "Expected Error Not Raised" Cluster

**Timestamp:** 2026-10-01 12:05:00 UTC+2  
**Domain Expertises Applied:** DFDL 1.0 Specification Conformance, Systems Architecture, Safe Embedded Rust (`#![no_std]` + `alloc`), Compiler Verification.

---

## 1. Executive Summary & Conformance Progress

A comprehensive audit was performed on the **"Expected Error Not Raised"** failure cluster (initially accounting for 397 failures, or 26.2% of all failures across the 4,337-test Apache Daffodil TDML conformance suite).

Rather than applying localized or type-specific surgical workarounds, standard-conforming architectural changes were designed and implemented across the compiler, schema IR, expression evaluation engine, and parser runtime:

1. **Choice Direct Dispatch Architecture (DFDL §15 & OGF Extensions)**:
   - Added schema definition validation and compile-time rejection of invalid configurations (`choiceDispatchKey` combined with `initiatedContent="yes"`, missing branch keys/ranges, duplicate keys, overlapping ranges, odd number of range tokens, descending range bounds, and invalid scope placement on global elements/group defs).
   - Implemented runtime dispatch key expression evaluation with strict non-empty string validation and branch key/range matching.
2. **Calendar Epoch & Binary Calendar Bounds (DFDL §13.11 & §13.13)**:
   - Implemented standard `is_valid_xs_date_time` validator enforcing ISO 8601/W3C XML Schema `xs:dateTime` lexical constraints on `dfdl:binaryCalendarEpoch`.
   - Generalized binary calendar parsing across all calendar types (`xs:dateTime`, `xs:date`, `xs:time`) and representations (`binarySeconds`, `binaryMilliseconds`), with strict epoch arithmetic, calendar bounds checking (`0x028D46FBFCAE62E8` / `0xFD72B90403519D18`), and tunable year limits (`minValidYear` / `maxValidYear`).
3. **Empty Element Parse Policy (DFDL §9.4)**:
   - Added `emptyElementParsePolicy` property resolution (`treatAsEmpty`, `treatAsAbsent`).
   - Enforced parse-time error raising when an element is required, has zero length / empty content, and policy is `treatAsAbsent`.
4. **Self-Referencing Unvalued Elements (DFDL §23)**:
   - Enforced schema definition and expression errors when expressions self-reference an element that does not yet possess a value, or when `dfdl:checkConstraints()` is invoked on an unvalued element.

## 2. Root Cause Analysis of "Expected Error Not Raised" Failures

The TDML test cases expecting errors were failing because the runtime or compiler was either:
1. **Silently ignoring unspecified choice branches** or falling back to speculative backtracking when direct dispatch was designated.
2. **Accepting syntactically invalid `binaryCalendarEpoch` formats** without raising a Schema Definition Error during schema compilation or property resolution.
3. **Failing to reject out-of-bounds calendar integer values** (e.g. millisecond values exceeding year 9999 or exceeding `i64` calendar limits).
4. **Returning empty strings instead of raising parse errors** when required elements parsed empty under `emptyElementParsePolicy="treatAsAbsent"`.
5. **Evaluating empty defaults for unvalued elements in self-referencing expressions**, bypassing the mandatory circular reference / missing value error requirement.

## 3. Detailed Architectural Fixes

### A. Choice Direct Dispatch Compiler & Runtime Pipeline
- **Specification Reference**: DFDL v1.0 Section 15 & Daffodil Direct Dispatch Specification.
- **Compiler Validation**:
  - Enforced that if `dfdl:choiceDispatchKey` is present on an `xs:choice`, `dfdl:initiatedContent` MUST NOT be `"yes"`.
  - Enforced that every branch of the choice MUST specify `dfdl:choiceBranchKey` and/or `dfdlx:choiceBranchKeyRanges`.
  - Enforced that branch keys are unique across branches, ranges contain an even count of valid integers with `min <= max`, and no scalar branch key falls within an integer branch range.
  - Enforced that `choiceBranchKey` attributes cannot be defined on global element declarations or children of global named group definitions.
- **Runtime Dispatch**:
  - Choice execution evaluates `choiceDispatchKey` against the active infoset document and variable map.
  - Rejects evaluation to empty string with `Runtime Schema Definition Error: Non-empty string required for choiceDispatchKey`.
  - Dispatches to the matched branch without speculative backtracking. If no branch matches, raises `Parse Error: Choice dispatch key '...' failed to match any branch`.

### B. Gregorian Calendar Arithmetic & Binary Calendar Bounds
- **Specification Reference**: DFDL v1.0 Section 13.11 & 13.13.
- **Validation**:
  - Added `is_valid_xs_date_time` checking year, month (1..=12), day (1..=31), hour (0..=24), minute (0..=59), second (0..=60), fraction, and timezone offset (`Z` or `±HH:MM`).
- **Binary Millisecond & Second Decoding**:
  - Implemented pure arithmetic conversion between Gregorian dates and cumulative days (`ymd_to_days` / `days_to_ymd`) with 400-year leap cycles, compatible with `#![no_std]` without external crate dependencies.
  - Added upper/lower bound checks against calendar bounds (`0x028D46FBFCAE62E8` and `0xFD72B90403519D18`).
  - Added tunable year limits check (`1..=9999`), raising `Tunable Limit Exceeded Error` when dates exceed allowable ranges.

### C. Empty Element Parse Policy
- **Specification Reference**: DFDL v1.0 Section 9.4.
- **Runtime Enforcement**:
  - In `parse_element_content`, when parsed text length is 0 (or no data) and the element has no default value and is required (`min_occurs > 0`), if `empty_element_parse_policy == TreatAsAbsent`, raises `Parse Error: Empty element not allowed in this position for required element '...'`.

### D. Self-Referencing Unvalued Elements
- **Specification Reference**: DFDL v1.0 Section 23.
- **Evaluation Engine**:
  - In `crates/dfdl-core/src/expr/eval.rs`, when resolving relative paths that point to the current element (`is_self_ref`), checks whether the element has an assigned value. If missing or `ElementState::NoValue`, raises `Expression Evaluation Error: Self referencing element '...' does not have a value`.
  - Handled identically for `dfdl:checkConstraints()` without arguments.

## 4. Systems, Safety & Embedded Verification

1. **`#![no_std]` + `alloc` Compliance**:
   - Zero references to `std::` or operating system facilities.
   - All string and vector operations explicitly use `alloc::string`, `alloc::vec`, and `alloc::format`.
   - Verified via `cargo check --target thumbv7m-none-eabi -p dfdl-core -p dfdl-xml -p dfdl-schema`.
2. **Panic Safety**:
   - Eliminated all slice/vector indexing (`[]`) in newly added logic in favor of `.first()`, `.get()`, `.get_mut()`, and `crate::util::get_slice_checked()`.
   - Zero `unwrap()` calls in production runtime paths.
   - Checked arithmetic (`checked_mul`, `checked_add`, `checked_sub`) prevents integer overflow when calculating epoch millisecond offsets.
3. **Clippy & Linter Verification**:
   - Strict `cargo clippy --all-targets -- -D warnings` executed with zero warnings.
   - Fully formatted according to `cargo fmt`.
