**Date :** 10 Octobre 2026 — 16:33:00  
**Auteur :** Antigravity (Paire-programmeur & Expert DFDL / Rust)  
**Objet :** Élimination de l'anti-pattern de re-parsing de chaînes XPath via un AST structuré et typé (`PathStep`, `StepTarget`, `PathAxis`).

---

## 1. Contexte et Objectifs de la Phase 2

Lors de l'analyse architecturale initiale du moteur d'expressions XPath/DFDL (`crates/dfdl-core`), un anti-pattern de *double parsing* a été identifié :
1. La grammaire Pest (`dfdl_expression.pest`) découpait correctement la syntaxe XPath (`axis_specifier`, `parent_step`, `self_step`, `wildcard_step`, `qname_step` avec `prefix` et `local_name`).
2. Cependant, `crates/dfdl-core/src/expr/parser.rs` reconstruisait des chaînes de caractères brutes (ex: `"elem"`, `"ex:elem"`, `"elem[1]"`, `".."`).
3. Lors de la traversée de l'arbre (`crates/dfdl-core/src/infoset/tree.rs`) et de l'évaluation (`crates/dfdl-core/src/expr/eval.rs`), ces chaînes étaient de nouveau scannées à la main avec `split(':')`, `split('[')`, `starts_with('{')`, `find('}')`, etc.

### Objectifs atteints :
- [x] Définition des types fortement typés `PathAxis`, `StepTarget` (`Unprefixed`, `Prefixed`, `Clark`, `Wildcard`, `SelfNode`, `ParentNode`), et `PathStep`.
- [x] Construction directe de l'AST de chaque étape depuis Pest sans passage intermédiaire par une chaîne bricolée.
- [x] Remplacement du scanning de chaîne dans `find_element_with_policy_checked` (`tree.rs`) par un pattern matching direct sur `StepTarget`.
- [x] Maintien strict de `#![no_std]` + `alloc`, compatibilité totale rétrocompatible avec `InfosetPath.segments()`.
- [x] Vérification de conformité : 0 avertissement Clippy sous `-D warnings`, 289 tests unitaires `dfdl-core` passés, 4,331 / 4,336 tests de la suite officielle Apache Daffodil TDML validés (0 régression).

## 2. Modèle de Données et Typage (`crates/dfdl-core/src/types.rs`)

### 2.1 Enum `StepTarget`
```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum StepTarget {
    /// Nom non préfixé (ex: `item`).
    Unprefixed(String),
    /// Nom qualifié avec préfixe explicite (ex: `ex:item`).
    Prefixed {
        prefix: String,
        local: String,
        raw: String,
    },
    /// Notation Clark avec URI d'espace de noms (ex: `{urn:test}item`).
    Clark {
        uri: String,
        local: String,
        raw: String,
    },
    /// Étape joker `*`.
    Wildcard,
    /// Étape self `.`.
    SelfNode,
    /// Étape parent `..`.
    ParentNode,
}
```

## 3. Optimisation de la Traversée d'Infoset (`crates/dfdl-core/src/infoset/tree.rs`)

Dans [`find_element_with_policy_checked`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/infoset/tree.rs), tout le bloc de recherche par `raw_step == "*"`, `raw_step.starts_with('{')`, et `raw_step.split_once(':')` a été remplacé par un pattern matching direct :

```rust
match &step.target {
    StepTarget::Wildcard => {
        let _ = try_push(&mut matches, elem);
    }
    StepTarget::Clark { uri, local, .. } => {
        if clean_elem == local.as_str()
            && elem.name.namespace.as_deref() == Some(uri.as_str())
        {
            let _ = try_push(&mut matches, elem);
        }
    }
    StepTarget::Prefixed { prefix, local, .. } => {
        if clean_elem == local.as_str()
            && (elem.name.namespace.is_some() || elem.name.prefix.is_some())
        {
            if let Some((_, uri)) = in_scope_namespaces.iter().find(|(p, _)| p == prefix) {
                if elem.name.namespace.as_deref() == Some(uri.as_str()) {
                    let _ = try_push(&mut matches, elem);
                }
            } else if elem.name.prefix.as_deref() == Some(prefix.as_str()) {
                let _ = try_push(&mut matches, elem);
            }
        }
    }
    StepTarget::Unprefixed(unpref_name) => {
        if clean_elem == unpref_name.as_str() {
            // Application de la politique UnqualifiedPathStepPolicy
            ...
        }
    }
    StepTarget::SelfNode | StepTarget::ParentNode => {}
}
```
