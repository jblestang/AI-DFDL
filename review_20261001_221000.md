## 2. Technical Domain Assessment & Changes Made

### A. Non-Textual and Sub-byte Charset Alignment (DFDL v1.0 §11.1)
- **Specification Rule**: Byte-oriented encodings (`UTF-8`, `ASCII`, `US-ASCII`, `ISO-8859-*`) require mandatory 8-bit alignment at the start of text parsing. When the stream's bit position is not a multiple of 8, a Parse Error must be raised.
- **Engine Enforcement**:
  - In `crates/dfdl-core/src/kernel/parser.rs`, implemented alignment checks in `parse_text_value` and in `parse_binary_value` for `xs:string`.
  - When `self.reader.bit_position() % 8 != 0`, immediately aborts with:
    `"Parse Error: charset not byte aligned: current bit position is {}"` reporting the 1-indexed bit position.
- **Test Verification**:
  - Validated by Daffodil test `unalignedCharsetWithMandatory8BitAlignment` in `encodings.tdml`.
  - Added dedicated unit test `test_unaligned_byte_oriented_charset_rejected` in `crates/dfdl-core/src/kernel/mod.rs`.

### B. Boolean and Type Facet Defaults Validation (DFDL v1.0 §9.4)
- **Specification Rule**: Default values for simple types in XML Schema must adhere strictly to the lexical space of the declared type. Specifically, boolean defaults must be one of `"true"`, `"false"`, `"1"`, or `"0"`.
- **Compiler Enforcement**:
  - In `crates/dfdl-schema/src/compiler.rs`, added lexical validation for `default` and `fixed` attributes across XML Schema scalar types during IR compilation.
  - For `xs:boolean`, invalid defaults (such as strings `"invalid"`, `"unknown"`) raise a `Schema Definition Error: Invalid value constraint value '{}' for type 'xs:boolean'`.
- **Test Verification**:
  - Validated with `booleanDefaultSDE` in `boolean.tdml`.
  - Unit test `test_invalid_default_value_constraint` in `compiler/tests.rs`.

### C. `separatorSuppressionPolicy="never"` Occurrences and Delimiter Semantics (DFDL v1.0 §14.2.2)
- **Specification Rule**: Under `separatorSuppressionPolicy="never"`, no separators may be suppressed. For bounded arrays and optional elements with `occursCountKind="implicit"`, all `maxOccurs` positions and their separators must be present in the representation.
- **Parser Kernel Enforcement**:
  - Added `slots_processed` tracking in `parse_element_with_separators` to distinguish between representation occurrences found in the data stream versus infoset elements materialized (which may be zero when `emptyElementParsePolicy="treatAsAbsent"`).
  - Enforced that if `slots_processed < maxOccurs`, a Parse Error is raised:
    `"Parse Error: All maxOccurs ({}) occurrences are required when separatorSuppressionPolicy is 'never', but only {} occurrences were found"`.
  - Corrected empty occurrence handling in infix sequences: when an empty occurrence is encountered and followed by a delimiter, its separator slot is accounted for rather than triggering premature backtracking.
- **Test Verification**:
  - Resolved `separatorSuppressionPolicy_never_optionalStringArray_3` and `separatorSuppressionPolicy_never_optionalIntArray_4`.
  - Added unit test `test_separator_suppression_never_requires_all_max_occurs` in `crates/dfdl-core/src/kernel/mod.rs`.

### D. Speculative Element Delimiter Rollback vs. Sequence Framing (DFDL v1.0 §16)
- **Specification Rule**: In an infix sequence with multiple distinct elements, an infix separator preceding a subsequent member must not be consumed by a speculative trailing array occurrence of the previous member.
- **Parser Kernel Enforcement**:
  - When an optional or array element consumes a separator and finds no valid subsequent occurrence, the parser inspects `self.peek_literal_delimiter(sep)`.
  - If another delimiter follows (a multi-delimiter run such as `1::3::5`), the empty slot is recorded and the separator consumed.
  - If no delimiter follows (e.g. `*street:Ridgewood Circle*city:Rochester`), the separator is recognized as belonging to the succeeding member (`city`), rolling back to before the separator so the next element parses cleanly.
- **Test Verification**:
  - Maintained zero regressions in `Lesson6_variable_array_01`, `Lesson6_variable_array_02`, and `occursCountKindImplicitSeparators01a..03`.
