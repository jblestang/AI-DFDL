# Engineering Review - Text Parser Escape Scheme Byte Lookahead & Hang Resolution
**Timestamp:** 2026-10-05 16:15:00  
**Scope:** `crates/dfdl-core/src/kernel/parser/text.rs`, Apache Daffodil Official TDML Suite (`whitespace_06` & `escapeScenarios.tdml`).

---

### 1. Executive Summary
During full-suite execution of the Apache Daffodil official TDML test harness (`test_apache_daffodil_official_tdml_suite`), testing stalled indefinitely on `section06/entities/Entities.tdml` (`whitespace_06`).

Root-cause analysis uncovered an infinite zero-bit consumption loop in `crates/dfdl-core/src/kernel/parser/text.rs` where escape scheme scanning routed `escapeCharacter` through delimiter parsing utilities (`peek_literal_delimiter`). When an escape character was defined as `"|"` (pipe) or characters with delimiter special meaning, `split_delimiter_alternatives` split `"|"` into empty tokens `["", ""]`, leading to matching zero bytes repeatedly at stream position 0.

The issue was resolved by replacing delimiter-based tokenization with direct byte-level lookahead against decoded character entity byte sequences, strictly obeying DFDL 1.0 §13.2.1 escape scheme semantics. All review filenames across the repository were also standardized to `review_YYYYMMDD_HHMMSS.md`.

---

### 2. Root Cause Analysis
1. **Delimiter Syntax vs Escape Characters:**
   In DFDL §12, delimiters (`separator`, `terminator`) support lists of alternatives separated by `|` (e.g., `,|\t|%NL;`). In contrast, DFDL §13 defines `escapeCharacter` and `escapeEscapeCharacter` as single character expressions or character entities (e.g. `%#x7C;` or `|`).
2. **Infinite Loop in `peek_literal_delimiter`:**
   In `section06/entities/Entities.tdml`, `EscapesSchema` defines `dfdl:escapeCharacter="|"`.
   The parser called `peek_literal_delimiter(escape_char, ...)`, which invoked `split_delimiter_alternatives("|")`. This produced two empty strings. An empty string delimiter matches immediately with 0 bits consumed, creating an infinite `while` loop that never advanced the stream.
3. **DFDL §13.2.1 Ambiguity Resolution:**
   When `escapeEscapeCharacter == escapeCharacter`, lookahead must check whether another escape character immediately follows. If so, it escapes itself (emitting a single literal); if not, it acts as an `escapeCharacter`, escaping any following in-scope delimiter or extra escaped character. If followed by neither, the escape character is discarded and the subsequent character treated as data.

---

### 3. Implementation Details
- **Byte-Level Escape Lookahead (`crates/dfdl-core/src/kernel/parser/text.rs`):**
  - Replaced `peek_literal_delimiter` for escape characters with exact byte sequences derived from `decode_dfdl_character_entities()` and encoded via `encode_text_string()`.
  - Used `reader.peek_bytes()` and `reader.consume_bytes()` for non-destructive check and consumption.
  - Implemented exact DFDL §13.2.1 handling for:
    - Escaped delimiters
    - Escaped escape characters (`escapeEscapeCharacter` escaping `escapeCharacter`)
    - Same character for escape and escape-escape
    - EOF dangling escape characters (discarded per specification)
- **Review Filename Standardization:**
  - Standardized all 7 non-conforming review files (`review_20261003_*.md`) from `_HHMM.md` to `_HHMMSS.md`.
