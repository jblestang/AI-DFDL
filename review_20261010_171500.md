## 1. Scope and Objective

Extension of pre-compiled DFDL properties (`DfdlProp<T>`) across the engine to eliminate runtime Pest parsing (`parse_expr`) and manual string scanning (`starts_with('{')`):
- `DfdlProp::Constant(T)`: Statically resolved value folded at schema compilation time.
- `DfdlProp::Expression { raw, ast }`: Validated and pre-compiled expression AST ready for direct evaluation in `ExprContext`.

Properties extended:
1. `length_prop`: `Option<DfdlProp<usize>>`
2. `occurs_count_prop`: `Option<DfdlProp<usize>>`
3. `nil_value_prop`: `Option<DfdlProp<String>>`
4. `text_standard_decimal_separator_prop`: `DfdlProp<String>`
5. `text_standard_grouping_separator_prop`: `DfdlProp<String>`
6. `calendar_pattern_prop`: `Option<DfdlProp<String>>`
7. `calendar_language_prop`: `Option<DfdlProp<String>>`
8. `calendar_time_zone_prop`: `Option<DfdlProp<String>>`
9. `output_new_line_prop`: `Option<DfdlProp<String>>`
10. `text_standard_exponent_rep_prop`: `Option<DfdlProp<String>>`
11. `text_boolean_true_rep_prop`: `Option<DfdlProp<String>>`
12. `text_boolean_false_rep_prop`: `Option<DfdlProp<String>>`

In addition to previously converted properties:
- `byte_order_prop`: `DfdlProp<ByteOrder>`
- `encoding_prop`: `DfdlProp<String>`
- `separator_prop`: `Option<DfdlProp<String>>`
- `initiator_prop`: `Option<DfdlProp<String>>`
- `terminator_prop`: `Option<DfdlProp<String>>`

## 2. Technical Evaluation by Domain

### A. Compiler Construction & Expression AST Pipeline
- **Observation:** In the previous implementation, runtime parsing called `parse_expr(...)` on raw property strings each time an element or delimiter was parsed/unparsed.
- **Resolution:** By introducing `DfdlProp<T>` with immediate compilation in `to_resolved_properties` and `SchemaBuilder::add_term_with_props`, expression parsing is strictly performed during schema compilation. Runtime routines now evaluate pre-parsed `ExprAst` nodes directly via `crate::expr::eval_expr` with zero Pest parser overhead.
- **Edge cases covered:**
  - DFDL §11.1 non-byte encodings prohibition for dynamic expressions correctly maintained (expressions enclosed in `{}` remain `DfdlProp::Expression` rather than constant-folding to preserve validation errors).
  - Escaped braces `{{` correctly de-escaped to literal `{` in `DfdlProp::parse_with`.
  - Empty delimiters `""` correctly map to `None` in `Option<DfdlProp<String>>`.

### B. Safety & Memory Footprint (`no_std` + `alloc`)
- **Evaluation:** `DfdlProp<T>` relies exclusively on `alloc::{string::String, boxed::Box}` and standard Rust enums. No heap allocations occur on the fast `Constant(T)` path.
- **Result:** Fully compatible with `#![no_std]` embedded targets and zero memory leaks.

### C. Backward Compatibility & Test Robustness
- **Evaluation:** Hand-crafted unit tests that instantiate `ResolvedProperties::default()` and manually assign raw string fields without going through `SchemaBuilder` are supported through fallback checks in runtime parser and unparser functions.
- **Result:** 100% of unit tests pass (289/289), all doc-tests pass (4/4), and official Apache Daffodil TDML test suite achieves 4,331 / 4,336 passes (99.9%) with zero regressions.
