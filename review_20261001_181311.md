## 2. Multi-Domain Technical Review

### 2.1 Schema Compiler & Type Lowering Architecture
- **Built-in Simple Type Restrictions & Inherited Facets (DFDL §5.1, §5.2, §12.3.2):**
  - Retained declared XML Schema type name on `XsdElement` as `pub type_name: Option<String>` to preserve type identity across AST lowering.
  - Automatically injected canonical XML Schema facets for built-in derived integer types:
    - `xs:integer`: `fractionDigits = 0`.
    - `xs:nonNegativeInteger`: `fractionDigits = 0`, `minInclusive = 0`.
    - `xs:positiveInteger`: `fractionDigits = 0`, `minExclusive = 0`.
    - `xs:nonPositiveInteger`: `fractionDigits = 0`, `maxInclusive = 0`.
    - `xs:negativeInteger`: `fractionDigits = 0`, `maxExclusive = 0`.
  - Enforced DFDL Section 12.3.2 Table 23: `lengthKind='implicit'` with `representation='text'` is strictly forbidden for all numeric types (`xs:decimal`, `xs:double`, `xs:float`, `xs:integer`, `xs:int`, `xs:short`, `xs:byte`, and unsigned equivalents), returning a Schema Definition Error.
  - Enforced DFDL Section 12.3.7.2: Binary integer bit length bounds validation (`1..=8` for byte, `1..=16` for short, `1..=32` for int, `1..=64` for long), rejecting invalid bit lengths (such as 64 bits on `xs:unsignedInt`).
  - Prohibited runtime-specified dynamic length expressions for binary floating point types (`xs:float`, `xs:double`), enforcing DFDL §12.3.7.2.

### 2.2 Property Validation & DFDL Escape Scheme Validation (DFDL §6.3, DFDL-6-036R)
- **Problem Statement:** Previously, `dfdl:defineEscapeScheme` and `dfdl:escapeScheme` stored attributes into a temporary property bag that was discarded without calling `to_resolved_properties()`. Consequently, entity and whitespace constraints on properties such as `escapeBlockStart`, `escapeBlockEnd`, `escapeCharacter`, and `escapeEscapeCharacter` were bypassed.
- **Architectural Solution:**
  - Invoked `to_resolved_properties(None)` directly on the escape scheme property store, triggering `validate_dfdl_property_entities`.
  - Enforced `property_forbids_literal_whitespace`: literal whitespace in escape properties (e.g. `escapeBlockStart="[ start ]"`, `escapeCharacter=" "`) is rejected with a Schema Definition Error requiring DFDL character entities (e.g. `%SP;`).
  - Enforced `property_disallows_character_classes`: forbidden character class entities (e.g. `%NL;`, `%WSP;`) are rejected in all numeric pad, boolean rep, and NaN/infinity properties.
  - Enforced rejection of unsupported `textBidi="yes"` and `floating="yes"` with Schema Definition Errors.
  - Validated `textNumberPattern` syntax: rejected missing positive parts, grouping separators in scientific notation (`E` with `,`), and unescaped trailing pad characters (`*`).

### 2.3 Kernel Parser & Unparser Diagnostics
- **Text Number Parsing (`crates/dfdl-core/src/kernel/parser.rs`):**
  - In `parse_flexible_int_i64` and `parse_flexible_uint_u64`: allowed zero fractional parts (`.00`) in lax mode while strictly rejecting non-zero decimal portions (e.g. `5.01`), aligning lax ICU behavior with XML Schema datatypes.
  - In `parse_text_value` for `DfdlSimpleType::Decimal`: added lexical digit validation (rejecting malformed strings like `"9a9"` or `"9a99"`), and enforced facet constraints `fractionDigits == 0` and `minInclusive == 0`.
- **Unparser Infoset Validation & Nilled State Handling (`crates/dfdl-core/src/kernel/unparser.rs` & `tree.rs`):**
  - Added `pub nil_attribute: Option<bool>` to `InfosetElement` to faithfully capture `xsi:nil` presence and boolean value.
  - In `parse_infoset_xml`:
    - Validated lexical representation of `xsi:nil`, strictly requiring `"true"`, `"false"`, `"1"`, or `"0"`.
    - Detected and rejected content errors: `xsi:nil="true"` on simple elements with text content, and `xsi:nil="true"` on complex elements with child nodes.
  - In `UnparserEngine`:
    - Validated that elements with `nil_attribute: Some(_)` or in `ElementState::Nil` are declared with `is_nillable="true"`. On non-nillable elements, an Unparse Error is raised: `"Unparse Error: Element '<name>' defines nil property but is not nillable"`.
    - Generalized `validate_unparse_value` across all simple numeric and string types.
    - Prevented integer truncation in TDML XML parsing by serializing large integers into `DfdlValue::Long`.

### 2.4 Expression Evaluation (`crates/dfdl-core/src/expr/eval.rs`)
- Validated `dfdlx:lookAhead` arguments: offset and bitLength must be non-negative values of type `xs:unsignedInt`. Negative values raise a Schema Definition Error (`"Schema Definition Error: out of range for xs:unsignedInt: <n>"`).

## 3. Residual "Expected Error Not Raised" Failure Clusters (401 remaining)

The remaining 401 test cases where an expected error was not raised fall into the following distinct categories:
1. **Layer Transformation Bombs (~45 test cases):** Test cases using custom Daffodil test layers (`CheckDigit`, `LineFolded`, `BombOutLayer`) that intentionally panic or throw exceptions during specific lifecycle hooks (`closeOutput`, `write`, `wrapInput`, `closeInput`, `getter`, `setter`).
2. **Unsupported Expression Functions (~25 test cases):** Calls to unsupported functions such as `fn:error()` or query-style XPath paths.
3. **Complex Unparser Infoset Structural Checking (~30 test cases):** Missing elements in complex type unparsing where mandatory sequence children are omitted from the infoset without defaults.
4. **Tunable Limits & Character Encoding Exceptions (~20 test cases):** Tests expecting specific tunable violations (`minValidYear`, `maxValidYear`) or ICU unmappable character exceptions.

## 4. Conclusion

Through generalized, specification-compliant architectural improvements, "Expected Error Not Raised" failures were reduced by 55 test cases (-12.1%), overall passing test cases reached a new record of **3,152** (+19), and strict `#![no_std]` compatibility and zero compiler/clippy warnings were fully preserved.
