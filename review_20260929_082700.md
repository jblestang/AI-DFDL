## Summary of Fixes Implemented

### 1. Primitive Scalar Binary Parsing & Byte Ordering (§12.3)
- **Root Cause**: `parse_binary_value` performed 64-bit byte-swapping on `u64` values regardless of the primitive bit-width (e.g. 16-bit `Short`, 32-bit `Int`), producing `0` for LittleEndian integers and truncating primitive values.
- **Fix**:
  - Implemented width-aware byte swapping per type:
    - 16-bit (`Short`, `UnsignedShort`): `val_u16.swap_bytes()`
    - 32-bit (`Int`, `UnsignedInt`, `Float`): `val_u32.swap_bytes()`
    - 64-bit (`Long`, `UnsignedLong`, `Double`): `val_u64.swap_bytes()`
  - Implemented `sign_extend` function for arbitrary-bit signed integers (e.g. $N$-bit signed values sign-extended to native Rust scalar types).
- **Unit Test**: `test_binary_value_little_endian` in [`crates/dfdl-core/src/kernel/parser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L1023-L1039).

### 2. Annotation Property Parsing (`<dfdl:property>` Tags) (§6.3)
- **Root Cause**: Schema compiler `parse_annotation_container` in `dfdl-schema` only extracted attributes from elements inside `<xs:annotation><xs:appinfo>` blocks, discarding `<dfdl:property name="inputValueCalc">{ ... }</dfdl:property>` element body content.
- **Fix**: Added `local == "property"` element handling in [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs#L561-L591) to capture element text content into `PropertyStore`.

### 3. Text Length Units Bit-to-Byte Conversion (§12.2)
- **Root Cause**: When `lengthUnits="bits"` was specified for explicit length text scalars, `parse_text_value` read `len` bytes instead of `len / 8` bytes, causing premature `EOF` errors.
- **Fix**: Converted bit length to byte length (`len / 8`) when `props.length_units == LengthUnits::Bits` in `parse_text_value`.
- **Unit Test**: `test_text_value_bits_length_units` in [`crates/dfdl-core/src/kernel/parser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L1056-L1073).

### 4. Unaligned Bit-Addressable Rollbacks (§9.2, §13)
- **Root Cause**: `BitReader::rollback` attempted `ByteSource::set_position` directly with raw `BitOffset`. When `bit_offset % 8 != 0`, `ByteSource` rejected the seek with `"Byte source position must be byte-aligned"`.
- **Fix**: Updated `BitReader::rollback` in [`crates/dfdl-core/src/io/bitstream.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/io/bitstream.rs#L154-L167) to seek to the byte boundary (`bit_pos / 8 * 8`) and advance by `bit_pos % 8` bits.
- **Unit Test**: `test_unaligned_bitreader_rollback` in [`crates/dfdl-core/src/kernel/parser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L1040-L1054).

### 5. Infoset Document Construction Fallback (§14)
- **Root Cause**: `InfosetBuilder::build()` returned `"Infoset document incomplete: no root element"` if `doc.root` was `None`, even when element stack contained parsed root elements.
- **Fix**: Updated `build()` in [`crates/dfdl-core/src/infoset/tree.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/infoset/tree.rs#L273-L283) to fall back to `self.stack.first()` when `doc.root` is unset.
