## 1. Domain Expertise Analysis

### 1.1 Concurrency, Performance & Infinite Loop Elimination in Delimiter Parsing
- **Zero-Length Delimiter Matches & Loop Termination:**
  - *Standard & Parsing Architecture Context:*
    In DFDL sequences with `separatorPosition="infix"` / `prefix` / `postfix` and `separatorSuppressionPolicy="anyEmpty"`, separator sequences can be empty (e.g. `separator=""` in `DFDLGeneralFormatBase.dfdl.xsd`, or `%ES;`). When `peek_delimiter_match_length` matches an empty token (`DelimToken::ES`), it returns `Some(0)` without advancing the stream.
  - *Root Cause Discovered:*
    In `crates/dfdl-core/src/kernel/parser.rs`, the separator consumption loops (`parse_element_with_separators` and sequence trailing separator loop) used `while !self.reader.is_eof()` without verifying that the matched separator length `> 0`. Whenever a schema had an empty separator, the parser matched 0 bytes, skipped 0 bytes, and looped forever at 100% CPU, causing test runner timeouts and process freezes.
  - *Fix Applied:*
    1. Guarded all separator consumption with `if !sep.is_empty()`.
    2. Added immediate break conditions: `if sep_len == 0 || self.is_in_scope_terminator_longer(sep_len) { break; }`.
    3. Result: The full test suite of 4,337 test cases runs to completion in **4.95 seconds** with **zero hangs**.

### 1.2 DFDL 1.0 Nillable Semantics & Delimiter Policies (DFDL 1.0 §13.15)
- **`dfdl:nilValueDelimiterPolicy` & Literal Character Repetitions:**
  - *Standard Requirement (DFDL 1.0 §13.15):*
    - The property `dfdl:nilValueDelimiterPolicy` controls whether an initiator, terminator, or both are required when a nil value is matched:
      - `initiator`: only the initiator is required.
      - `terminator`: only the terminator is required.
      - `both`: both initiator and terminator are required (default).
      - `none`: neither initiator nor terminator is required.
    - When `nilKind="literalCharacter"`, the nil value is a character that repeats for the entire length of the element (derived from `length` or `maxLength`).
    - When `nilValue="%ES;"` or `""`, an empty string nil matches if the element is empty, bounded by its terminator or enclosing scope delimiters without advancing the reader.
  - *Root Cause Discovered:*
    - `NilValueDelimiterPolicy` was missing from `ResolvedProperties`, so schemas specifying `nilValueDelimiterPolicy="none"` still enforced framing.
    - Literal character nils (e.g. `literal-character-nils.tdml`) only compared a single character rather than checking if the entire fixed length was filled with the literal character.
    - Empty string nils (`%ES;`) attempted literal string matching which failed because `DelimToken::ES` produces zero length, or falsely matched non-empty data.
  - *Fix Applied:*
    1. Added `NilValueDelimiterPolicy` (`Both`, `Initiator`, `Terminator`, `None`) to [`ResolvedProperties`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs#L117-L130).
    2. Implemented repeating character nil matching across explicit lengths in [`parse_simple_primitive`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L1735-L1753).
    3. Implemented delimiter-aware empty nil matching checking terminator / EOF / in-scope delimiters in [`parser.rs:1754-1804`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L1754-L1804).

### 1.3 Implicit Alignment Calculation (DFDL 1.0 §12.1.2 Table 34 & §12.2)
- **Automatic Alignment Derivation for Primitive Types:**
  - *Standard Requirement (DFDL 1.0 §12.1.2 Table 34):*
    When `alignment="implicit"`, the alignment in bits is derived from the representation and type:
    - Binary integers: 8 bits (`xs:byte`), 16 bits (`xs:short`), 32 bits (`xs:int`), 64 bits (`xs:long`).
    - Binary floats: 32 bits (`xs:float`), 64 bits (`xs:double`).
    - Textual representations: Derived from character encoding (UTF-8 = 8 bits, UTF-16 = 16 bits, UTF-32 = 32 bits).
    - `xs:string` representation is ALWAYS `Text` per §12.2, even if enclosing schema defaults to `binary`.
  - *Fix Applied:*
    1. Implemented `compute_implicit_alignment` in [`crates/dfdl-schema/src/compiler.rs:2530-2615`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs#L2530-L2615).
    2. Enforced `xs:string` representation defaults to `Text` in `compiler.rs:1992-1997`.
    3. Resolved `implicitAlignmentString1`, `implicitAlignmentUnsignedInt`, `implicitAlignmentInt`, and related alignment test suites in `Aligned_Data.tdml`.
