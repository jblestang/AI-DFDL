## 1. Character Encoding Engine (`dfdl:encoding`) Implementation
In response to review feedback regarding strict DFDL 1.0 §11 compliance, the ad-hoc byte conversion was replaced with a dedicated, modular, panic-free character encoding engine in [`crates/dfdl-core/src/encoding.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/encoding.rs).

### Supported DFDL Encodings (§11.1)
- **`UTF-8` / `UTF8`**: Strict UTF-8 validation with lossy byte-to-char fallback for malformed byte sequences.
- **`UTF-16` / `UTF-16BE` / `UTF-16LE`**: Multi-byte 16-bit code unit decoding in big-endian or little-endian byte ordering.
- **`ASCII` / `US-ASCII` / `ASCII-7`**: 7-bit ASCII character range enforcement (`0..=127`).
- **`ISO-8859-1` / `Latin1` / `CP1252`**: Single-byte ISO-8859-1 mapping (`0..=255`).
- **`EBCDIC` / `IBM037` / `CP037`**: Full 256-entry EBCDIC-US (IBM037) byte-to-Unicode mapping table.

## 2. Integration into Engine Parser
- Both `parse_text_value` and `parse_binary_value` (for `xs:string`, `xs:dateTime`, `xs:date`, `xs:time`, `xs:decimal`) now decode raw bitstream bytes via `crate::encoding::decode_text_bytes(&bytes, &props.encoding)`.
- Eliminates hardcoded UTF-8 assumptions and enables native parsing for multi-byte UTF-16, EBCDIC, and ASCII datasets without external dependencies.
