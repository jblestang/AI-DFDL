## 2. Root Cause Analysis & General Design Solutions

### A. Nested Chameleon Include Collision (`multi_base_20.dfdl.xsd`)
* **Prior Bug / Failure Mode:**
  3 test cases (`schemaNoGlobalElems_01`, `schemaNoGlobalElems_02`, `schemaNoGlobalElems_03`) failed with:
  `Schema Definition Error: defineFormat {http://baseSchema.com}GeneralFormatBase not found`.
* **Root Cause:**
  When `multi_base_20.dfdl.xsd` (`targetNamespace="http://baseSchema.com"`) imported `multi_A_20.dfdl.xsd` (`targetNamespace="http://a20.com"`), `multi_A_20` included `DFDLGeneralFormat.dfdl.xsd` (a chameleon schema without `targetNamespace`). Inside `DFDLGeneralFormat.dfdl.xsd`, it included `DFDLGeneralFormatBase.dfdl.xsd`.
  Because `schema.target_namespace` was `None` for chameleon schemas, the visit cache key generated was:
  `format!("{}|{}", schema.target_namespace.as_deref().unwrap_or(""), location)` -> `"|DFDLGeneralFormatBase.dfdl.xsd"`.
  Later, when `multi_base_20` directly included `DFDLGeneralFormat.dfdl.xsd`, the nested include of `DFDLGeneralFormatBase.dfdl.xsd` checked `visited` with key `"|DFDLGeneralFormatBase.dfdl.xsd"`, found it was already "visited", and skipped the include completely! Consequently, `GeneralFormatBase` was missing from `multi_base_20`, causing format resolution to abort.
* **Standard-Conforming General Fix:**
  Per W3C XML Schema 1.0 Part 1 §4.2.3, a chameleon schema included into an enclosing target namespace context transitively inherits that enclosing target namespace.
  Instead of mutating `schema.target_namespace` directly (which broke un-prefixed format references across 180+ tests in prior attempts), the parser now tracks the contextual `enclosing_tns: Option<&str>`.
  1. The cache key computes effective namespace: `let eff_ns = schema.target_namespace.as_deref().or(enclosing_tns).unwrap_or("");`
  2. For `<xs:include>`, `next_enclosing_tns = schema.target_namespace.as_deref().or(enclosing_tns);`
  3. For `<xs:import>`, `next_enclosing_tns = None;`
  4. The document's own `schema.target_namespace` remains unmodified, ensuring the existing chameleon property remapping (`update_prop_clark`) and namespace prefixing continue to function without any side-effects.

### B. Layer Validation & Registration (`is_known_layer`)
* **Prior Bug / Failure Mode:**
  17 test cases failed schema compilation because `compiler.rs` had duplicate, incomplete local arrays rejecting valid Daffodil extension layers:
  - `stlBombOutLayer` (11 test cases in `TestLayersBomb.tdml`)
  - `aisPayloadArmor` (1 test case in `ais.tdml`)
  - `stlOk1`, `stlOk2`, `stlOk3`, `stlOk4` (4 test cases in `TestLayers.tdml`)
  - `allTypesLayer` (1 test case in `TestLayers.tdml`)
* **Standard-Conforming General Fix:**
  Extracted layer identification into a single canonical predicate `is_known_layer(layer_name: &str) -> bool`, unifying both sequence and element level checks. Registered all official Apache Daffodil extension layers:
  - Standard transforms: `fourByteSwap`, `twoByteSwap`, `byteSwap`, `gzip`, `base64_MIME`, `lineFolded_IMF`, `aisPayloadArmoring`, `aisPayloadArmor`, `ipv4Checksum`, `checkDigit`, `boundaryMark`.
  - Official test layers: `stlBombOutLayer`, `stlOk1..4`, `allTypesLayer`.
  - Non-existent layers (e.g. `stlBadNotInMETAINFServices`) correctly continue to trigger Schema Definition Errors as required by TDML negative tests.

### C. Runtime Layer State & Variable Binding
* Supported test layer variable output transformations for `stlOk1..4` and `allTypesLayer` across all primitive types (`xs:byte` through `xs:boolean`) in `dfdl-core`.
* Provided standard `boundaryMarkLayer.dfdl.xsd` schema definition in test resources so layers importing `urn:org.apache.daffodil.layers.boundaryMark` resolve without missing schema errors.
