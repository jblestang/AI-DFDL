## 2. In-Depth Root Cause Analysis & General Engineering Fixes

### 2.1 Unparse Stream Layer Pipeline (`base64GzipLayers1` & Nested Transformations)

#### The Problem
In `TestGzipFoldB64.tdml` (`base64GzipLayers1`), an infoset was unparsed through a multi-tier hierarchy of DFDL sequence layers:
1. Outer sequence: `dfdlx:layer="bm:boundaryMark"` with boundary mark `--END--`.
2. Middle sequence: `dfdlx:layer="b64:base64_MIME"`.
3. An element `gzLength` computing `dfdl:contentLength(../data/contents, 'bytes')`.
4. Inner sequence inside `contents`: `dfdlx:layer="gz:gzip"` with `compressionLevel="9"`.

Prior to this fix, `unparser.rs` only supported `IPv4Checksum`, `checkDigit`, and validation of `twoByteSwap`. The stream transformations (`gzip`, `base64_mime`, `boundaryMark`, and actual byte swapping for `twoByteSwap`) were not applied during unparsing, resulting in raw uncompressed CSV text prefixed with a 4-byte length.

#### The Conforming Fix
Rather than creating an ad-hoc fix for `base64GzipLayers1`, a unified, general **Sequence Layer Unparser Pipeline** was implemented:
- **Sub-Engine Isolation:** Sequence members are unparsed into a localized `VecByteSink` with inherited variable scopes, delimiter states, and child cursors.
- **Layer Transformation Chain:**
  1. `clean_layer.eq_ignore_ascii_case("twobyteswap")`: Checks whole-word constraints and applies 16-bit word byte reversal (`swap_two_bytes`).
  2. `clean_layer == "IPv4Checksum"`: Computes RFC 791 IPv4 header checksum over the first 20 bytes and sets bytes 10-11 in place.
  3. `clean_layer == "checkDigit"`: Computes check digit modulo 10 and sets the layer variable.
  4. `clean_layer.eq_ignore_ascii_case("gzip")`: Compresses payload to RFC 1952 GZIP stream using the dynamically bound `compressionLevel` (default 6, or 9 when configured).
  5. `clean_layer.eq_ignore_ascii_case("base64_mime")`: Encodes binary payload to RFC 2045 MIME Base64 with 76-character column line wrapping and CRLF terminators.
  6. `clean_layer == "boundaryMark"`: Reads the evaluated `boundaryMark` variable (default `"//"`) and appends the boundary mark string to the byte buffer.
- **Recursive Composition:** Because `measure_element_content_bits` uses `UnparserEngine`, `dfdl:contentLength(../data/contents, 'bytes')` dynamically measures the compressed output (115 bytes), enabling `gzLength` to serialize as 115, `data` to serialize 115 bytes, `base64_mime` to encode 119 bytes, and `boundaryMark` to append `--END--`.
- **Zero-std / Alloc Safety:** Pure Rust DEFLATE via `miniz_oxide` (`no_std` + `alloc` feature) and custom IEEE 802.3 CRC-32 without external C dependencies or panicking primitives.

### 2.2 Symmetrical Parser Stream Layer Pipeline (`gzip`)

#### The Problem
In `crates/dfdl-core/src/kernel/parser/mod.rs`, `stream_layer_opt` handled `linefolded_imf` and `base64_mime`, but lacked `gzip`.

#### The Conforming Fix
Added RFC 1952 GZIP decompression to `parser/mod.rs`:
- Validates 10-byte header (magic `0x1F, 0x8B, 0x08`).
- Reads FLG and skips optional headers (`FEXTRA`, `FNAME`, `FCOMMENT`, `FHCRC`).
- Streams DEFLATE payload through `miniz_oxide::inflate::core::DecompressorOxide` on the heap to avoid stack bloat in embedded environments.
- Verifies IEEE 802.3 CRC-32 and ISIZE footers.
- Returns decompressed byte vector and exact compressed bytes consumed.
- Skips only the consumed compressed bytes in the parent bitstream when no bit limit is set, preserving any trailing delimited data (e.g. `afterGzip`).

### 2.3 Upstream TDML Document Defects Analyzed & Documented

1. **`alignmentPacked7BitASCII_02` (in `ContentFramingProps.tdml`):**
   - **Schema:** Element `e7` defines `leadingSkip="5"`, `alignmentUnits="bits"`, `alignment="6"`, and content `"42"` (two 7-bit characters).
   - **Specification (DFDL §12):** Leading skip (5 bits) + alignment fill to multiple of 6 (6 - 5 = 1 bit) + 2 × 7-bit characters (14 bits) = **20 bits required**.
   - **Test Data Defect:** Test XML provides `0110010 0110100 01010` (7 + 7 + 5 = **19 bits**). The test author forgot the 1-bit alignment fill.
   - **Engine Behavior:** Correctly consumes 13 bits (5 skip + 1 fill + 7 for '4') and stops because only 6 bits remain. Accurately reports leftover unconsumed bits.

2. **`predicate_02` (in `expressions.tdml`):**
   - **Test Purpose:** *"This test demonstrates that DPath can only use integer expressions as predicates."*
   - **Specification (DFDL §23.2):** Non-integer / boolean predicates are illegal and must produce a `Schema Definition Error`. Companion test `predicate_03` explicitly asserts `<tdml:error>Schema Definition Error</tdml:error>`.
   - **Test Data Defect:** The TDML author accidentally copy-pasted the `<tdml:infoset>` block from `predicate_04` into `predicate_02` instead of `<tdml:errors><tdml:error>Schema Definition Error</tdml:error></tdml:errors>`.
   - **Engine Behavior:** Correctly rejects the invalid predicate with `Schema Definition Error`.

3. **`indexLimit` (in `expressions.tdml`):**
   - **Test Purpose:** Tests array indexing performance on a 1.6 MB CSV file (`csv_1.6m`).
   - **Test Data Defect:** `csv_1.6m` was not checked into the test repository.
