## 2. Domain Expertise & Specification Analysis

### 2.1 DFDL §6.3.1 Character Entities & Delimiter Matching
- **Specification Rule:** DFDL standard character entities (e.g. `%SOH;`, `%SO;`, `%SI;`, `%ACK;`, `%DEL;`) represent specific character codes in the component's encoding. When used in delimiters, they represent literal byte sequences rather than dynamic regex or whitespace classes.
- **Deficiency Identified:** In [delimiters.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs), `parse_single_delim_tokens` recognized only `%NL;`, `%CR;`, `%LF;`, `%NEL;`, `%LS;`, `%FF;`, `%VT;`, `%SP;`, `%HT;`, `%NUL;`, `%ES;`, and `%WSP*;`/`+`/`;`. Any other `%<NAME>;` returned an immediate `SchemaDefinition` error, preventing delimiter recognition. Additionally, `%SO;` (`\x0E`) and `%SI;` (`\x0F`) were missing from `decode_dfdl_character_entities`.
- **Systemic Resolution:**
  - Added `%SO;` and `%SI;` to [properties.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs).
  - Updated `parse_single_delim_tokens` to decode `%<NAME>;` via `decode_dfdl_character_entities` and push the decoded bytes into `current_lit`, matching them as literal bytes without altering character class semantics.

### 2.2 DFDL §13.6 ICU textNumberPattern Affixes & Padding
- **Specification Rule:** ICU DecimalFormat patterns define prefix, body, and suffix. Single quotes enclose literal characters, and consecutive single quotes `''` produce a single literal quote. A pad escape `*<pad_char>` specifies padding character and location. Per §13.6:
  > "A negative subpattern specifies only the negative prefix and suffix. All other attributes are taken from the positive subpattern. This includes the pad character and pad position."
- **Deficiencies Identified:**
  1. `trim_matches('\'')` stripped only edge quotes and did not unescape `''` or embedded quotes.
  2. Pattern digit searching scanned `#` and `0` inside `'...'` and characters consumed by `*<pad_char>` (e.g. in `*##`).
  3. `PatternPadPos::BeforeSuffix` attempted to trim trailing pad characters *before* stripping the suffix, leaving pad characters unstripped.
  4. In `text.rs`, `normalize_text_number` was called on `val_str` prior to `parse_int`, stripping affixes before strict pattern validation occurred.
- **Systemic Resolution:**
  - Added [`unquote_icu_affix`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/numbers.rs) handling `'...'` and `''` unescaping.
  - Implemented state-machine scanning in [`extract_pattern_affixes`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/numbers.rs) to skip quoted sections and pad escape characters.
  - Corrected [`strip_pattern_affixes_and_pad`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/numbers.rs) for `BeforeSuffix` to strip suffix before trimming pad characters.
  - In `text.rs`, passed raw `val_str` to `parse_int`, `parse_uint`, and `parse_float` so pattern matching operates directly on the bitstream text.

### 2.3 DFDL §13.15 Complex Element Nil Representation
- **Specification Rule:** Complex elements may only be nilled with `dfdl:nilValue="%ES;"`. If an initiator is present, the element is nil only if no child content is present before its terminator or enclosing scope boundary.
- **Deficiency Identified:** For complex elements with `lengthKind="implicit"`, `nilValue="%ES;"` evaluated to true on empty parsed bytes, incorrectly marking complex elements as nilled and leaving child data unparsed in the stream.
- **Systemic Resolution:** In [element.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs), verified that for complex elements with `%ES;`, nil is only acknowledged if an expected terminator matches or the reader is at EOF/enclosing delimiter boundary.
