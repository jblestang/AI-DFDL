## 1. Domain & Conformance Audit Findings

### 1.1 Element Evaluation Context Propagation (DFDL 1.0 §18)
- **Problem**: When evaluating element-level expressions (such as `dfdl:occursCount`, `dfdl:length`, `dfdl:inputValueCalc`, and `<dfdl:assert>`), `ExprContext` was initialized using `builder.current_path()` without including the target element name itself. As a result, relative paths like `../header/message_size` or `../xCount` popped the parent container path instead of the element path, failing path resolution.
- **Fix Implemented**:
  - Updated [`evaluate_asserts`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L646) and [`evaluate_length_property`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L692) in `crates/dfdl-core/src/kernel/parser.rs` to accept `elem_name: Option<&str>` and push `elem_name` onto `current_path`.

### 1.2 Root Node `..` Popping Protection (XPath 2.0 / DFDL §18)
- **Problem**: In `resolve_path`, when a path contained `..` segments while `norm` was at the document root node (`/`), calling `norm.pop()` stripped the root path structure.
- **Fix Implemented**:
  - Updated [`resolve_path`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/eval.rs#L202) in `crates/dfdl-core/src/expr/eval.rs` to check `if norm.is_absolute() && norm.segments().is_empty() { continue; }`, ensuring `..` at the root node safely remains at root.

### 1.3 Nested Relative Path Unit Test Coverage
- **Fix Implemented**: Added unit test `test_relative_path_navigation_nested` in [`crates/dfdl-core/src/expr/mod.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/mod.rs) verifying `../header/message_size - 4` navigation from `/e2/message`.
