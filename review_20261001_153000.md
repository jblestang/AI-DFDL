## 2. Specification Conformance & Architectural Fixes

### 2.1 DFDL §14.2 & §16.1.2 — Infix Speculative Separator Rollback
- **Problem Statement:** In sequence groups with `dfdl:separatorPosition="infix"` and `dfdl:separatorSuppressionPolicy="anyEmpty"`, speculative parsing of optional array element occurrences (e.g. `street` in `address2` with `minOccurs="0" maxOccurs="2" dfdl:occursCountKind="parsed"`) consumed an infix separator before attempting to parse the element body. When the occurrence failed to match (e.g., encountering the subsequent sibling `city`), previous code erroneously swallowed the separator under a misclassified empty element branch. Consequently, subsequent elements failed with `Delimiter mismatch in bitstream: delimiter='*'`.
- **Architectural Solution:**
  - In `crates/dfdl-core/src/kernel/parser.rs` (`parse_element_with_separators`), restricted separator retention on element parse error strictly to `sep_pos == SeparatorPosition::Prefix` (where non-trailing empty elements in `trailingEmptyStrict` retain their own prefix separator).
  - For `SeparatorPosition::Infix`, any element parse failure when `count >= min_occurs` triggers full transactional rollback of both the infoset checkpoint and the bitstream checkpoint (`reader_cp`) taken prior to separator matching.
  - Sibling elements (`city`, `state`, `country`) now receive their expected infix separator cleanly.

### 2.2 DFDL §12.3 & §15 — Choice Group In-Scope Terminator Scoping
- **Problem Statement:** Sequence groups and complex elements properly evaluated and registered their `dfdl:terminator` in `self.in_scope_terminators` and `self.in_scope_delimiters` prior to parsing their children. However, `TermKind::Choice` did not evaluate or push its terminator into delimiter scope. As a result, delimited string elements within a choice (e.g. `<xs:element name="str" type="xs:string"/>` with `lengthKind="delimited"`) did not recognize the choice's closing delimiter `)` as an in-scope terminator, consuming data up to EOF and causing the choice's terminator match to fail.
- **Architectural Solution:**
  - In `crates/dfdl-core/src/kernel/parser.rs` (`parse_term`), added uniform terminator evaluation and registration to `in_scope_terminators` and `in_scope_delimiters` for `TermKind::Choice`.
  - Scoping is safely managed via an isolated execution closure with guaranteed pop on both success and error paths, mirroring the sequence group implementation.

### 2.3 DFDL §12.1 & Appendix B (Table 53) — Non-Scoping Framing Properties
- **Problem Statement:** Complex elements specifying `dfdl:leadingSkip` and `dfdl:trailingSkip` (e.g. `e17` in `Aligned_Data.tdml`) propagated their framing skips to child sequences and child terms during schema lowering (`PropertyStore::merge_parent`) and resolution (`to_resolved_properties`). This caused nested sequences to skip double the framing bits, desynchronizing the bitstream and triggering delimiter mismatches on inner element terminators (`:`).
- **Architectural Solution:**
  - DFDL 1.0 explicitly designates `leadingSkip` and `trailingSkip` as non-scoping properties (alongside `initiator`, `terminator`, `separator`, and `occursCount`).
  - In `crates/dfdl-core/src/expr/properties.rs`, excluded `leadingSkip`, `trailingSkip`, and `occursCount` from `merge_parent`.
  - In `to_resolved_properties`, updated `leadingSkip` and `trailingSkip` resolution to read local properties via `self.get_property(...)` rather than inheriting from parent scopes.

### 2.4 DFDL §6.3.1 — Delimiter Literal Brace Unescaping (`{{` -> `{`)
- **Problem Statement:** DFDL schemas escape literal opening braces as `{{`. When parsed as delimiters, `{{` was previously treated as an expression attempt or remained unescaped, causing delimiters such as `{}` or `{{` to fail against the data stream.
- **Architectural Solution:**
  - In `crates/dfdl-core/src/kernel/parser.rs` (`evaluate_delimiter_str`), distinguished expressions (`starts_with('{') && !starts_with("{{") && ends_with('}')`) from literal escaped delimiters.
  - Literal brace escapes (`{{`) are unescaped to `{` across all simple types in delimited parsing.

### 2.5 DFDL §14.2 — Elimination of Sequence Separator Property Inheritance
- **Problem Statement:** Sequence separators previously inherited to child sequences and group references, leading child sequences and hidden groups to steal separators belonging to the outer sequence.
- **Architectural Solution:**
  - Per DFDL §14.2, removed `parent.and_then(|p| p.get_property("separator"))` fallback in `PropertyStore::to_resolved_properties`. Separators now apply strictly to the sequence group on which they are declared.

## 3. Domain Expert Reviews

### 3.1 Systems & Safety Domain Review
- **Transactional Invariant:** All bitstream rollbacks use exact `Checkpoint` structures tracking `(BitOffset, u32)` without loss of bit-level alignment. Rollbacks on speculative branches leave the bitstream precisely at the byte/bit boundary expected by the next member.
- **Panic Safety:** Replaced all test `expect(...)` invocations with robust pattern matching (`match ... { Ok(c) => c, Err(_) => return }`), preventing test runner crashes when optional external test resources are absent.

### 3.2 Cyber & Parser Security Domain Review
- **Denial-of-Service / Loop Termination:** Infix array parsing checks `(self.reader.is_eof() || (new_reader_cp == reader_cp && !has_next_sep))` to ensure zero-width element matches cannot cause infinite loops under `OccursCountKind::Parsed`.
- **Bounded Resource Consumption:** Scoped delimiter stacks (`in_scope_terminators`, `in_scope_delimiters`) are strictly bounded by schema depth (`MAX_TERM_DEPTH = 32`).

### 3.3 Embedded & `#![no_std]` Compatibility
- Compilation was verified against `thumbv7m-none-eabi`.
- Code relies solely on `core` and `alloc`, maintaining zero OS or stdlib dependencies in `dfdl-core` and `dfdl-schema`.
