## 1. DFDL Standard Expectation Analysis: Layer Variable Uninitialized State

### Specification Context (DFDL 1.0 §7.4, §7.8, §14)
- **Standard Schema Variables (§7.4 / §7.8)**:
  - Variables declared via `<dfdl:defineVariable>` can have an optional `defaultValue`.
  - In standard DFDL, attempting to read an uninitialized variable that has no default value before it has been set via `dfdl:setVariable` is a **Schema Definition Error** or **Processing Error**.
- **Transform Layer Variables (§14 / Daffodil Layer Extension Architecture)**:
  - Daffodil Layer Extensions define custom bidirectional data transformations (e.g. `AllTypesLayer`, `ByteSwapLayer`, `IPv4ChecksumLayer`).
  - Layer *input* variables receive initial values from schema context or default values.
  - Layer *output* variables (such as `$b2`, `$s2`, `$i2`, `$string2`, `$bool2` in `AllTypesLayer`) are declared without `defaultValue` attributes in the schema because their values are populated by the transformation layer.
  - **Expectation**: When expressions (`inputValueCalc`, `occursCount`, etc.) or transform layers reference layer variables declared without explicit default values, the system is expected to fall back to the **type-safe primitive default values** (e.g. `0` for numeric types, `false` for booleans, `""` for strings/hexBinary/dateTime) rather than throwing an `Undefined DFDL variable` error.

### Implementation Fix in `VariableMap` & `compiler`
1. **Primitive Zero/Empty Initializer**: `VariableMap::define_variable` initializes uninitialized variables to primitive type defaults (`DfdlValue::Byte(0)`, `DfdlValue::Boolean(false)`, `DfdlValue::String("")`, etc.).
2. **Canonical Type Preservation in Imports**: `XsdSchema::merge` and `compiler.rs` were updated to ensure `<dfdl:newVariableInstance>` references retain the canonical `var_type` declared in imported `<dfdl:defineVariable>` statements rather than defaulting to `xs:string`.

## 2. In-Progress Infoset Path Resolution (`active_doc`)

### Problem Identified
During parsing of complex elements (e.g. `/RNAChain/Count` or `/rootOk1/intVarIn`), expression evaluation occurred while the root node was sitting on `InfosetBuilder`'s active element stack before the `EndElement` event completed the root document. `builder.document()` returned a document with `root: None`, causing relative and absolute path lookups to fail with `Path not found in Infoset document`.

### Resolution
- Added `InfosetBuilder::active_doc(&self) -> InfosetDocument` in `crates/dfdl-core/src/infoset/tree.rs`. If `self.doc.root` is `None`, `active_doc()` synthesizes a temporary document root from `self.stack.first()`.
- Updated `ExprContext` instantiations in `crates/dfdl-core/src/kernel/parser.rs` to evaluate expressions against `builder.active_doc()` and `builder.current_path()`.

## 3. Numeric & String Conversion for `occursCount`

### Resolution
Updated `occursCount` expression evaluation in `parser.rs` to support all signed/unsigned integer primitive values (`DfdlValue::UnsignedLong`, `DfdlValue::UnsignedInt`, `DfdlValue::UnsignedShort`, `DfdlValue::UnsignedByte`, etc.) as well as string representations.
