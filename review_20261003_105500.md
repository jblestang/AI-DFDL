# Review 2026-10-03 10:55 - unmappable characters, lengthPattern, 6-bit/octal

Conformance 720 -> 708, no regressions. Fixed: packed7BitASCII4-8, packed7BitASCII_unparse2/3,
packed6BitASCII_unparse1/2, packed5Bit_unparse2, octalLSBF_unparse1, octalLSBF_unparse_error.

## Changes
- New property encodingErrorPolicy (`ResolvedProperties.encoding_error_policy_error`).
  Sub-byte unparse: `error` -> UnmappableCharacterException; `replace` -> per-encoding replacement
  code (5-bit X, 6-bit _, 7-bit ?, others 0). Unmappable pad characters use code 0.
- encoding.rs: `strict_sub_byte_code` / `sub_byte_replacement_code`. 6-bit packed table fixed
  (codes 0-31 = 0x40-0x5F, 32-63 = 0x20-0x3F). 7-bit, octal, hex, bits, base4 are strict instead of masking.
- lengthPattern in sub-byte encodings peeks in character width; match reported in characters
  (bits when lengthUnits=bits; bytes unit not handled).

## Remarks
- encodingErrorPolicy is not yet applied to byte encodings (US-ASCII, ISO-8859-1, ...) in
  `encode_text_string`; the same fix should be generalised there.
- No dedicated unit test for sub-byte lengthPattern (covered by 5 conformance tests).
- lengthPattern with lengthUnits=bytes on sub-byte text is not converted.
