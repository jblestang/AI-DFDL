## 1. Executive Summary & Defect Analysis (Issue F8)

### 1.1 Context & Specification Baseline
- **DFDL v1.0 §15.1.2 (`dfdl:choiceLength` and `dfdl:choiceLengthKind`):**
  The DFDL specification explicitly defines `dfdl:choiceLength` as a non-negative integer giving the length of the choice group in **bytes**.
  Unlike simple element length calculation (DFDL §12.3) which is parameterized by `dfdl:lengthUnits` (`bytes`, `bits`, or `characters`), choice group lengths are always specified in **bytes**.
- **Previous Defect:**
  In [crates/dfdl-core/src/kernel/parser/mod.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/mod.rs#L1194-L1202) and [crates/dfdl-core/src/kernel/unparser.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs#L788-L795), `choice_length` was conditionally converted to bit length based on `term.properties.length_units`:
  ```rust
  // PREVIOUS (INCORRECT) CODE:
  let explicit_choice_bits = if term.properties.choice_length_kind == LengthKind::Explicit {
      term.properties.choice_length.map(|l| {
          match term.properties.length_units {
              LengthUnits::Bits => l,
              _ => l.saturating_mul(8),
          }
      })
  }
  ```
  When a schema defined `dfdl:lengthUnits="bits"` in scope (or on a parent container) along with `choiceLength="2"`:
  - The parser/unparser allocated only `2` bits instead of `16` bits (2 bytes).
  - Any binary branch consuming 16 bits (such as `12 34`) was falsely rejected for exceeding the choice length (`"Parse Error: Branch consumed data exceeding explicit choiceLength"`).

## 2. Surgical Fixes Implemented

### 2.1 Parser Kernel ([crates/dfdl-core/src/kernel/parser/mod.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/mod.rs))
Decoupled `explicit_choice_bits` unconditionally from `term.properties.length_units`:
```rust
// DFDL §15.1.2: dfdl:choiceLength is always specified in bytes,
// regardless of any in-scope dfdl:lengthUnits.
let explicit_choice_bits = if term.properties.choice_length_kind == LengthKind::Explicit {
    term.properties.choice_length.map(|l| l.saturating_mul(8))
} else {
    None
};
```

### 2.2 Unparser Kernel ([crates/dfdl-core/src/kernel/unparser.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs))
Similarly updated padding bit computation to calculate `target_bits` unconditionally in bytes (multiplied by 8):
```rust
// DFDL §15.1.2: dfdl:choiceLength is always specified in bytes,
// regardless of any in-scope dfdl:lengthUnits.
let target_bits = target_len.saturating_mul(8);
```

### 2.3 Schema IR Documentation ([crates/dfdl-core/src/schema/ir.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs))
Corrected doc comment on `choice_length`:
```rust
/// Choice explicit length in bytes (DFDL §15.1.2: `dfdl:choiceLength`).
pub choice_length: Option<usize>,
```

### 2.4 Targeted Regression Test ([crates/dfdl-tests/src/lib.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-tests/src/lib.rs))
Implemented `test_f8_choice_length_independent_of_length_units`:
- Configures `representation="binary"`, `lengthUnits="bits"`, `alignmentUnits="bits"`.
- Choice element has `dfdl:choiceLengthKind="explicit"` and `dfdl:choiceLength="2"`.
- Child elements have lengths 16 bits (`Branch16`) and 8 bits (`Branch8`).
- Verifies that parsing `[0x12, 0x34]` (16 bits) succeeds as `Branch16` without rejection.
- Verifies that unparsing the infoset back produces the exact 2-byte stream `[0x12, 0x34]`.
