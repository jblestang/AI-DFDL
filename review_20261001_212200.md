### 1.2 DFDL v1.0 Specification Compliance
The fixes implemented in this iteration were deliberately designed to be **generalized, standard-conforming fixes** rather than narrow point-patches:

1. **General Comparison Operators Rejection (DFDL v1.0 §23.3):**
   - DFDL expressions do not support sequence types. General comparison operators (`=`, `!=`, `<`, `<=`, `>`, `>=`) from XPath 2.0 operate on node sequences and are explicitly unsupported in DFDL expressions.
   - Any occurrence in an expression now systematically returns a `SchemaDefinition` error advising the author to use value comparison operators (`eq`, `ne`, `lt`, `le`, `gt`, `ge`).
   - Standard conformance resolved: `comparison_operators_03`, `comparison_operators_04`, `comparison_operators_07`, and related test cases.

2. **Binary Integer Bit Length Bounds (DFDL v1.0 §12.3.7.2):**
   - Validated across **all** binary integer types (`Byte`, `UnsignedByte`, `Short`, `UnsignedShort`, `Int`, `UnsignedInt`, `Long`, `UnsignedLong`):
     - `Byte` / `UnsignedByte`: 1 to 8 bits
     - `Short` / `UnsignedShort`: 1 to 16 bits
     - `Int` / `UnsignedInt`: 1 to 32 bits
     - `Long` / `UnsignedLong`: 1 to 64 bits
     - `Float`: exactly 32 bits
     - `Double`: exactly 64 bits
   - Implemented symmetrically at:
     - Compile time for direct explicit lengths on simple types and elements (`crates/dfdl-schema/src/compiler.rs`)
     - Compile time for `dfdl:prefixLengthType` referencing named simple types (`crates/dfdl-schema/src/compiler.rs`)
     - Runtime during binary parsing (`crates/dfdl-core/src/kernel/parser.rs`)
     - Runtime during binary unparsing (`crates/dfdl-core/src/kernel/unparser.rs`)
   - Standard conformance resolved: `invalidUnsignedIntBitLength`, `invalidUnsignedShortBitLength`, `invalidUnsignedByteBitLength`, `invalidIntBitLengthExpr`, `unparseInvalidIntBitLengthExpr`, `invalidShortBitLengthExpr`, `invalidByteBitLengthExpr`, `invalidLongBitLengthExpr`.

3. **Virtual Decimal Point Validation (DFDL v1.0 §13.7.1):**
   - In `dfdl:textNumberPattern`, the `V` character specifies an assumed virtual decimal point with an exact scale.
   - Optional digits (`#`) after `V` are semantically invalid and prohibited; only explicit digits `0-9` are permitted after `V`.
   - Standard conformance resolved: `vpattern_bad_02`, `vpattern_bad_03`, `zoned_vpattern_bad_02`, `zoned_vpattern_bad_03`.

4. **Dynamic Non-Byte-Sized Encoding Prohibition (DFDL v1.0 §11.1):**
   - DFDL requires that non-byte-sized encodings (`X-DFDL-US-ASCII-6-BIT-PACKED`, 5-bit, 7-bit, bit-packed) be statically specified literals in the DFDL schema; they cannot be computed dynamically via expressions.
   - Symmetrically enforced in both parser (`crates/dfdl-core/src/kernel/parser.rs`) and unparser (`crates/dfdl-core/src/kernel/unparser.rs`).
   - Standard conformance resolved: `encoding_property_expression3` and `encoding_property_expression2_unparse`.

5. **Query-Style Paths Prohibition & Exceptions (DFDL v1.0 §23.2, §23.5):**
   - DFDL expressions identify a single node and do not return node sequences.
   - Referencing an array element (`maxOccurs > 1` or unbounded) in any path without an index predicate (`[...]`) is rejected as a `Schema Definition Error` citing query-style paths not supported.
   - Path step predicates are now correctly preserved during AST construction (`build_path_internal`).
   - Implemented the explicit standard exception for `fn:count()` and `fn:exists()` (§23.5), which take an array node sequence as their operand.
   - Standard conformance resolved: `sequenceReturned_01`, `sequenceReturned_02`, `sequenceReturned_03`, while maintaining 100% pass on `longPath_01` and `dfdl2263`.
