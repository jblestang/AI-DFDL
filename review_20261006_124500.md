## 1. Executive Summary & Root-Cause Analysis

Nineteen failures originally identified under « 5. Unparse Execution Failures » were analyzed, grouped into 5 architectural clusters, and resolved with standard-conforming fixes across all types rather than localized hacks:

| Cluster | Cases Addressed | Root Cause | Architectural Resolution |
| :--- | :--- | :--- | :--- |
| **Cluster 1: Qualified Path Steps in OVC** | `OutputValueCalc_01` to `08`, `arrayWithFollowingOVC`, `varInstance_13` | `make_expr_context` built `ExprContext` with `&[]` in-scope namespaces, preventing evaluation of qualified QNames (e.g. `ex:xi`) during unparsing. Path resolution lacked dynamic OVC evaluation fallback. | Track compiled schema `in_scope_namespaces` during unparsing in `UnparserEngine`. Cache computed OVC values in `ovc_values` keyed by normalized infoset paths. Support forward/dynamic OVC calculation in `eval_ovc_for_path` and `resolve_path`. |
| **Cluster 2: Separator Suppression vs Element Padding** | `parsedOptArrayThenScalar02`, `impOptArrayThenScalar02`, `roundTripErrorHalfwayThrough` | `is_empty_infoset_element` treated elements with empty XML tags as empty representation even when `lengthKind="explicit"` with length > 0 and `textPadKind="padChar"`, skipping element unparsing. | Per DFDL §14.2.3, if padding is emitted, the element does NOT have empty representation. Evaluated elements with explicit length > 0 and `padChar`/`fillByte` as non-empty for separator suppression. |
| **Cluster 3: Explicit Length Text Padding** | `explicit_unparse_02`, `ovcContentLengthCycle2` | An artificial check raised `"Data length X doesn't match expected output data length Y and textPadKind is 'none'"` on explicit length strings shorter than the target length. | Per DFDL §13.7.1 and §14.2.2, pad with `fillByte` (or pad character) up to target length instead of aborting when `textPadKind="none"`. |
| **Cluster 4: PUA Control Character Encoding** | `puaInfosetChars_04_ffb` | TDML document text runner did not remap Unicode Private Use Area (PUA) characters (e.g. `U+E001` -> `0x01`) when comparing unparsed raw control characters. | Remapped PUA codepoints to raw byte representations in `assemble_document_bytes_and_bits_with_base_dir`. |
| **Cluster 5: Delimiter Alignment & Dynamic OVC** | `separatorMTA_01`, `blob_06` | In-sequence delimiters on sub-byte boundaries (e.g. comma following 2-bit symbols) lacked Mandatory Text Alignment (MTA). Dynamic OVC references across sibling elements were not available during length calculation. | Enforced MTA bit alignment before writing sequence separators in `unparse_sequence`. Dynamically evaluated and cached OVC values across infoset traversal. |

## 2. Multi-Disciplinary Domain Reviews

### 2.1 DFDL v1.0 Standard Conformance Review
- **OVC Evaluation Semantics (§17.2):**
  - Section 17.2 states: *"The computed value replaces any value present in the infoset for that element."*
  - The implementation replaces infoset placeholders by updating `self.ovc_values` and binding them into the expression evaluation context.
  - Forward references (e.g. element `a` referencing element `b[dfdl:occursIndex()]` where `b` occurs later in the sequence) now resolve through `eval_ovc_for_path` using scoped schemas and expression budgets, matching Apache Daffodil behavior.
- **Empty Representation & Separator Suppression (§14.2.3):**
  - Section 14.2.3 states: *"if padding or filling is output, the element does not have empty representation."*
  - In `is_empty_infoset_element`, if `length_kind == Explicit && length > 0 && text_pad_kind == PadChar`, or `text_output_min_length > 0`, the function returns `false`. This prevents suppressive separators from eliminating elements that produce valid output padding.
- **Mandatory Text Alignment (§12.3):**
  - Sequence separators are terms of the enclosing sequence and inherit its character encoding. When unparsing sequences containing mixed sub-byte elements (e.g. `X-DFDL-BASE4-MSBF`), prefix and postfix separators now align to the character unit boundary (`encoding_unit_bits`) using `fillByte` before emitting delimiter characters.
