## 2. Detailed Technical Remediation

### Priorité 1 : Construction directe et fortement typée de `PrefixLengthDescriptor`

- **Location:** [`crates/dfdl-schema/src/compiler/lower.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler/lower.rs#L884-L1130)
- **Previous implementation:**  
  Constructed a composite delimited string `format!("{clean_plt}:{rep}:{l}:{units}:{alignment}:{length_units}")` with special sentinel `@nested@` for nested elements, parsed back downstream using `split(':')`.
- **New implementation:**  
  Directly builds `Option<PrefixLengthDescriptor>` with fields:
  - `prefix_length_type: QName`
  - `prefix_includes_prefix_length: bool`
  - `length_units: LengthUnits`
  - `representation: Representation`
  - `length_in_units: u64`
  - `alignment_in_bits: u32`
- **Result:**  
  Eliminated all runtime string allocations, string parsing errors, and formatting ambiguities. `#![no_std]` + `alloc` compatibility fully preserved.

### Priorité 2 : Élimination de `split(':').next_back()`

### Priorité 3 : Normalisation W3C XML 1.0 §3.3.3 des valeurs d'attributs

- **Location:** [`crates/dfdl-xml/src/reader.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-xml/src/reader.rs#L297-L389)
- **Specification requirement:**  
  W3C XML 1.0 §3.3.3 mandates that literal whitespace characters (`\t`, `\r`, `\n`) in attribute values MUST be normalized to space (`0x20`), whereas numeric character entities (`&#x9;`, `&#xA;`, `&#xD;`) MUST NOT be normalized and preserved as tab/newline.
- **New implementation:**  
  `decode_attribute_value` scans and separates literal character runs from character entities. Literal `\t`, `\r`, `\n` are transformed to `' '`, while entity references (`&#x9;`, `&#xA;`) are preserved verbatim as their decoded characters.
- **Test coverage:**  
  Added comprehensive test case `test_xml_reader_extended_edge_cases` (point 13) validating exact behavior.

## 3. Concurrency & Execution Analysis (The "Hang" Investigation)

During execution of the test suite, the user reported that the test command seemed to hang:
`cargo test -p dfdl-tests test_apache_daffodil_official_tdml_suite -- --ignored --nocapture`

### Root Cause Analysis
1. **No Infinite Loop:** Process monitoring (`sample`, `ps`, and debug telemetry) confirmed that no infinite or busy loop existed. CPU time remained zero while awaiting locks.
2. **Cargo Target Directory File Lock:** Running `cargo test --workspace` concurrently with an interactive `cargo test` in a separate terminal caused cargo's internal file lock on `target/.package-cache` / `target/.cargo-lock` to block the second invocation until the first completed.
3. **Execution Scale:** The Apache Daffodil official TDML test suite executes **4,336 test cases** across **193 TDML test suites**. Because test runners buffer test logs until completion (unless `--nocapture` with intermediate progress messages is streamed), the test appeared paused during its ~10-second run.
4. **Validation:** Executed with `TDML_DEBUG=1`, the entire 4,336-test suite completes in **9.80 seconds** with:
   - **4,331 passed (99.9%)**
   - **5 failed (0.1%, identical to known baseline of leftover bitstream data)**
   - **0 schema compilation failures**
