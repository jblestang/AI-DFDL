# Engineering Review - Pattern Assertion Timing & Fatal RSDE Choice Propagation
**Timestamp:** 2026-10-05 10:30:00  
**Scope:** `dfdl-core` (`kernel/parser/element.rs`, `kernel/parser/mod.rs`, `expr/eval.rs`), Conformance testing on Apache Daffodil TDML Assert & Discriminator Suites.

---

### 1. Executive Summary
This development cycle resolved critical specification deviations regarding:
1. **DFDL §7.3 Pattern Assertion Evaluation Timing:** Pattern assertions (`testKind="pattern"`) must be evaluated at the start of the component before consuming framing (initiator, prefix) or component data, looking ahead into the raw bitstream.
2. **DFDL §7.4 vs §7.3 Missing Node Semantics:** In a `dfdl:discriminator`, referencing a non-existent element in the infoset evaluates to `false` (causing a Processing Error / PE for choice branch backtracking). In `dfdl:assert` and general DFDL expressions, referencing a non-existent element causes an Expression Evaluation Error which is a fatal Runtime Schema Definition Error (RSDE / `DFDLErrorKind::SchemaDefinition`).
3. **DFDL §5 Fatal RSDE Non-Backtracking:** When an alternative branch in an `xs:choice` raises a `SchemaDefinition` error (RSDE), it must immediately terminate processing and cannot be suppressed or treated as a backtrackable branch alternative.

---

### 2. Changes Implemented

#### A. Start-of-Component Pattern Assertion Evaluation (`crates/dfdl-core/src/kernel/parser/element.rs`)
- Implemented `evaluate_pattern_asserts` at the start of `parse_single_element_occurrence` before consuming any initiator, prefix, or value bytes.
- Peeks into the raw data stream using non-destructive checkpointing and text decoding according to the element's encoding property.
- Matches against anchored regex `^(?:{pattern})` or unanchored fallback.
- In `evaluate_asserts` (invoked post-parse), skipped `testKind == TestKind::Pattern` to avoid redundant evaluation against an advanced bitstream position.
- Tests passing: `assertPatternInitsTerms`, `assertPatternPass1`, `assertPatternPass2`, `assertPatternPass3`.

#### B. Sequence and GroupRef Pattern Assertions (`crates/dfdl-core/src/kernel/parser/mod.rs`)
- Integrated `evaluate_pattern_asserts` at the entry points of `parse_sequence` and `TermKind::GroupRef`.
- Standardized error message diagnostics:
  `Parse Error: Assertion failed for pattern '{pattern}'`
- Tests passing: `assertOnSequence`, `assertOnGroupRef`, `assertOnElemRef`.

#### C. Path Resolution RSDE and Choice Branch Fatal Error Propagation (`crates/dfdl-core/src/expr/eval.rs`, `crates/dfdl-core/src/kernel/parser/mod.rs`)
- In `resolve_path`, when a target element is not found in the Infoset document, returned `DFDLErrorKind::SchemaDefinition` with standard message:
  `Runtime Schema Definition Error: Expression Evaluation Error in '{current_path}': element '{qname}' does not exist in Infoset document (Path not found in Infoset document: '{path}')`
- In `evaluate_discriminator`, caught expression evaluation errors when testing expressions, evaluating to `false` (Processing Error) per DFDL §7.4.
- In `xs:choice` branch parsing, added an explicit check:
  ```rust
  Err(e) => {
      if e.kind == DFDLErrorKind::SchemaDefinition {
          return Err(e);
      }
      ...
  }
  ```
  ensuring fatal Schema Definition Errors terminate immediately without backtracking.
- Tests passing: `assertSDENotPE1`, `occursCountSDENotPE1`, `discrimPEvalueLength1`, achieving 100% pass rate (87/87 in `assert.tdml`, 12/12 in `discriminator.tdml`).
