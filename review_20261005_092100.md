## 2. Key Root Causes & Architectural Fixes

### A. Non-matching `dfdl:lengthKind="pattern"` Return Semantics (`regexLookaheadFail`)
- **Standard Reference:** DFDL 1.0 §12.3.4 (`lengthKind="pattern"`):
  > "When parsing, if the regular expression does not match at the current position, the length is zero."
- **Root Cause:** In [`crates/dfdl-core/src/kernel/parser/element.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs#L2473), when `re.match_prefix_len` failed, it returned `Err(DFDLError::new(DFDLErrorKind::Parse, "dfdl:lengthPattern did not match at current position"))`.
- **Architectural Fix:** Per DFDL specification, returned `Ok(Some(0))` on non-matching pattern length. Verified with `regexLookahead` test series (3/3 passing).

### B. Comprehensive DFDL Whitespace Character Matching in Delimiters (`delimsCheck`)
- **Standard Reference:** DFDL 1.0 §6.3.1 (Character Entities):
  > "Character entity `%WSP;` matches any single whitespace character. This includes Space (0x20), Tab (0x09), and any characters matched by `%NL;` (LF 0x0A, CR 0x0D, NEL 0x85, LS 0x2028)."
  > `%WSP*;` matches zero or more whitespace characters.
- **Root Cause:** In [`crates/dfdl-core/src/kernel/parser/delimiters.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/delimiters.rs#L618), `DelimToken::WSP`, `DelimToken::WSPStar`, and `DelimToken::WSPPlus` only matched ASCII `0x20` and `0x09`. Consequently, for terminator `%WSP*;%NL;`, `WSPStar` halted before `0x0A`, allowing `NL` to incorrectly match `0x0A`. Per DFDL specification, `WSP*` greedily matches all whitespace (including newlines), causing `%WSP*;%NL;` to never match when followed by non-whitespace/EOF.
- **Architectural Fix:** Updated `DelimToken::WSP`, `DelimToken::WSPStar`, and `DelimToken::WSPPlus` to match all specification-defined whitespace: space (`0x20`), horizontal tab (`0x09`), newline (`0x0A`, `0x85`), and carriage return (`0x0D` with optional CRLF lookahead). Wrapped terminator failure diagnostics with contextual "Terminator '{term_raw}' not found".

### C. Java Regex Incompatibility Rejection in `dfdl:lengthPattern` (`regexCompatFail`)
- **Standard Reference:** DFDL 1.0 §12.3.2 (`dfdl:lengthPattern`):
  > "Regular expressions in DFDL are Java regular expressions (as defined by java.util.regex.Pattern)."
- **Root Cause:** Rust's `regex` engine accepts Python-style 8-digit hexadecimal unicode escapes (`\UXXXXXXXX`), whereas Java regular expressions reject `\U` as an illegal escape sequence. In `newRegex` test case `regexCompatFail`, `\U0010ffff` was accepted by the schema compiler rather than raising a Schema Definition Error.
- **Architectural Fix:** In [`crates/dfdl-core/src/pattern.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/pattern.rs#L48), rejected `\U` escapes with an explanatory error. In [`crates/dfdl-core/src/expr/properties.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs#L995), emitted standard diagnostic `"Schema Definition Error: InvalidRegex: '{}' is not a valid regular expression"`.

### D. Navigation Past Root Element Diagnostic in Expressions (`expresion_bad_path_to_element`)
- **Standard Reference:** DFDL 1.0 §23 (Expression Language):
  > "In DFDL expressions, the root element has no parent. A path expression that attempts to step above the root element is a Schema Definition Error."
- **Root Cause:** In [`crates/dfdl-core/src/expr/eval.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/eval.rs#L850), stepping `..` checked `if norm.segments().is_empty()`. Since the root element was at index 0 of `norm`, popping the root element left `norm` empty; a subsequent step `..` or child step did not trigger the navigation past root check, incorrectly falling back to an unrooted element search in the infoset document.
- **Architectural Fix:** Changed the boundary check to `if norm.segments().len() <= 1` before popping `..`. If `norm` is at the root element (or already empty), stepping `..` immediately raises `Schema Definition Error: Relative path step '..' navigates past root element in path '...'`.

### E. Prefix Normalization in Self-Axis Steps (`self_axis_01`, `multiple_axis_01`)
- **Standard Reference:** DFDL 1.0 §23.2 (Path Expressions):
  > Step `self::prefix:name` matches the current element if its local name matches `name`.
- **Root Cause:** In [`crates/dfdl-core/src/expr/eval.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/eval.rs#L839), `expected` retained its namespace prefix (e.g. `"ex:c2"`), whereas `clean_curr_head` was local name `"c2"`. Comparing them directly failed with `self::ex:c2 does not match current element 'c2'`.
- **Architectural Fix:** Extracted `clean_expected = expected.split(':').next_back().unwrap_or(expected)` before comparison. Verified all 15 axis tests pass 100%.
