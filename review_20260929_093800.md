## Executive Summary

1. **Native Pest Grammar Expression Parsing**:
   - Updated `expression` rule in [`crates/dfdl-core/src/expr/dfdl_expression.pest`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/dfdl_expression.pest) to:
     ```pest
     expression = { SOI ~ ("{" ~ expr ~ "}" | expr) ~ EOI }
     ```
   - Pest natively handles both bare literal/expression forms (`dfdl:length="13"`) and enclosed forms (`dfdl:length="{ 10 }"`). Manual string slicing of `{` and `}` in Rust was removed from `parse_expr`.

2. **Strict `dfdl:inputValueCalc` Standard Compliance (§17.1)**:
   - Enforced strict DFDL §17.1 rules in `parse_single_element_occurrence`. Calculated elements do not consume input data and fail with a parse error if evaluation fails, with zero fallback to bitstream text parsing.

3. **Prefixed Length Resolution (`LengthKind::Prefixed`) (§12.3.4)**:
   - Added `prefix_length_type` property extraction in [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs) and [`crates/dfdl-core/src/expr/properties.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs).
   - Implemented prefix length integer reading in `evaluate_length_property` in [`crates/dfdl-core/src/kernel/parser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs#L584-L610) to dynamically read the prefix length field (e.g. 16-bit `unsignedShort`, 32-bit `int`, 8-bit `byte`).

4. **Schema Element Reference Support**:
   - Added `ref` attribute parsing (`<xs:element ref="...">`) in schema compiler to resolve element QNames and properties correctly.
