## 1. Domain & Specification Background

In DFDL implementations (Apache Daffodil / OGF DFDL v1.0):
1. **Schema Definition Warnings**:
   - Certain schema discrepancies are non-fatal warnings by default (e.g. `appinfoDFDLSourceWrong` when `<xs:appinfo source="...">` uses `http://www.ogf.org/dfdl/dfdl-1.0/` instead of `http://www.ogf.org/dfdl/`).
2. **Warning Escalation Tunable (`escalateWarningsToErrors`)**:
   - In Daffodil TDML suites and Daffodil config, `daf:tunables` or TDML `config` can set `escalateWarningsToErrors="true"`.
   - When set, any unsuppressed schema definition warning is escalated to a fatal `SchemaDefinitionError`.
3. **Warning Suppression (`daf:suppressSchemaDefinitionWarnings`)**:
   - Elements or enclosing schema contexts may specify `daf:suppressSchemaDefinitionWarnings="appinfoDFDLSourceWrong"`.
   - When suppressed, the warning is suppressed and not escalated.
4. **AST-bounded Escalation**:
   - If a schema file defines multiple global elements, only the requested root element and elements referenced/reachable by the grammar are validated/escalated during compilation for that root. Global elements that are unused by the target root must not trigger compilation failures for that target root.

## 2. Changes Made

1. **`SchemaCompiler` Escalation Configuration:**
   - Added `escalate_warnings: bool` and `pub fn set_escalate_warnings(&mut self, val: bool)` in `dfdl-schema/src/compiler.rs`.
2. **Warning Recording on AST:**
   - In `parse_annotation_container`, when an appinfo source discrepancy (`appinfoDFDLSourceWrong`) is encountered, recorded `__dfdl_appinfo_source_warning` on the element's `PropertyStore`.
3. **AST Lowering Escalation Validation:**
   - In `lower_element_to_ir_bounded`, checked whether `__dfdl_appinfo_source_warning` is present on the effective element properties.
   - Checked whether `suppressSchemaDefinitionWarnings` on the element or parent suppresses `appinfoDFDLSourceWrong`.
   - If not suppressed and `self.escalate_warnings` is enabled, escalated the warning to a `SchemaDefinition` error.
4. **TDML Test Harness Support:**
   - Extended `ConfigOption` in `dfdl-tests/src/tdml.rs` to support `EscalateWarningsToErrors(bool)`.
   - Updated TDML config parsing to parse `<daf:tunable name="escalateWarningsToErrors">true/false</daf:tunable>`.
   - Updated `SchemaCacheKey` to incorporate `escalate_warnings` so schemas compiled under different tunable settings are not erroneously reused.
