# Architectural & Conformance Code Review: Delimiter/Separator Mismatches Resolution

**Timestamp:** 2026-10-01 14:00:00 UTC+2  
**Domain Expertises Applied:** DFDL 1.0 Specification Conformance, Systems Architecture, Safe Embedded Rust (`#![no_std]` + `alloc`), Compiler Verification.

## 1. Executive Summary & Conformance Progress

A comprehensive audit was performed on the **"Delimiter/Separator Mismatches"** failure cluster (which previously accounted for 231 failures, or 49.8% of parse execution failures across the 4,337-test Apache Daffodil TDML conformance suite).

Rather than applying localized, surgical, or type-specific fixes, standard-conforming architectural changes were implemented specification-wide across the schema IR, expression properties resolution, compiler type resolver, infoset tree builder, and parser runtime:

1. **DFDL Entity Parser Fix (%WSP*; character length calculation)**:
   - Fixed off-by-one bug where token parsing advanced by 7 bytes instead of 6 bytes (`"%WSP*;".len()`), which corrupted subsequent delimiter character literals and caused prefix/infix separators with whitespace entities to drop their leading character.
2. **InputValueCalc in Separated Sequences (DFDL §17.1)**:
   - Elements with `dfdl:inputValueCalc` have no physical representation in the input data stream.
   - Bypassed all framing, alignment, and separator matching for `inputValueCalc` elements, and ensured they do not contribute to physical sequence element counts (`total_element_count`).
3. **Infix Separator Suppression with Optional/Absent Members (DFDL §14.2)**:
   - Infix separators appear between physical representations. When preceding elements are absent or have 0 occurrences (`total_element_count == 0`), an infix separator must only be demanded if `separatorSuppressionPolicy="never"`.
   - Updated infix separator evaluation conditions across sequence parsing and element parsing.
4. **Unordered Sequences Support (DFDL §14.3)**:
   - Modeled `SequenceKind` (`Ordered` vs `Unordered`) in schema IR and property resolution.
   - Implemented transactional multi-pass parsing for unordered sequences in `ParserEngine`, trying each candidate member against the bitstream, matching infix/prefix/postfix separators transactionally, and stably reordering the constructed infoset elements to match schema definition order per DFDL §14.3.
5. **Simple Type Restriction Chain Resolution**:
   - Added deep traversal of user-defined simple type restriction chains in the schema compiler, correctly resolving nested custom types (e.g. `IsrmResultTag -> uint32 -> unsignedInt`) to their primitive representations and preventing fallback to `String`.
6. **Complex Element Value Length Calculation (DFDL §23)**:
   - Permitted `dfdl:valueLength` calculation on complex elements with children even when their element state is `ElementState::NoValue`, enabling accurate length computation during unparsing.
