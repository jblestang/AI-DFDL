## 2. Multi-Domain Expertise Assessment

### 2.1 DFDL Standard & Specification Domain Expertise
- **§13.7 (`dfdl:decimalSigned` Semantics across Binary and Text Formats):**
  - **Issue:** Previously, `dfdl:decimalSigned="no"` was either unmodeled or ignored during text/binary parsing and unparsing of decimal and integer types.
  - **Standard Conforming Architecture:**
    - Added `pub decimal_signed: bool` (defaulting to `true`) to [`ResolvedProperties`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/schema/ir.rs#L400-L415).
    - Populated `decimal_signed` in [`to_resolved_properties`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs#L1240-L1250).
    - In [`crates/dfdl-core/src/kernel/parser/binary.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/binary.rs), packed/BCD and binary numbers parse raw values and verify that negative representations (or negative signs) are rejected with a typed `DFDLErrorKind::Parse` error when `decimalSigned="no"`.
    - In [`crates/dfdl-core/src/kernel/parser/text.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/text.rs), explicit `-` signs on decimal representations trigger an immediate parse error if `props.decimal_signed` is false.
    - In [`crates/dfdl-core/src/kernel/unparser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/unparser.rs), negative values bound to elements with `decimalSigned="no"` fail unparsing cleanly.

- **§13.11 (`dfdl:binaryCalendarRep="bcd"` & `"ibm4690Packed"` Constraints):**
  - **BCD Digit Invariant:** Strict hexadecimal nibble bounds `[0x0..=0x09]` enforced in calendar nibble decoding. Values `0xA..=0xF` raise standard `Parse Error: Invalid high/low nibble for BCD digit` errors.
  - **Calendar Pattern Letter Whitelist:** BCD and IBM4690 packed calendars cannot accommodate separators, literals, or alphabetic words. The compile-time pattern whitelist in [`PropertyStore::to_resolved_properties`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/expr/properties.rs) now permits all valid numeric calendar tokens (`y`, `Y`, `u`, `M`, `L`, `d`, `D`, `H`, `h`, `m`, `s`, `S`, `K`, `k`, `w`, `W`, `F`, `g`, `e`, `c`) while rejecting separators and textual flags (such as `-`, `:`, `'E'`) when `representation="binary"`.

- **§13.14 (Strict Grouping, Negative Subpatterns, and Number Formats):**
  - Grouping separator validation (`validate_and_clean_integer_grouping`) in [`crates/dfdl-core/src/kernel/parser/numbers.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/numbers.rs) ensures that in strict mode:
    1. Negative subpatterns strictly inherit grouping configuration from the positive subpattern (`pos_grp`), ignoring erroneous grouping characters within negative subpatterns.
    2. Grouping intervals must uniformly match the defined grouping size (`pos_grp`).
    3. Trailing, leading, or misplaced grouping characters reject immediately.
    4. Unsolicited whitespace without explicit pattern padding is rejected in strict mode.

- **W3C XML Schema Datatypes (§3.2, §3.3 Calendar Bounds & Prohibited Timezones):**
  - Added pattern characters `K` (hours 0..=11) and `k` (hours 1..=24) in [`crates/dfdl-core/src/kernel/parser/calendar.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/calendar.rs).
  - Out-of-range hours (`H > 23`, `h > 12`, `K > 11`, `k > 24`) fail parsing.
  - W3C XML Schema prohibited timezone `-00:00`, `-0000`, and `-00` are strictly rejected across `xs:date`, `xs:time`, and `xs:dateTime`.

### 2.2 Software Architecture & Modularization
- The previous monolithic `crates/dfdl-core/src/kernel/parser.rs` was split into clean domain modules under [`crates/dfdl-core/src/kernel/parser/`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/):
  - `binary.rs`: Binary scalar, packed, and BCD parsing.
  - `calendar.rs`: Calendar patterns, timezones, and text/binary calendar extraction.
  - `delimiters.rs`: Delimiter matching and rollback mechanisms.
  - `element.rs`: Complex element orchestration and occurrences handling.
  - `numbers.rs`: Numeric parsing, grouping validation, exponent and sign extraction.
  - `text.rs`: Delimited text primitive parsing.
  - `tests.rs`: Specialized unit test cases.
- All cross-module dependencies are clean and non-cyclic.

### 2.3 Safety, Robustness, and Embedded Resource Constraints
- **`#![no_std]` + `alloc` Compliance:** No references to `std::` primitives were introduced; all string and vector manipulations utilize `core::` and `alloc::`.
- **Arithmetic Safety:** All calculations, nibble extraction, and offsets utilize checked or saturating arithmetic (`saturating_add`, `checked_mul`).
- **Memory Safety:** No raw pointer operations or `unsafe` blocks.
