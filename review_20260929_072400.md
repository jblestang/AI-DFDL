## 2. Key Insights & Architectural Impact

1. **`dfdl:inputValueCalc` Evaluation Order (132 test cases / 24.7%)**:
   - In [`crates/dfdl-core/src/kernel/parser.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser.rs), elements containing `dfdl:inputValueCalc` should **not** attempt to read or parse input bytes from the bitstream. Instead, `inputValueCalc` elements compute their value purely via expression evaluation on the current infoset tree state.
   - Fixing the control flow so `inputValueCalc` bypasses stream reads resolves the `InputValueCalc_*` test family.

2. **Binary Bit Alignment & Length Handling (336 test cases / 62.9%)**:
   - In `parse_binary_value`, element alignment (`dfdl:alignment`) and length specifications (e.g. `dfdl:lengthKind="implicit"` vs `"explicit"`) must dynamically dictate the exact bit-width read from the bitstream rather than defaulting to full type width (e.g., 32 bits for `xs:int`).
