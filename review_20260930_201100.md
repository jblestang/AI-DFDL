## 2. Key Implemented Fixes & Standards Compliance

### 1. `prefixLengthType` Simple Type Constraints (DFDL 1.0 §12.3.4)
- **Root Cause:** `prefixLengthType` was not checked to ensure it refers to an integer simple type (`xs:unsignedLong`, `xs:long`, `xs:int`, `xs:short`, `xs:byte`, etc.).
- **Generic Fix:** Added strict validation requiring `prefixLengthType` to refer to an integer simple type per DFDL 1.0 §12.3.4.
- **Impact:** Resolved **6 expected error test cases**.

### 2. Unparse Array `maxOccurs` Error Formatting (DFDL 1.0 §14.2)
- **Root Cause:** When unparsing elements exceeding `maxOccurs`, the unparser emitted `"Expected at most X occurrence(s)..."`, which failed to match TDML expectations for `"Expected array end event"`.
- **Generic Fix:** Formatted the unparser error message to `"Unparse Error: Expected array end event for '...', received element start event..."`.
- **Impact:** Resolved **4 unparse error test cases**.

### 3. `separatorSuppressionPolicy="never"` Missing Separator Enforcement (DFDL 1.0 §14.2)
- **Root Cause:** When optional elements were omitted in a sequence with `separatorSuppressionPolicy="never"`, the parser did not check if the required separator was missing.
- **Generic Fix:** Enforced missing separator parse errors when `separatorSuppressionPolicy="never"` and optional elements are omitted without separators.
- **Impact:** Resolved **3 parse error test cases**.

### 4. `textStandardDecimalSeparator` & `textStandardExponentRep` Required Checks (DFDL 1.0 §13.6)
- **Root Cause:** Property resolution defaulted missing `textStandardDecimalSeparator` to `"."` instead of validating whether it was defined when required.
- **Generic Fix:** Required `textStandardDecimalSeparator` and `textStandardExponentRep` to be explicitly defined when text numeric representation is used.
- **Impact:** Resolved **3 schema definition error test cases**.

### 5. Negative `dfdl:length` Error String Formatting (DFDL 1.0 §12.3)
- **Root Cause:** Negative `dfdl:length` error messages did not include the invalid negative integer value.
- **Generic Fix:** Formatted negative `dfdl:length` error messages to include the evaluated negative integer value (`"dfdl:length cannot be negative: -10"`).
- **Impact:** Resolved **2 runtime schema definition error test cases**.

### 6. `lengthKind='implicit'` Property Resolution & Simple Type Constraints (DFDL 1.0 §12.3.2)
- **Root Cause:** In `to_resolved_properties`, `length` property was only looked up directly on `self` (`self.get_property("length")`) without checking `parent` properties, causing elements with default format `dfdl:length="1"` to evaluate `length` as `None` when `lengthKind="implicit"`, triggering erroneous `lengthKind='implicit' with representation='text' is not allowed for simple type 'String'` errors.
- **Generic Fix:** Updated `len_str` in `to_resolved_properties` to check `parent` (`self.get_property("length").or_else(|| parent.and_then(|p| p.get_property("length")))`), and added `length_expr.is_some()` to `is_valid_implicit` in `compiler.rs`.
- **Impact:** Eliminated false positive schema definition errors for `lengthKind='implicit'` on simple types (e.g. element `opt`).

### 7. Sequence Unparser Array Bounds Enforcement (DFDL 1.0 §14.2 & §16.1)
- **Root Cause:** Sequence unparsing called `unparse_element` directly on matched child elements in a loop without validating `minOccurs` or `maxOccurs`.
- **Generic Fix:** Added `minOccurs` and `maxOccurs` bounds validation inside the sequence unparser loop.
- **Impact:** Correctly raises `"Unparse Error: Expected array end event for '...', received element start event"`.

### 8. Bitwise Function Type and Signedness Validation (DFDL Extensions §23)
- **Root Cause:** Bitwise functions `dfdlx:bitOr`, `dfdlx:bitAnd`, `dfdlx:bitXor`, and `dfdlx:bitNot` accepted arbitrary types and mismatched signedness without validation.
- **Generic Fix:** Implemented `validate_bitwise_operand` in `eval.rs` ensuring arguments are `xs:unsignedLong`, `xs:long`, or subtypes, rejecting unbounded types (`xs:integer`, `xs:nonNegativeInteger`, `xs:decimal`) and ensuring operand signedness matches.
- **Impact:** Resolved 9 expected error test cases (`must match in signedness` and `xs:unsignedLong or xs:long or a subtype of those`).

### 9. Relative Path Steps Beyond Document Root (DFDL 1.0 §23)
- **Root Cause:** Path resolution in `eval.rs` silently clamped at the root when extra `..` steps were encountered.
- **Generic Fix:** Enforced Schema Definition Error when `norm.segments().is_empty()` and a `..` step is processed.
- **Impact:** Resolved path-beyond-root diagnostic test cases (`test_expr_path_past_root1`, `beyondRoot_01`).

### 10. `totalDigits` Positive Integer Validation (XML Schema §4.3)
- **Root Cause:** `totalDigits` facet was parsed as a raw string without validating that it is a positive integer greater than zero.
- **Generic Fix:** Added positive integer parsing checks for `totalDigits` in `compiler.rs`.
- **Impact:** Correctly rejects invalid facet schemas (`totalDigits="0"`, `totalDigits=".3"`).

### 11. Fixed-Length Facet Constraints for `lengthKind='implicit'` (DFDL 1.0 §12.3.2)
- **Root Cause:** `compiler.rs` allowed `lengthKind='implicit'` for `xs:string`/`xs:hexBinary` if either `minLength` or `maxLength` was present.
- **Generic Fix:** Required `minLength == maxLength` (or `length` facet) when validating `is_valid_implicit`.
- **Impact:** Properly rejects variable-length facet configurations under implicit length kind (`maxLength02`, `maxLength04`, `maxLength05`).
