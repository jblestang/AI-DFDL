## 1. Executive Summary & Defect Scope (Issue F5)

### 1.1 Specification Baseline (DFDL v1.0 §12.3.4 `lengthKind="pattern"`)
- In DFDL §12.3.4, when `dfdl:lengthKind="pattern"`, the length of the element is determined by matching the regex specified in `dfdl:lengthPattern` against the incoming data stream from the current position.
- The specification does not define an arbitrary 4,096-byte evaluation boundary.
- **Previous Defect:**
  In [crates/dfdl-core/src/kernel/parser/element.rs:2683](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs#L2683), the parser loop was hardcoded as `for _ in 0..4096`.
  - On an input of 5,000 characters matching `A+`, it truncated lookahead silently at 4,096 bytes (32,768 bits).
  - At root level, this left 904 bytes unconsumed, causing a spurious left-over data error.
  - In a sequence followed by a delimited element, parsing succeeded falsely while corrupting the subsequent element by reassigning the remaining 904 `'A'` characters to it.
  - No resource exhaustion error was emitted upon hitting the arbitrary limit.

## 2. Technical Implementation & Fixes

### 2.1 Incremental Lookahead with Explicit Resource Limit ([crates/dfdl-core/src/kernel/parser/element.rs](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-core/src/kernel/parser/element.rs#L2678-L2725))
- Replaced the hardcoded `for _ in 0..4096` loop with a dynamic reader loop driven by EOF and bounded by an explicit 1 MiB (`1_048_576` bytes) safeguard (`MAX_PATTERN_LOOKAHEAD_BYTES`):
  ```rust
  const MAX_PATTERN_LOOKAHEAD_BYTES: usize = 1_048_576; // 1 MiB
  let mut exceeded_limit = false;
  while !self.reader.is_eof() {
      if let Some(cb) = sub_byte_bits {
          if sub_byte_text.len() >= MAX_PATTERN_LOOKAHEAD_BYTES {
              exceeded_limit = true;
              break;
          }
          match self.reader.read_bits(cb) {
              Ok(code) => sub_byte_text
                  .push(crate::encoding::decode_sub_byte_char(code, &props.encoding)),
              Err(_) => break,
          }
      } else {
          if bytes.len() >= MAX_PATTERN_LOOKAHEAD_BYTES {
              exceeded_limit = true;
              break;
          }
          if let Ok(b) = self.reader.read_bits(8) {
              let _ = try_push(&mut bytes, b as u8);
          } else {
              break;
          }
      }
  }
  let _ = self.reader.rollback(reader_cp);
  if exceeded_limit {
      let msg = alloc::format!(
          "Implementation Limit: dfdl:lengthPattern lookahead exceeded maximum buffer window ({} bytes)",
          MAX_PATTERN_LOOKAHEAD_BYTES
      );
      return Err(DFDLError::new(DFDLErrorKind::ImplementationLimit, &msg));
  }
  ```
- If the stream exceeds 1 MiB without reaching EOF, an explicit `DFDLErrorKind::ImplementationLimit` is raised instead of silently corrupting downstream parsing.
