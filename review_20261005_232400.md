## 1. Executive Summary & Root Cause Analysis

### 1.1 Specification Foundation: DFDL v1.0 §5.2.5
Section 5.2.5 of the DFDL 1.0 Specification establishes the lexical namespace scoping rule:
> *"Prefixes in expressions are resolved using the in-scope namespaces of the element or annotation containing the expression (that is, where the expression is written, not where it is evaluated)."*

### 1.2 Identified Failure Modes
Prior to this resolution, two test suites failed under Category 2.a:
1. `choiceBranchKeyRanges_01` in `choiceBranchRanges/choiceBranchKeyRanges.tdml`:
   - **Root Cause:** Expression contexts for choice dispatch key, variable setting, and delimiters were not initialized with `term.properties.in_scope_namespaces`.
   - **Fix:** Systematically propagated `.with_namespaces(&term.properties.in_scope_namespaces)` across all term expression evaluators (`choice_dispatch_key`, `execute_set_variables`, `execute_new_variable_instances`, and delimiters).
2. `namespaces_qnames` in `section06/namespaces/namespaces.tdml`:
   - **Root Cause:** A complex type or anonymous simple type restriction (`<xs:element name="num"><xs:simpleType xmlns:foobar="..."><xs:restriction base="foobar:numType"/></xs:simpleType></xs:element>`) inherits expressions such as `length="{ ../ex1:len }"` defined on base type `numType`'s annotation (`<xs:annotation xmlns:ex1="http://example.com/1">`).
   - During schema parsing of `numType`, when sibling XML child elements like `<xs:restriction base="xs:int"/>` were encountered after the annotation, `st_props.update_namespaces(&reader.in_scope_namespace_bindings())` was invoked. Because `reader.in_scope_namespace_bindings()` returned all ancestor namespaces from the root schema (`xmlns:ex1="urn:ex1.NothingUseful"`), the local annotation's inner binding `ex1="http://example.com/1"` was clobbered by the root schema default.
   - **Architectural Conforming Fix:** 
     1. Added `XmlReader::current_element_namespace_bindings(&self)` in [`crates/dfdl-xml/src/reader.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-xml/src/reader.rs) to return only XML namespace declarations (`xmlns` and `xmlns:prefix`) explicitly declared on the current element frame, without outer ancestor pollution.
     2. Updated [`crates/dfdl-schema/src/compiler.rs`](file:///Users/jean-baptiste/AI-DFDL/crates/dfdl-schema/src/compiler.rs) to use `current_element_namespace_bindings` when updating child tags and annotations, preserving lexical bindings of annotations.
     3. Ensured `PropertyStore::update_namespaces` correctly tracks inner element shadowing while preserving non-shadowed parent prefixes.
